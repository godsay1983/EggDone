# 便签本地历史版本实现方案

更新：2026-09-12。对应双端体验 Roadmap E8b。当前完成 E8b1 数据内核，**尚无用户可操作的历史版本界面**；不得将内核测试等同整个 E8b 完成。

## 范围与保留策略

- 只保存本机曾被替换的标题和正文，以及来源更新时间、来源设备、留档时间。初次插入不生成历史，旧便签升级后从下一次改文开始留档，不制造升级前的历史。
- 生产数据库触发器在文字实际改变时留存旧文字，覆盖编辑保存、同步合并和导入覆盖。相同文字的重复保存、只换色/置顶/改附件不创建文字版本；相邻相同文字不重复留档。空白旧标题与正文不额外占用历史。
- 每条便签最多 100 个版本，全库最多 1000 个，按本机递增 ID 淘汰最早记录，不按远端时间淘汰。连续保存可能较快用尽每条上限；这是近期已保存文字历史，不是逐键撤销或永久备份。
- 标题和正文沿用 100 / 20000 个 Unicode 字符的现有边界。按最大正文估算，1000 份文本约 80 MB 的 UTF-8 原始数据量，另有索引、数据库页和 WAL；不是磁盘占用硬上限，删除记录也不保证数据库文件立即缩小。
- 软删除保留历史。先从回收站恢复便签，再打开历史；物理删除便签时清理对应历史。全库容量淘汰同样适用于已软删除便签。
- 历史不参与 S3 同步，不增加 Object Key，不改变 JSON/完整附件 ZIP 的导出格式。恢复后的当前文字按既有协议正常同步。另一端不会自动获得这一端的历史列表，但另一端被替换的文字会在当地留档。
- 数据库级保护副本或系统整库备份可能包含这张本地表，不能声称所有形式的备份都排除了历史。卸载/清除应用数据或丢失本机数据库会丢失本地历史。
- 不回退图片/文件、附件顺序、颜色、置顶、关联关系或创建时间。恢复正文中提到的附件名称不表示恢复了文件原件。

## 数据与事务

桌面迁移 18 → 19；鸿蒙迁移 19 → 20。迁移使用实际数据库事务，所有 DDL 成功后才记录 schema 版本。迁移失败整体回滚并允许重试，不清空便签或既有同步状态。

表 `note_history`：

| 字段 | 含义 |
| --- | --- |
| id | 本地自增安全整数，作为稳定版本标识，不跨端使用 |
| note_uuid | 原便签 UUID |
| title / content | 替换前的标题、正文 |
| updated_at / updated_by | 被替换文字所属便签的版本信息 |
| captured_at | 数据库留档时间，仅供显示，不用于冲突决胜 |

触发器：`notes_capture_history` 捕获旧文字；`note_history_retention` 负责容量上限；`notes_delete_history` 清理物理删除的便签历史。

恢复流程：

1. 列表只读最多 100 条摘要，正文摘要最多 120 字符；完整内容在选定版本后读取。
2. 预览在同一事务中读取历史全文与当前文字/版本，界面将两者展示给用户。
3. 确认恢复重新读取数据库，并逐项比较预览中的当前文字、来源时间/设备和目标快照。内容改了但时间戳未变，也判为冲突。目标被淘汰、便签删除/缺失时不接受调用方提供的旧正文代替。
4. 仅更新标题、正文、修改时间和本机修改设备；新时间为 max(本机时间, 当前版本+1, 历史来源版本+1)，拒绝不安全整数/溢出。
5. 当前非空文字由同一事务的触发器保留。历史插入失败、当前文字更新失败或提交失败均不能留下半个恢复结果。
6. 当前文字已与选定历史相同则返回未改变，不新增版本，不更新修改时间或触发同步。

桌面模块 `note_history.rs`、`note_history_commands.rs` 和 `src/lib/api/noteHistoryApi.ts` 提供 list / preview / restore。鸿蒙 `NoteHistoryRepository.ets` 负责相同契约，使用既有操作队列和原生 IMMEDIATE 事务；组件不直接访问数据库。恢复接口返回 boolean，区分写入和无变化。

错误码分层：`NOTE_HISTORY_INVALID_ID`、`NOTE_HISTORY_NOTE_UNAVAILABLE`、`NOTE_HISTORY_NOT_FOUND`、`NOTE_HISTORY_CONFLICT`、`NOTE_HISTORY_INVALID_TEXT`、`NOTE_HISTORY_INVALID_VERSION`、`NOTE_HISTORY_DATABASE_FAILED`。UI 阶段翻译成中英文可操作提示，不直接展示路径、SQL 或原始数据库异常。

## 后续 UI 实现

- 在已有便签编辑/更多操作中增加历史入口，不新增主导航。未保存草稿不创建无意义历史。
- 打开历史前等待当前草稿保存及附件操作结束，失败保留编辑器；预览期间不能让旧编辑器自动保存覆盖已恢复正文。
- 列表、当前/历史全文预览、恢复确认、取消、加载失败重试、冲突后重新预览均需实现。
- 明示“仅本机文字历史，不含附件”；关闭预览不改文，恢复后刷新当前编辑器与列表并沿用正常同步调度。
- 使用公共胶囊/按钮样式和现有主题，手机及窄窗口单栏，平板/桌面宽窗口可并排预览；不强行将长文挤进窄侧栏。
- 完成/返回/系统返回遵循已有保存保护，保留便签来源、筛选和滚动位置。覆盖中英文、亮暗、大字体、窄窗口、平板分屏和键盘。
