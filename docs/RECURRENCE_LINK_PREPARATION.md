## 状态规则

只检查非删除、非耗尽规则的当前实例。耗尽/删除的旧规则不要求历史任务仍在本地，也不会复活旧任务。

| 状态 | 含义和处理 |
| --- | --- |
| ready | 当前任务存在，属于该规则，尚未完成/删除；不修改 |
| bind | 仅首实例允许关联为空；全部前置条件通过后补齐关联 |
| reconcile | 当前任务已完成或删除；交给后续确定性补算，不在本接口推进 |
| missing | 当前任务缺失；等待 Todo 下载，禁止以日期猜测或重新创建 |
| conflict | 旧快捷重复、其他系列、后续实例缺少关联，或不同活跃规则争用首实例/当前实例；阻止准备 |
| archived | 仅归档而未完成/删除；不能把归档当作完成，阻止准备 |

规则文档先经过既有严格协议校验，非法文档及重复当前实例会直接报错。关联校验不比较计划日期与任务实际日期，避免覆盖用户改期。

## 事务行为

1. 从数据库读取规则及其当前任务，不能使用调用前缓存的 UI 对象。
2. 若有 missing、conflict 或 archived，整个批次不补写任何关联，返回阻塞状态。
3. 全部通过后，仅把首实例的空 repeat_series_uuid 设置为 first_todo_uuid。
4. 更新对应任务的 updated_at/updated_by，时间至少大于现有任务和规则时间；超出安全整数范围则失败回滚。
5. 不修改标题、备注、日期、提醒、排序、完成/删除/归档时间；不插入 Todo，不推进规则，不写旧实例回执。
6. 所有绑定使用同一立即事务；中途失败或提交失败回滚已写入的关联和 dirty。鸿蒙与规则合并/推进共用 RecurrenceQueue。
7. 重放不重新绑定、不抬高时间戳、不产生额外 dirty。绑定只使 Todo dirty，规则 revision 保持不变。

返回值含绑定的任务 UUID、关联结果和观察到的规则 revision。首实例在绑定前已完成/删除时，绑定后返回 reconcile。

## 不能替代的门槛

`can_prepare` 仅表示本地关联前置条件满足，不是“可以上传规则”或“已经同步成功”。

- 调用结束后，任务/规则仍可能被其他操作修改，后续编排必须重新读取快照。
- reconcile 必须实际补算，再检查新当前实例。
- Todo 条件上传成功，且对应快照包含规则所引用的任务后，才能上传规则。
- 配置切换、409/412 完整流程有限重试、部分成功和 revision CAS ACK 仍需 D2C 实现。
- 当前任务已被永久清理时保留 missing，不从旧规则推断重建。旧版本丢失的全天语义也不在本步自动修复。
- 普通完成/删除入口、备份恢复及旧客户端行为验证完成前，继续关闭规则创建 UI。
