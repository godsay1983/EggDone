- 桌面命令仅在提交成功、数据库锁释放后发送 todos-changed；可选同步调度失败不变成保存失败。

## 提交会话约束

TaskChecklistEditorSession 的两端实现主体一致，注入读取/保存和 UUID 生成，便于使用真实 repository 或隔离测试。

1. 读取不写库；调用方修改返回快照不改变会话内部的父版本、子项和规则基线。
2. 同一负载失败重试保留 operation_uuid；字段、清单或未来定义改变时使用新 UUID，基线仍保持首次读取值。
3. 保存中禁止再次保存和重新加载；提交请求在异步调用前复制，调用方后续修改不会改变正在保存的请求。
4. 保存成功后必须重新加载才能再次提交。幂等回执也可能来自较早提交，不能把回执当作最新数据库快照。
5. 读取失败不沿用之前成功的基线；并发读取时较晚发起的请求优先，旧响应不能覆盖新任务。
6. 归档任务拒绝保存；已完成任务拒绝修改未来规则，但允许按现有后端规则编辑当前清单。
7. 日期、提醒、分组、规则合法性，以及父任务/规则/子项冲突，仍由生产事务最终校验。会话不会吞掉保存错误。
