## 目标与基线

让用户清楚知道内容是否保存、是否同步、误操作能否恢复；新增能力优先连接任务、便签和专注。小艺后续开发与专项验收暂停，现有代码保留，桌面唤醒失败待华为反馈。主分支合并不等于发布。

既有 NS0-NS7 已按用户整体验收收口。智能列表、自定义重复、附件、同步诊断、快速收集、备份和国际化均是已有功能，本轮只改进体验，不重复建设。任务便签关联沿用既有 TASK_NOTE_LINK_IMPLEMENTATION_PLAN.md 和 TASK_NOTE_LINK_ROADMAP.md，不能提前标记已实现。

## 执行顺序与责任

1. E1：鸿蒙任务编辑完善。桌面端维持读写兼容，本阶段只更新桌面方案和验证契约，不强行重做桌面编辑器。
2. E2-E6：双端体验收敛，包括状态表达、控件规范、任务与便签布局、撤销和偏好持久化。
3. E7：双端任务便签关联，执行已有 L1-L5。
4. E8：回收站、便签历史、统一搜索分别交付。
5. E9：按实际需求选择模板、检查清单、专注历史及自动备份。端到端加密单独立项，不列入近期承诺。

每次完成一个明确子阶段，分别报告两端修改、自动化证据、人工验收及遗留风险。未经用户要求不升版本、不提交或推送、不发布。不将编译/宿主测试当作真机、视觉或真实 S3 验收。

## E1：鸿蒙任务编辑

### E1a 统一草稿与原子保存

- 在任务编辑内部配置自定义重复，子编辑器的“应用”只更新内存草稿；取消子编辑器保留先前草稿，取消整个任务编辑不写任务、规则、回执或同步状态。
- 最终只有任务编辑的“保存”提交。标题、备注、分组、重要性、当前项日期/提醒与规则创建/替换同一 RDB 事务；规则保持不变时不重置计数、锚点或 UUID。
- 继续复用 RecurrenceQueue、规则协议与严格版本快照检查。过时任务/规则、已删除/归档/完成的当前项、未知关联一律报冲突，不覆盖。
- 自定义转不重复或普通重复复用已有原子解除关联事务。普通转自定义首版仅转换当前项，不改其他普通系列任务，必须明确此范围。
- 新规则/修改规则的日期以规则表单为准，同步到任务草稿摘要；当前任务的独立提醒保留为绝对时间，变化后提示用户复核，不自动发明相对提醒。
- 提醒注册、卡片刷新、UI 重载在提交后执行。提交后失败不能把已保存说成未保存，也不能要求重新创建。
- 不新增数据库字段，不改 S3 Object Key、规则文档 v1 或备份 v2；现有桌面端能继续读取规则、墓碑和任务字段。
- 普通重复“本次及以后”与新建任务入口保持原有语义，不顺带重构；普通任务其他保存路径的整体事务化作为后续独立检查项。

### E1b 表单与预览

2026-09-11已实现，用户已确认测试通过：采用胶囊选项、间隔/次数加减和直接数字输入，纯函数预览最多5次（含当前项）。未改规则保留原锚点/计数，修改后按新规则预览；原生时区换算与保存共用，预览本身不落库。不改变E1a事务与双端数据协议。

复用规则引擎，加入间隔步进器、频率/结束条件按需展示和未来几次计划日期预览。预览不创建任务，不改变 generated_count；正确处理月底、闰年、时区、夏令时、次数/日期终止。首版不做相对提醒持续联动。

手机/窄分屏单列，宽平板采用有限宽度居中面板，底部操作固定、正文滚动；不引入全局窗口监听。亮暗、中英文、大字体、键盘避让沿用主题与资源体系。

## E7：任务与便签关联

严格先 L1 协议/迁移，再 L2 原子操作、L3 同步/备份、L4 UI、L5 发布验收。便签创建关联任务、任务打开资料、便签查看关联任务。不复制附件，解绑不删内容，重复首版仅关联当前实例，不新增主导航。

## E8：恢复与查找

- E8a 回收站：先冻结删除/恢复/保留策略，保留同步墓碑保护长期离线设备。已有短时撤销不能代替完整回收站。
- E8b 便签历史：首版本地快照，恢复前预览，当前版本保留，禁止直接覆盖或暗示历史自动跨端同步。
- E8c 统一搜索：同一入口搜索任务、便签标题正文与附件名称，按类型分组显示摘要。首版不做 PDF 内容和 OCR，不引入重型索引。

## E9：后续候选

模板与单层检查清单分开交付，重复继承语义双端先冻结。专注历史首版本地统计，暂停与休息不计入，失败不影响计时或已审核实况窗。自动轮换备份区分元数据/完整附件、缺失文件和恢复预览；同桶备份不等于独立灾备。

加密需要密钥恢复、旧端兼容、大附件和迁移设计。无服务端不能承诺忘记密码可找回。暂不增加多人协作、复杂项目管理、排行榜、跨端活动专注控制或大而全 AI 助手。

## 验证与交付

数据改动覆盖新旧库、事务回滚、重复请求、并发编辑、完成/删除竞争；共享算法采用 Rust/TypeScript/ArkTS fixture 对照。同步改动另验真实双端 S3 离线/冲突/重试。UI 覆盖亮暗、中英文、大字体、桌面窄宽/缩放、手机/平板/键盘。

桌面代码改动使用 pnpm check/build、cargo fmt/check 与相关单测；鸿蒙使用生产代码宿主测试、国际化检查、DevEco CLI 构建、可用 MCP 检查和原生设备验收。纯文档改动只校验链接/差异，不声称完成全量构建。所有版本、签名、发布操作独立授权。
