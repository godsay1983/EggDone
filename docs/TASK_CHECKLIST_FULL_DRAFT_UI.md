# 任务设置与检查清单统一草稿：P1d-2b-2

日期：2026-09-14。开发分支实现，未发布；本轮未安装设备，手机/平板和真实 S3 验收待进行。

## 用户入口

打开已有任务的清单计数，或“更多 → 检查清单”，展开“任务设置”：
- 同一份草稿编辑标题、备注、日期、时间、提醒、分组、重要程度、重复设置及清单。
- 日期无时间时按全天保存；修改已有定时任务的日期保留时间。提醒独立设置，不随日期暗中移动。
- 设置默认折叠；清单仍是首屏主体。桌面沿用紧凑字体，鸿蒙按钮自动折行，展开设置后增加可滚动高度，底部保存/取消不进入滚动区。
- 自定义重复打开已有规则编辑器的草稿模式；子面板确认只应用到外层草稿，子面板取消不应用新配置，最终保存才写库。
- 原有普通“编辑”入口仍保留。本阶段在清单面板提供完整编辑，不重构所有历史快捷操作入口。

## 重复语义

- 默认保留当前重复设置；打开面板本身不会转换普通重复。
- 原普通重复选择“本次及以后”后，转换为独立自定义规则与清单定义，后续继承当前内容和顺序，子项未勾选。
- 明确选择每天、每周、每月、工作日或自定义，表示更改本次及以后规则；界面有影响范围说明。
- 工作日从不早于所选日期的下一个有效工作日开始；每月使用已有重复引擎的月日截取规则。
- 自定义规则编辑初值使用剩余总次数；用户明确修改次数或改用新的重复预设时按新配置执行。
- 停止重复保留历史、当前清单与原提醒。已完成、只读、历史或身份不明确的实例不允许配置新规则。
- 沿用“保留规则 + 本次及以后”时，若日期与原规则不一致，保存明确报错；可选择仅本次或在自定义规则中明确调整，不暗中改变旧规则。
- 后续定义最多 20 项。过大的导入清单仍可仅编辑当前，不自动截断。
- 不修改已生成的其他任务，不重写历史定义。

## 实现边界

两端共享 ChecklistTaskDraft 纯草稿编排，复用 P1b-2 的完整保存事务和 P1d-2a 的冲突/重试会话。
时间解析委托已有引擎：桌面增加只读 resolve_checklist_rule_time 命令调用 Rust 时区解析；鸿蒙使用原 RecurrenceTime 与时区 provider。
没有新增数据库迁移、同步对象、系统权限或依赖。原提醒未修改时允许保留过去时间，新设置的提醒必须在未来。
鸿蒙保存后刷新任务，提醒时间或标题变化时取消原注册；新提醒有效时重新注册。提交后的刷新错误不再次保存任务。
桌面提醒仍由现有数据库扫描流程读取已提交值。

## 验收步骤

1. 打开清单 → 任务设置，同时改日期、提醒、分组、重要程度和子项；取消后重开应无变化。
2. 再修改并保存，检查任务列表、清单、日期及提醒；两端同步后核对一致。
3. 原普通重复选择本次及以后，保存并完成当前任务；核对下一次内容、未勾选状态和日期。
4. 自定义重复先修改并取消子面板，再取消外层；原规则应不变。确认子面板后也必须最终保存才生效。
5. 检查手机/平板小窗、英文、大字体、键盘弹出时的设置选中状态和底部操作；提醒修改/清除后验证系统通知。
