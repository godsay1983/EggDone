# 检查清单同步实现与验证

日期：2026-09-14。阶段：P1c-2。两端版本仍为桌面 1.1.0 / 鸿蒙 1.2.0，schema 仍为 20 / 21。

## 已实现

- 复用现有整场同步锁、S3 签名器和父任务/重复规则同步，不新建独立后台同步循环。
- 与任务对象同目录的 `task-checklist-definitions.json`、`task-checklist-items.json` 分别使用 definitions / items v1 协议。同步开始前校验保留路径及对象名冲突，失败不上传父任务。
- 顺序：任务与规则同步 → 下载定义、下载子项 → 同事务合并两者并补齐 → 条件上传定义 → 条件上传子项 → 原有便签、关联与附件流程。
- 两份下载都有效后才合并；缺失父任务/规则的孤立记录按协议保留，不猜测生成。已有父任务上按原规则确定性补齐，不覆盖用户修改、勾选或墓碑。
- 下载仅 404 表示无对象；403、401、网络错误、损坏 JSON/UTF-8、缺少或弱 ETag 都失败，不按空数据覆盖。每份文档上限 4 MiB。
- PUT 必须持有本客户端、本目标对象的最新 GET 回执：已有对象用 If-Match，404 用 If-None-Match。HEAD 只用于发现变化，不授权写入。
- 409/412 或上传期间本机依赖变化时，重新同步父任务/规则并重新下载两份清单，整个实体会话最多两轮；耗尽后保留待同步，后续会话可以重试。
- 空本地领域且 GET 404 时不创建空对象，但确认该领域已完成。没有重复规则的旧配置不要求创建空规则文件；非空规则仍必须已完成对应本机版本的上传确认。
- 合并、补齐、快照采集在一个本地事务中；网络请求在事务外。确认时重新比较父任务、规则和两份清单正文、版本及配置世代。
- 定义与子项独立记录 synced_revision/ETag。定义成功、子项失败时保留定义回执，子项继续待同步，不伪造整场成功。
- 修改桶、路径或凭据使两领域 revision/generation 增长并清除 ETag；旧响应不能确认新配置，改回原配置也不复用旧世代。
- 两端同步汇总新增 checklists 待同步领域；桌面同步诊断显示“检查清单”，鸿蒙待同步详情显示同名领域。首页继续复用已有“待同步/已同步”含义，不新增按钮。
- 自动轮询观察两对象的组合 token；只有完整上传回执才能更新已确认 token，配置变化会重置观察状态。

## 自动化证据

- 桌面 `cargo test --locked --lib --quiet`：298 通过、12 默认忽略。其中新增 7 个清单测试覆盖独立 ACK、原子合并、版本/世代失效、真实签名 HTTP 传输、部分失败和有界重试。
- 默认忽略的清单 loopback 测试由下述跨端脚本显式运行 seed / verify 两次并通过；其余 11 个旧的外部 S3 测试本轮未运行。
- 桌面前端：36 个文件、326 项 Vitest 通过；`pnpm check` 为 0 errors / 0 warnings，`pnpm build` 成功。
- 鸿蒙 `node scripts/test-task-checklist-sync.cjs`：16 个事务/会话场景及轮询世代检查通过。使用生产 ArkTS、隔离 SQLite 与可控传输替身。
- 鸿蒙生产协议 84 样例、完整编辑 25 组、继承 19 组、重复快照 19 组、原有同步会话 42 组、关联会话 9 组、传输 62 组及同步汇总 19 场景通过。
- 鸿蒙 Debug 构建通过；原有异常处理、弃用 API 和重复组件 id 警告未在本阶段扩展清理。

跨端实传命令（从鸿蒙仓库运行）：

```powershell
node scripts/test-task-checklist-http.cjs --desktop=D:/Develop/EggDone
```

该脚本临时启动仅监听 127.0.0.1 的内存对象服务，校验 SigV4 与条件写，不读取用户数据库、文件或云端凭据。它调用桌面生产同步代码播种，使用鸿蒙完整 SyncService 下载并修改，再调用桌面生产同步代码验证回传。还覆盖断连、403/500、损坏响应、独立回执、模拟冲突，以及真实抢先写入导致的 412 与双方数据保留。服务及数据库在脚本结束时关闭。

共享同步样例：`fixtures/task-checklist-sync-v1.json`。基础合并、墓碑、身份和继承契约仍由原共享协议/继承样例覆盖。

## 未完成与下一步

- 尚未在用户手机/平板安装，不访问用户桶；真实设备、实际 S3/MinIO、旧端混用与完整业务验收留在 P1e/P4。
