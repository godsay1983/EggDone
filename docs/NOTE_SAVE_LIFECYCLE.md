## 行为矩阵

| 场景 | 两端行为 |
| --- | --- |
| 空白新便签，或只改颜色/置顶 | 未创建记录的空草稿关闭时丢弃，不产生空便签 |
| 只添加图片或文件 | 沿用附件流程先确定便签身份；空正文用文件名或默认标题，不能按空草稿丢弃 |
| 已有便签快速连续输入 | 每个UUID保留最新快照，串行写入；同时调用保存会等待同一批在途保存，不提前报告结束 |
| 正文保存失败 | 待保存内容仍在内存队列，错误可见；点击编辑器“重试”再次提交，不要求重新输入 |
| 创建成功，后续文字/颜色/置顶保存失败 | 保留已创建UUID和完整草稿；重试更新同一条记录，不再次创建 |
| 保存过程中继续编辑草稿 | 当前快照完成后继续保存新变化，全部完成才将草稿切换为已创建便签 |
| 返回/完成/切换便签 | 先等待保存，失败保留当前编辑内容，不静默关闭 |
| 附件正在处理 | 阻止关闭或切换；附件错误仍使用附件区自己的处理入口 |
| 已有便签换色/置顶失败 | 不展示无效的正文重试按钮；重新执行原操作。新草稿的颜色/置顶仍纳入草稿重试 |

保存失败指本地写入失败，不等于S3同步失败。离线时本地数据库正常，仍可保存；同步状态独立沿用E2。

## 实现要点

- `NoteStore`按UUID保留待写快照，数据库成功后才移除；旧快照失败不能覆盖后来输入。
- 多次flush共用在途Promise；失败停止自动重试，等待明确重试或下一次编辑。
- 草稿创建和后续更新不是新增数据库事务；使用当前编辑会话的已创建身份完成恢复，错误不销毁草稿。
- 桌面：返回/完成、新建、打开其他便签、切换任务视图/智能列表、定位指定任务、编辑器内Ctrl+F均先经过保存保护。
- 鸿蒙：沿用工作区切换及返回任务保护，补充编辑器关闭、设置、分组、智能列表导航前保存。
- 重试入口只在有待保存正文或新草稿失败时出现，复用现有中英文“重试”与按钮样式。
- 刷新列表不能清掉仍有待写正文的错误提示；换色/置顶先等待正文写入。
