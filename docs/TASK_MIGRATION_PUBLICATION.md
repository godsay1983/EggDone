## 共享契约

暂存根为当前桶中的 `eggdone-migration-staging/v1/<SHA256(mainKey UTF-8)>/<operation UUID>/`。
它是独立不可变种子，不是活动同步根；存储权限若仅允许旧对象前缀，本步会因权限不足停止。
数据按摘要存储到 `objects/<SHA256>`，最后条件创建 `manifest.json`。
同字节可共享一个对象键；文件进度仍以逻辑文件名计数。没有改写旧空间的 PUT 或 DELETE。

清单采用无空白 JSON 数组，稳定跨 Rust/ArkTS 序列化：
```text
["eggdone.migration-seed.v1", operation, sourceBinding, cloudManifestHash,
 [[sourceKey, etagOrNull, fileNameOrNull, sizeOrNull, shaOrNull], ...8 domains],
 [[fileName, size, sha], ...]]
```
sourceBinding 继承已验证云快照的 endpoint/region/bucket/mainKey/pathStyle/allowHttp 摘要。
不发布访问密钥、本机数据库、私有历史或本机恢复快照。云端原始数据和引用附件仍是原有明文格式，不提供端到端加密。

app_metadata 中 `migration.backup.publication.v1` 持久保存 operation、云快照 operation/hash、来源、文件清单、确认状态、完成文件名和 published。
该键在本机快照排除的 migration.backup.* 范围内；进度写入不会使源快照自行失效。
只有云快照身份和摘要相同才复用目标；新的快照需要新计划与重新确认，旧暂存保留。

## 写入与恢复规则

- 整体沿用同步会话锁；网络传输不持有数据库事务。
- 确认摘要必须与当前计划匹配；源库、配置及快照变化即停止，不静默更换目标。
- 开始与发布前重读八个旧云对象，核对存在状态、强 ETag 和原始摘要。
- 每个目标先 GET；不存在才以 If-None-Match: * 创建。409/412 不是成功证明，必须再次读取并核对大小和 SHA-256。
- 持久进度只用于恢复展示，每次继续仍读取所有目标；不根据“已完成”跳过校验。
- 最后条件创建清单，再读回清单和全部文件，之后才记录发布完成。
- 已观察到清单或本机已记录发布完成时，目标缺失/损坏即停止，不拿旧快照自动修补；目标不同内容绝不覆盖。
- 小文件 GET 保留 16 KiB 的有界错误响应空间，以容纳 S3 的 404 XML；200 内容仍严格受预期文件大小限制。错误文案不泄露底层凭据或响应。
- 文件数最多 10000、文件总量最多 512 MiB、单文件最多 20 MiB，沿用前置快照更严格的元数据/附件限制。GET、PUT 目标只能属于本次暂存命名空间。

## 尚未完成

1. 本阶段没有活动空间选择、协议升级、原子切换、其他设备加入或多设备同时迁移的仲裁。不同设备可能产生独立暂存种子，不会自动选出一个。
2. 旧空间没有被冻结。八对象复核不是原子云事务，其他设备仍可能在复核后写入；切换前必须再次收敛来源并做领域约束校验。此暂存清单不能直接用作激活授权。
3. 未接生产终态账本同步、终态优先过滤和远端清理执行器；有同步历史的设备仍禁止永久删除，完整清空回收站仍未交付。
4. 私有快照不是独立灾备，旧私有快照及云端孤立暂存尚无清理 UI，也不会自动删除。用户应注意暂存占用与存储费用。
5. 传输故障/数据库重开自动化不等于应用被系统强杀的原生验收；在清单写入回复丢失且远端清单又被外部删除的极端情况下，未记录发布完成的计划无法证明历史上曾发布，不能据此开放活动空间修复。
