# 清单备份 v4 实现与验证

日期：2026-09-14。阶段：P1c-3。桌面 1.1.0 / 鸿蒙 1.2.0 开发分支，应用版本与数据库 schema 未变。

## 格式与兼容性

- 普通 JSON 和完整备份中的 data.json 升为 v4，必含 task_checklist_items 与 task_checklist_definitions 两个 v1 文档，包括空定义和墓碑。
- ZIP manifest 仍为 v1；附件路径、大小、SHA256、文件预检和安装回滚继续使用现有实现。
- v1/v2/v3 仍按旧契约校验，不允许携带清单字段。缺少清单领域时保留本机已有记录和同步回执，不将缺失解释为删除。
- v4 拒绝缺少新领域、null、错误领域版本、非法记录、身份冲突及未知顶层字段。新版本备份不能交给只支持 v3 的旧应用恢复；请保留升级前备份。
- 导出不包含同步 ETag、revision、ACK、配置凭据或本机编辑操作回执。既有可移植重复实例回执保持原契约。

共享样例：fixtures/task-checklist-backup-v4.json。含两个子项（一个已删除且缺父任务）及两个定义（含空定义墓碑），用于生产解析器和事务测试。

## 导出与恢复

两端从同一事务快照读取父任务、便签、附件元数据、重复规则、关联、清单子项和定义，校验后导出。
桌面 JSON 与 ZIP 共用 capture_export；鸿蒙复用 DataExchangeService.captureExport。

恢复复用原有整笔事务，清单在父领域之后合并；任何领域的校验、写入、回执重置或提交失败都回滚。
完整备份继续走附件安装补偿流程，不在数据事务外单独写清单。

- 按现有清单协议合并，不把恢复解释为重新创建或解除删除。
- 本机子项及定义墓碑优先于备份中的活动副本；空文档不清空当前数据。
- 父任务缺失或仍删除时，不制造父任务、不显示相关子项。恢复本身不推进重复阶段、不生成继承项。
- v4 恢复后两个领域分别增加 revision/generation，清空 ETag 和 synced_revision，保持待同步；备份不是远端上传证明。
- 清除本机清单编辑操作回执，避免恢复后重放旧编辑结果；不导入其他设备的本机回执。
- 清单依赖、后续继承与跨设备同步继续由现有生产同步流程处理。

## 用户可见变化

数据管理的导入预览新增中英文清单摘要：
子项总数、已删除子项数、重复定义数、备份中缺失父任务数。
缺失父任务按子项引用的 todo_uuid 去重统计，包括已删除子项引用；不是本机合并后的缺失数，也不是规则缺失数量。
摘要说明按合并规则恢复，不声称所有记录都是新增。
旧格式显示“本机已有清单和重复清单定义将保留”。

本阶段仍没有清单编辑/勾选入口；这些入口在 P1d 实现。
