日期：2026-09-18。阶段：LC2a-1，候选模型与任务单域隔离原型，纳入本次提交。两仓库镜像保存本记录和纯原型脚本。

## 结论与授权边界

旧协议不能仅追加一个永久删除字段：当前两端未扩展协议的生产同步内核会在往返序列化时丢掉未知字段。当前按更新时间决胜的普通删除标记，也不能替代永久删除凭据。

候选方向是新协议独立空间与显式迁移。用户已明确接受参与设备升级、迁移前汇合离线修改、保留旧空间，以及旧版后续写入不自动进入新空间的成本。此确认是后续实现方向，不是授权迁移实际数据或删除旧空间。

本轮未修改生产 Rust/ArkTS 同步实现、数据库 schema、备份格式或应用版本。原型不被任何应用导入；没有清空按钮、物理删除或实际用户空间迁移。LC2a 总门槛仍未完成。

## 候选数据与合并

代码：scripts/purge-compat-prototype.cjs。

- envelope 绑定 protocol 与 space_id，包含普通 records 和 terminals；仅模拟 todo、note。
- 普通记录保存 kind、uuid、updated_at、deleted_at、body；终态仅保存 kind、uuid、operation_uuid、purged_at，不携带正文。
- 同一空间内按 kind + uuid 联集终态；终态存在即压过任何时间戳的普通记录，包括恢复和旧备份。终态不按时间过期。
- 同一身份的多个终态以规范 JSON 最小值选取元数据出处，不用时钟判断是否仍然永久删除。普通记录按时间及规范 JSON 决胜。
- 清空候选操作要求仍在回收站且与预览全量指纹一致；预览后的编辑/恢复返回冲突，重复操作不恢复正文。
- 保留已有终态后导入旧备份；从未获得过终态的独立新库不能凭空识别历史删除，新设备加入仍待全量凭据门槛实现。
- 输入采用严格字段、UUID、安全整数、重复身份和空间校验。原型限制 2 MiB、每类 1000 条、32 层；超过则拒绝，不截断终态。这不是正式容量与分页方案。

合并证明只针对此候选表示；原型使用聚合 checkpoint，不等于决定把现有所有生产领域改为单一对象。

## 同步与迁移原型

测试路径固定为 account/lifecycle-prototype/v1/<space_id>/checkpoint.json；迁移发布标记为 account/lifecycle-prototype/v1/migration.json。均为测试命名，不冻结为正式 Object Key。

新端原型同步要求远端存在、空间匹配且有 ETag，使用 If-Match 合并写入。404、损坏、外来空间、412 或配置变更不返回成功确认，不自动重建缺失根对象。最终回复丢失可重新拉取再合并。

迁移仅覆盖测试 account/todos.json 的合成任务样本：
1. 显式确认并固定源 ETag、目标空间、操作 ID 与 seed 指纹。
2. 校验源对象，按 If-None-Match 创建目标 checkpoint；同请求恢复要求暂存内容相同。
3. 再次检查源 ETag，然后条件创建不可覆盖的迁移发布标记。
4. 读回发布标记后才允许调用方切换本机目标；暂存成功不代表迁移完成。
5. 相同发布请求重试时只验证现有目标，不用初始 seed 覆盖已经继续同步的数据；竞争请求失败，不自动删除旧空间或孤立暂存对象。

调用方尚无持久日志或原生本机目标事务。publish 接收受信构造器生成的 plan，不是可直接加载任意磁盘文件的生产恢复入口；后续持久恢复必须加入完整计划校验、固定批次回执和权限/目标绑定。

## 已知迁移竞争

即使再次检查源 ETag，旧端仍可在检查结束与发布标记写入之间修改旧空间。专门的反例测试证明：此时新空间可发布，但旧端晚到内容仍只在旧空间。

因此不能声称源 ETag 重查能冻结旧客户端或实现无损原子搬迁。迁移预览必须要求离线修改先汇合、旧设备升级并停止旧版写入；保留源对象版本与旧空间供核对。旧空间变化提示及人工处理入口属于后续设计，不宣称本轮已实现。回退旧协议也不能保留新协议终态保证。
