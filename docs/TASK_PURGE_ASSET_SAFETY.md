## 缺失附件下载

- “准备本机快照”优先复用已经校验的备份副本，再尝试本机 UUID 派生路径；本机文件缺失或损坏时只读下载。
- 对象来自当前保存的同步配置，使用原有 Object Key 派生和凭据保险库；包含回收站附件、原图及预览。不接收界面传入的 URL 或路径。
- 仅写入应用私有 migration-backups/<operation>/ 文件，不覆盖本机 note-assets、不恢复删除记录、不改缓存状态、不写云端。
- 关闭同步开关不禁止用户主动点击准备快照时的只读取件；面板预先说明缺失文件会联网下载。此行为不启用自动同步。
- 下载前后重新检查完整本机源快照，目标配置、epoch、业务记录或 dirty/ACK 变化时拒绝确认。
- 校验固定清单中的大小与 SHA-256，落盘刷盘后再读回；下载不是“文件完整”的替代条件。
- Rust 附件 GET 改为按预期大小有界读取，拒绝超长/截断响应和非 200 状态；ArkTS 使用已有有界 NetworkKit 下载。
- 断网、错误凭据、文件不存在、摘要不匹配均保留未完成计划和已校验副本，下次准备复用。失败不更新 verifiedAt，不清 dirty、不写 ACK、不创建同步 epoch。
- 原空间和所有设备均已丢失的附件仍阻止完整备份，不静默略过；尚未增加用户接受不完整备份的选项。
- 重新校验仍只验证已经保存的文件；要补齐文件应点击“准备本机快照”。
- UI 区分同步配置/凭据不可用、远端下载失败、本机文件缺失、源变化及隔离恢复失败，不展示密钥、URL 或服务响应正文。

## 条件清理

- 原有延迟清理使用同一原生 S3 客户端，本轮为其增加强 ETag 与签名 If-Match。
- HEAD 必须返回 200、匹配大小/摘要及有效强 ETag，随后 DELETE 必须携带该 ETag。缺失、弱值、通配符及非法 ETag 不发 DELETE。
- 409/412、权限错误、不支持条件删除、网络结果不明均失败，不重试为无条件 DELETE。
- 仅 200/204/404 视为删除请求已完成；202 等不视为完成。HEAD 404 为文件本来不存在。
- 条件请求头只作用于本次 DELETE，不污染共享客户端的后续 GET/PUT。
- 这修复的是对象版本竞态；不等于新空间终态传播和远端清理队列已经接入。
- 已测试的 SeaweedFS 4.34 会执行 If-Match；不能据此声称所有 S3 兼容服务都遵守条件请求。正式迁移仍需存储能力验证，禁止无条件降级。
- 不删除用户旧空间、独立备份或对象历史版本，不承诺取证级擦除。
