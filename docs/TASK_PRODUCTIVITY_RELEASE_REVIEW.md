## 升级与使用边界

- 升级前先导出并保留备份；需要附件原件时使用完整备份，普通 JSON 仅含附件元数据。
- 两端尽量同时升级。旧客户端不能显示/管理新增的清单和模板，也不能导入 v5 备份；不能用旧二进制直接打开已迁移的新库。
- v1-v4 备份缺少模板时会保留本机模板；恢复合并遵循墓碑保护，不等于撤销删除。完整备份内 data.json 同样使用 v5。
- 清单勾选不会自动完成主任务；重复的“仅本次”和“本次及以后”分别影响当前实例及系列定义。
- 模板与任务彼此独立；复制/模板使用重置旧提醒及完成状态，确认草稿才创建。模板首版不携带旧日程、附件或关联。
- 批量首版不解析标题中的时间，不将 Markdown 已勾选标记变成完成任务；重复标题只提示。只恢复已确认提交的请求，不承诺未提交草稿跨进程保存。
- 结束批次恢复只清除本机待确认记录，不删除已经创建的任务；核对任务列表后再决定是否重新创建。
