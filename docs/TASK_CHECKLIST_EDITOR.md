# 检查清单完整编辑事务（P1b-2）

日期：2026-09-14。两端内部持久化能力完成，尚无产品入口。
前置存储见 [P1b-1](TASK_CHECKLIST_STORAGE.md)，整体进度见 [roadmap](TASK_PRODUCTIVITY_ROADMAP.md)。

## 本轮实现

- 一次事务保存标题、备注、日期/时间、提醒、分组、优先级、重复设置和当前清单。
- “以后”操作同事务停止旧规则、建立新规则与不可变清单定义、保存当前实例清单和本机回执；任何写入或提交失败全部回滚。
- 即使日程没有变化，只修改以后清单仍使用新规则 UUID；旧规则/定义保留，不改变历史实例。
- 未修改的日期与提醒保留；不调用会清空提醒的旧独立规则编辑路径，不在数据库事务中调用系统 API。
- 暂无新 Tauri command、鸿蒙 store/UI 调用，不修改已有任务编辑界面或小艺、实况窗。

## 调用契约

桌面：`src-tauri/src/task_checklist_editor.rs` 的 `save`。
鸿蒙：`data/repositories/TaskChecklistEditorRepository.ets` 的 `save`，类型在 `models/TaskChecklistEditor.ets`。

请求包含：
- task：P1b-1 的清单保存请求，含稳定 operation_uuid、父任务版本和完整子项快照。
- fields：due_date、due_at、reminder_at、group_uuid、priority、repeat_rule，nullable 字段明确传 null。
- expected_rules：完整重复规则文档快照；当前采用保守冲突检查，其他任务规则变化也可能要求刷新重试。
- mode：keep / replace / stop；replaces_uuid 为被替换或停止的活动规则。
- replacement：新规则 UUID、经过既有重复引擎校验的 schedule 和 timezone_id。
- future_entries：新规则的后续清单定义，最多 20 项；可为空，不能用缺失定义代替清空。

返回 updated_at、rule_uuid、reminder_changed。重放回执可能返回之前的结果，调用方须重新读取当前任务，不能把旧草稿覆盖回界面。
这是编辑已有父任务的内部 API；新建入口接线仍待 P1d，P1b-1 的调用方拥有事务模式可用于原子新建。

## 三种模式

| 模式 | 行为 |
| --- | --- |
| keep | 只保存当前任务和清单，不修改高级重复规则与定义；不允许偷偷将已关联高级系列切换成旧式重复。 |
| replace | 新建或分叉高级规则，原规则停止；定义从新系列 index=2 生效，当前任务单独保存清单。 |
| stop | 停止当前有效高级规则或清除旧式重复；保留日期、提醒、当前清单及历史定义。 |

规则 UUID 不复用；不能向已有旧规则补一份可变定义。缺少规则上下文或当前实例关联不匹配时拒绝，不猜测或重启历史系列。
仅本次编辑不改变未来模板；当前清单项保留自身身份，不伪装成新定义的继承项。
已完成任务不能通过本接口修改未来规则；已归档/删除任务拒绝编辑。

## 日期与提醒

共享请求使用规范日期语义：全天仅 due_date，定时仅 due_at；两者不能同时存在。
定时规则按既有时区服务计算，并校验与任务日期匹配；不引入另一套日历算法。
鸿蒙本地全天任务仍保留现有 due_at 投影；日期未改时保留原投影，日期改变才重新映射。桌面全天任务 due_at 为 null。
用户明确修改的提醒必须晚于提交时刻；原值不变时即使已经过期也保留，避免仅改清单失败或意外重新安排提醒。
reminder_changed 只供产品层提交成功后协调系统提醒。系统提醒注册、失败反馈和原生触发验收不属于已完成证据。

## 原子性与重试

- 比较父任务版本、完整子项及规则快照，防止旧草稿覆盖更新。
- 复用 IMMEDIATE 事务；标题/清单、规则、定义、父字段、标脏和回执一起提交。
- 外层回执保存在 app_metadata 的 checklist.editor.v1 命名空间，仅留本机。
- 内部基础保存回执使用独立 UUIDv5 域 eggdone:checklist-editor-body:v1；存在内部回执却缺少外层回执时拒绝，不能跳过父任务校验。
- 同一操作 UUID 和负载重试返回原结果，改变负载必须使用新 UUID；now 不进入负载指纹，允许稍后重试。
- 无内容变化不提升父任务时钟或清单 revision；操作回执仍保存。
- 分组必须存在且未删除；非法日期、旧草稿、无效规则、身份复用、超限、时钟溢出都拒绝。
- 事务竞争/存储错误向调用方返回，不无限重试，不把异常当成保存成功。
