## 功能入口

| 功能 | 如何操作 | 必须说明的边界 |
| --- | --- | --- |
| 任务与便签关联 | 任务更多中的关联便签；已保存便签的添加/关联管理，可创建任务或关联已有内容 | 解绑不删任务、正文或附件；重复任务只关联当前实例；每个任务本地新建最多 20 条关联 |
| 回收站 | 更多中的回收站；宽平板侧栏管理区域 | 先预览再确认；不提供永久删除或定期清空；仅归档任务不在回收站 |
| 便签历史 | 已保存便签编辑器的历史入口 | 仅本机文字历史，不是附件历史或永久备份；最多每便签 100、全库 1000 个版本 |
| 统一搜索 | 更多中的统一搜索；鸿蒙宽平板侧栏或已保存便签编辑器 | 查任务标题/备注、便签标题/正文、附件文件名；不含 PDF 正文或 OCR；搜索不会自动打开或下载附件 |
| 固定智能列表 | 在智能列表中固定常用筛选 | 最多两个；固定与当前筛选独立，属于本机偏好，不跨端同步 |

回收站恢复任务会保留标题、正文、完成状态和任务日期，但清空旧提醒、普通重复/系列及归档状态，不重启自定义规则，不自动恢复旧关联。恢复后需要重新检查提醒、重复和关联。

便签恢复只能带回符合恢复条件的附件元数据；远端原件已清理、丢失或无法下载时，不能保证原文件可用。文字历史恢复不回滚附件、颜色、置顶或关联。升级不会补造升级前的文字历史。

## 混用与备份兼容

这里的“新端”指确实包含本批关联/历史/搜索实现的构建，而不是只比较版本字符串。“旧端”限定为仍支持既有任务、便签、附件及重复规则协议的客户端，更早版本不能一概承诺兼容。

| 组合或操作 | 行为与建议 |
| --- | --- |
| 新桌面 + 新鸿蒙 | 使用既有实体对象和独立 `task-note-links.json` v1 同步关系；两端都升级并验收后，再向用户承诺完整关联流程 |
| 新端 + 上述旧端 | 旧端仍按原协议处理已有内容，但不会显示/维护关联或新历史入口；新端收到明确的实体删除后协调关联墓碑；这是协议设计，用户实际旧包混用仍需 L3d3/L5 验收 |
| 在同一设备直接安装旧二进制打开升级后的库 | 不支持；数据库版本保护会拒绝超出支持范围的库。跨端协议兼容不等于本机数据库可降级 |
| 新端导入有效 v1/v2 数据备份 | 保留当前关联，不把旧备份缺少 links 字段当作删除；实体删除仍按事务协调 |
| 新端导出普通 JSON 或完整 ZIP | 数据文档 `format_version: 3`，包含关联记录及解绑墓碑；ZIP 外层 manifest 仍为 v1，不能混淆两层版本 |
| 只支持 v1/v2 的旧端导入新 v3 备份 | 不支持。不得手改格式版本或删除字段骗过校验；先升级目标客户端 |
| 恢复已解绑关系的旧备份 | 恢复实体不自动重连，本机解绑墓碑继续保护；需要用户显式重新关联 |
| 本地文字历史的迁移 | 不随 S3、应用 JSON 或完整附件 ZIP 导出；恢复后的当前文字正常同步。系统整库备份可能含历史，不承诺所有备份方式均排除它 |

元数据 JSON 不包含图片/文件原件；完整 ZIP 也必须核对缺失文件提示与恢复预览，不能把元数据数量当作原件完好证明。同一个同步桶不是独立备份；不要手工删除云端墓碑、links 或修改同步对象来“修复”冲突。

## 安全升级步骤

1. 在旧客户端先保存当前编辑内容，确认任务、便签和附件各自状态。未同步的数据仍可能只在本机，不因首页显示文字已同步就假定所有附件已上传。
2. 通过数据管理分别保留元数据备份和包含附件的完整备份；确认导出成功、可预览且没有未说明的缺失文件。备份放在独立安全位置，不覆盖唯一旧备份。旧端不能导出的本机偏好等信息另行记录。
3. 记录两端原版本、包身份、当前数量和少量可核对样本；敏感正文、凭据和用户原数据库不提交到 Git，也不用来注入故障。
4. 使用经过核对的正式升级包保留数据覆盖安装，不卸载重装、不清库。启动后检查任务/分组/便签、已有附件可打开、日期/重复未改变和本机设置。
5. 两端升级后，使用用户认可的专用测试内容验证创建关联、双向打开、解绑、删除/恢复、离线重试；提前说明测试内容可能同步到其他设备，结束只清理这批内容。
6. 核对来源便签编辑未保存时的保存保护，检查搜索返回、历史恢复、原提醒状态以及窄窗口/手机/平板操作。故障时保留备份和未保存内容，不直接降级二进制，不修改 schema 标记绕过保护。

本轮没有执行以上真实用户升级步骤。若恢复或启动失败，先保留升级后的数据和旧备份供诊断，在授权的隔离环境复现；不能把唯一用户库覆盖为旧备份后声称问题已解决。
