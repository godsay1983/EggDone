# 双端保存与同步状态表达

更新：2026-09-11。E2a已提交；E2b附件明细与重试已开发，用户确认本轮验收通过，未发布。

## 三个独立维度

1. 本机保存：只有编辑器或仓库写入成功才能称为已保存；同步摘要不能推断草稿已保存。关闭同步时显示“仅本机”，不声称未保存的输入已经落库。
2. 内容上传：任务、便签、附件元数据及待上传二进制均可能各自成功或失败。有新修改或待上传内容时，上一轮成功不能覆盖当前待处理状态。
3. 原文件下载：看到附件元数据或缩略图不代表本机有原文件。图片和文件仍按需下载，下载状态由附件本身展示；下载失败不伪装成上传失败。

不增加数据库字段，不修改S3键、合并规则、ETag、回执、备份或重复任务协议。不增加自动下载，不修改重试次数或退避时间。

## 首页摘要契约

按以下顺序判断；使用已经应用的同步配置，不使用设置页尚未保存的开关。

| 条件（按优先级） | 中文摘要 | 英文摘要 | 含义与操作 |
| --- | --- | --- | --- |
| 同步关闭 | 仅本机 | Local only | 保存后的内容留在本机；入口仍可进入同步设置 |
| 已启用但凭据缺失 | 待配置 | Set up sync | 完成同步配置 |
| 本轮仍在执行/重试 | 同步中 | Syncing | 等待本轮结果，不能提前报完成 |
| 网络错误 | 离线 | Offline | 已保存的本机内容不受影响；连网后重试 |
| 冲突未解决 | 待重试 | Retry needed | 稍后重试，不能称已合并成功 |
| 有已知附件上传失败 | 附件失败 | Upload failed | 重试并检查附件；不掩盖部分失败 |
| 其他同步失败 | 同步失败 | Sync failed | 检查设置和诊断，保留原始失败详情 |
| 有本机修改/待重试标记 | 待同步 | Pending | 保存到本机不等于已上传 |
| 有待上传附件 | 附件待传 | Uploads pending | 上传链路未完成，包括二进制已上传但元数据尚未确认 |
| 本轮成功且无上述待处理项 | 已同步 | Synced | 本轮内容同步完成；不代表原文件已下载，也不保证其他设备已经拉取 |
| 尚无成功或明确待处理结果 | 未同步 | Not synced | 手动同步；不把未知状态当成功 |

摘要颜色与文案使用同一个状态：执行中、成功、待处理、普通状态不会各自独立判断而相互矛盾。

## 两端接入与差异

- 纯状态选择函数：桌面 `src/lib/sync/syncSummary.ts`，鸿蒙 `services/sync/SyncSummary.ets`。源码及 `docs/fixtures/sync-summary-v1.json` 跨仓库对照，不引入运行时共享包。
- 桌面：底部状态入口和同步设置摘要采用统一状态；时间及技术详情保留在诊断区域。手动完成提示同样使用摘要，不重复刷新诊断后把“诊断读取失败”说成同步失败。
- 桌面：首次启动使用已有运行快照；缺凭据不恢复为成功。同步结束检查回执/运行快照的待上传数量和新修改。诊断读取失败时回退本轮回执；配置变化后的旧结果不能覆盖新状态。
- 鸿蒙：首页胶囊、状态面板标题/说明/配色采用同一选择函数；设置页保留技术错误。保存的启用状态单独投影，未保存的设置草稿不改变首页语义。
- 鸿蒙：现有上传摘要能区分失败数量；桌面现有运行快照只有待上传总数，不能凭总数推断失败数量。因此桌面上传异常仍可显示通用“同步失败”，不虚构精确失败计数。
- 两端待上传查询都排除已上传远端但下载失败的附件。E2b在当前便签的附件管理中补齐失败原因与操作，不增加全局“待下载数量”或全量附件扫描。
- 远端附件清理失败是非阻塞警告，仍保留在诊断/既有提示中，不谎称清理成功，也不把它改为正文同步失败。
- 既有手动同步、设置、诊断/复制入口保留。本轮没有新增首页按钮或改变手机/平板布局断点。

## 用户验收

1. 关闭同步后新增任务：桌面底部、鸿蒙首页显示“仅本机”，任务关闭重开后仍在。
2. 启用有效同步：修改任务后依次看到“待同步/同步中/已同步”；打开状态详情，能看到按需下载说明。
3. 断网修改任务并同步：最终显示“离线”或网络失败摘要，本机内容仍在；恢复网络后手动同步，再确认状态恢复。
4. 添加较大附件并同步，期间继续编辑任务：不能在尚有修改或待上传内容时持续显示“已同步”。阶段可能很短，可结合待上传统计核对。
5. 在另一设备同步带图片/文件的便签：允许首页内容已同步，但附件仍显示需下载；下载失败不能被描述为上传失败。
6. 两端中文/英文、亮暗主题、窄窗口/缩放、手机/平板分屏复看：摘要和详情可读，错误详情可换行；手动同步与诊断入口可达。

入口：两端打开带附件的便签，进入“管理附件”。首页摘要仍表示内容上传状态；单附件标签表示该附件的传输和本机可用性，不能互相替代。

| 附件状态 | 显示 | 说明或操作 |
| --- | --- | --- |
| 本机待传 / 正在上传 | 待上传 / 上传中 | 沿用现有同步队列 |
| 二进制已上传，元数据未确认 | 待同步确认 | 不提前显示全部同步完成 |
| 上传失败，远端未确认文件 | 上传失败 | “重新上传”加入同步队列；需启用同步 |
| 下载失败，远端已有文件 | 下载失败 | “重新下载”，不重新上传 |
| 本机仅有缩略图 | 仅缩略图 | 打开时仍需下载原文件 |
| 仅有远端元数据 | 原文件待下载 | 打开或保存时按需下载 |
| 下载进行中 | 下载中 | 等待当前操作 |
| 原文件路径已记录且传输状态已确认 | 本机可用 | 不等于其他设备已下载；实际打开仍会检查文件 |
| 未知或不一致状态 | 状态待确认 | 不把未知状态当成功 |

- 固定的原因提示分为权限/凭据、网络、校验、文件不可用、未知；这是错误文本分类建议，不是精确诊断。附件卡片不展示原始错误中的路径、URL或凭据；既有同步诊断入口保留技术详情。
- 两端共享 `docs/fixtures/attachment-presentation-v1.json` 及纯状态/重试选择函数；不增加数据库字段、同步协议或全局附件扫描。
- 图片重试只有在远端缩略图元数据完整且本机无缩略图时下载缩略图；没有远端缩略图元数据时直接重试原文件，避免无效重试。文件始终重试原文件。
- 重试进行时禁用入口，并在父级加忙碌保护；重新上传仍受现有同步配置控制。正常按需下载策略、自动同步退避均不变。
- 本轮不新增首页“待下载总数”；避免为了首页展示扫描全部附件或自动下载。详情以当前便签附件为范围。

### E2b 设备验收入口

1. 在设备A便签中添加图片和文件，同步至设备B；设备B打开“管理附件”，原文件未下载时应显示“仅缩略图”或“原文件待下载”，而不是“本机可用”。
2. 点击打开/保存，下载成功后应显示“本机可用”；退出再进入，内容和附件仍能打开。
3. 在原文件尚未下载时断网打开附件：应显示“下载失败”和“重新下载”。恢复网络后重试，应恢复可用，不进入重新上传队列。

5. 中文/英文、亮暗主题、桌面窄窗口与缩放、鸿蒙手机/平板分屏复看：标签、原因说明、重试及删除可读可操作，连续点击不重复发起重试。
