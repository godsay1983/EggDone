# 全领域迁移预览与持久恢复原型

日期：2026-09-18。阶段 LC2a-2a，纳入本次提交。前一阶段提交：桌面 d9dad0a，鸿蒙 4925b30。

本轮只交付隔离 host 原型：云端对象清单、内部备份预览、持久确认/进度，以及进程终止后继续。不是正式迁移功能；不修改生产应用、数据库版本、备份 v5 或同步协议，不开放清空按钮。用户已接受迁移方向，无需再次询问相同成本；每次实际迁移仍必须确认具体预览。

## 当前数据清单

依据两端当前生产代码，而非假设所有记录存在一个 tasks JSON。默认主路径 account/todos.json 下有 8 个元数据对象，包含 9 类记录：

| 源对象 | 数据 | 依赖及迁移要求 |
| --- | --- | --- |
| todos.json | groups、todos | 保留完成/归档/软删除、日期/提醒及重复绑定，不在迁移时调用恢复或推进重复 |
| notes.json | notes | 保留全文、颜色、置顶和软删除；不重新生成 UUID |
| note-attachments.json | attachments | 元数据与 original / preview.jpg 字节分别校验，不把文字成功当成附件完整 |
| recurrence-rules.json | rules | 与任务当前实例及清单定义共同保留，迁移不得执行调度 |
| task-note-links.json | links | 保留关系及删除标记；不复制关联实体 |
| task-checklist-items.json | items | 保留所属任务、勾选状态及删除标记 |
| task-checklist-definitions.json | definitions | 保留规则/首任务和条目定义，不展开新实例 |
| task-templates.json | templates | 独立实体，不跟随来源任务删除 |

附件对象是 account/note-assets/v1/<attachment_uuid>/original 与可选 preview.jpg。原型按附件元数据列举，不依赖桶全量 LIST；保留全部引用，包括软删除附件，不清理孤立文件。

生产依据：
- 桌面 src-tauri/src/sync.rs、s3_sync.rs、recurrence_protocol.rs、task_note_link_protocol.rs、task_checklist_sync.rs、task_template_sync.rs。
- 鸿蒙 services/sync/SyncObjectKey.ets、S3SyncClient.ets、TaskNoteLinkSyncSession.ets、TaskDocumentDomain.ets 及 models/NoteAttachmentSyncModels.ets。

生产允许自定义主 Object Key，推导规则含文件名后缀和冲突校验；本原型只支持以上固定合成路径，不能直接套到任意用户配置。后续原生适配必须复用各端真实 key 派生器。

### 本机数据不冒充云领域

便签历史、操作回执、草稿、偏好、设备身份、缓存路径、凭据、各领域 dirty/ACK 及同步配置世代属于本机状态，不新增同名云 JSON。备份 v5 也不等于完整本机数据库镜像。

本轮保留合成 local_history 哨兵验证切换事务不会随意清表，并未读取或备份真实便签历史。正式迁移需增加本机数据库快照、待上传附件盘点、未上传编辑汇合与目标相关回执/ACK 重置设计；不能只复制云端现有数据就认为本机未同步内容已安全迁移。

### 预览与内部备份

capture 读取全部 8 个元数据对象，再读取附件元数据声明的二进制。每项记录原 key、ETag、SHA-256 和字节数；显式记录远端缺失，不把权限错误或超时视为缺失。主任务对象缺失则拒绝，次级领域允许缺失并显示计数零。

原始字节逐字保存，包括 JSON 空白和未知字段；仅检查 format_version、领域数组形状和附件身份/哈希，不宣称已复用生产领域的全部语义校验或完成跨领域外键验证。原型不更改旧记录，也不按领域顺序触发业务操作。

读取结束后重查每个源对象的存在性、ETag、长度和哈希；确认后发布前再查。任何变化要求重新预览，不把旧确认套到新快照。

预览计数包含全部行，不默认过滤软删除。缺失附件单独列出，保守地阻止确认，包括软删除附件已被旧清理策略回收的情况。后续需定义“已按规则回收”与“活动内容丢失”的分级处理，目前不提供静默忽略。

原型容量限制：总字节 32 MiB、最多 264 对象、每领域最多 10000 行。达到上限拒绝，不截断；正式大文件迁移需要流式处理和可恢复分片，本轮不覆盖。

### 持久确认与发布

独立 SQLite 数据库中：
- local_target：合成 source scope、epoch、本机 revision、活动目标。
- migration：固定计划 JSON、摘要、确认摘要和 prepared / confirmed / complete 状态。
- backup：源对象的原始字节，含显式缺失。
- progress：复制对象与哈希，仅作进度记录，不作远端存在证明。

prepare 将计划和备份放入同一事务。confirm 要求与当前预览摘要相同、无缺失附件，且配置及本机修订未变化。恢复时重新校验计划拓扑、备份内容和大小，不信任已有 progress。

目标使用测试专用 account/migration-prototype/v2/<space>/objects/<source_key_hash>/<content_hash>。创建后读回哈希验证；所有对象成功并再次检查源版本后，条件创建 migration.json 发布标记。发布标记绑定整份计划与摘要，不是正式同步根对象或备份导入格式。

读取发布证明及逐项校验目标后，在同一 SQLite 事务中切换本机目标并记录 complete。配置/本机 revision 变化不覆盖新配置；已提交后的重试只返回既有完成结果，不重置后续配置或数据。

暂存成功不算已迁移。最终回复丢失后，恢复通过相同发布标记识别原计划；若发布对象存在但对应数据缺失，不用旧备份自动修补，停下报告错误。竞争迁移不能覆盖已有发布者。

### 隔离与保留

合成 remote.sqlite 模拟支持条件创建的对象存储，没有 HTTP/S3 网络连接。旧对象不被原型写入或删除。测试目录只由 mkdtemp 创建，并核对父目录、名称和所有权标记后清理；失败证据保留。

确认记录、备份与发布标记含业务数据，因此正式版本不得写普通日志，需按本机敏感数据保存策略处理。SHA-256 是完整性校验，不是针对同权限恶意修改者的认证签名。

## 验证与限制

两端分别执行镜像套件，各通过 43 项检查，其中覆盖 25 个实际子进程终止时点；成功后已清理自身测试目录。LC2a-1 原型回归各 29 项/125 组合并通过；共享契约各 69 项/125 组结合性通过。前一阶段提交前桌面 pnpm check/build、cargo fmt/check 通过，保留既有大 chunk 和 dead-code 提示。本增量未修改生产 UI 或 ArkTS，未重新构建/安装 HAP。

本轮自动化覆盖：
- 8 个元数据对象、9 类记录、original/preview 完整字节保存，源 ETag 不变；本机哨兵不变。
- 未确认及旧摘要拒绝、附件缺失、元数据损坏、附件哈希不匹配、次级领域缺失与后来出现。
- 源读取中变化、备份/计划损坏、配置/本机修订变化、权限错误、外来 scope、计数边界。
- 丢失发布回复、竞争发布、目标缺失/损坏、进度不能绕过验证。
- 10 个实际复制对象各在创建前后终止进程，加发布前后、切换前、事务提交前后，共 25 个时点。父进程只终止自己创建的测试子进程；重新打开原数据库并继续同一操作。

使用 Node 内置 SQLite + 合成对象存储，在 Windows host 上测试真实子进程终止，不再仅靠抛异常模拟进程终止。但这不是物理断电、操作系统崩溃、真实 S3 多对象迁移、ArkData、已发布旧版二进制或真机验收。synchronous=FULL 也不能代替上述验证。

源 ETag 重查不能冻结旧客户端，或保证 8 个对象来自同一业务事务。最终重查之后的旧端晚到修改仍只在保留的旧空间。正式预览必须明确汇合离线修改、停止旧版使用，并提供旧空间变化核对；不能宣称无损原子搬迁。

本轮没有实现将这些旧对象装载为新协议实体的生产导入器，亦未将 LC2a-1 的终态合并自动接到全部领域。新设备加入、现有活动空间切换、旧备份回导仍需完整端到端方案。
