# 清空回收站：正式迁移与验收

日期：2026-09-19。双端代码闭环已接通，提交信息见最新 handoff；未升版、未发布，真实用户空间未迁移或清空。
本文覆盖早期文档的“尚未接通”描述，不把自动化通过等同于真机验收。

## 用户流程

1. 参与设备升级后，先汇合旧空间的离线修改并完成同步。
2. 回收站 -> 迁移准备 -> 检查并准备。空回收站也保留入口。
3. 阅读并勾选旧空间保留、旧版后续写入不自动进入新空间的确认。
4. 首台设备选择“迁移并启用”；其他设备保留原来的同步配置，选择“加入新空间”。
5. 返回回收站，单项、勾选批量或清空全部。确认时固定目标，之后删除的新项目不顺带清空。
6. 显示本机移除、等待同步、云端附件待清理或本次完成。断网/权限错误保留进度，可同步并刷新进度、继续本机清理。

不要求用户修改 Object Key；手工填写 v2 路径不能取得激活权限。
迁移准备内部执行本机快照、缺失附件下载、隔离恢复、云快照和暂存，不再提供多个工程步骤按钮。

## 数据边界

- 固定来源映射：eggdone-space-links/v2/<旧主键 UTF-8 SHA-256>.json，条件创建、读回确认；不同候选不能各自覆盖同一来源。
- 映射 wire 为 [1, oldMainKey, seedManifestString]。来源指纹包含 endpoint、region、bucket、旧主键、path style 和 HTTP 选项，不含凭据。
- 新空间位于 eggdone-spaces/v2/<publication UUID>/。八域封装、引用文件和空终态账本全部核验后才写 ready.json。
- 登记来源前验证八域 schema、实际封装大小及活动附件/关联/清单/重复实例的父记录；软删除关系、停止规则和独立定义不因缺少旧实例而被擦除。
- 已 ready 的空间只验证当前文档，不重放种子，避免覆盖后续修改。文档/账本缺失、损坏或空间不符时停止，不自动补成空数据。
- 本机最终事务同时保存空间证明、主键、epoch、全部 ACK 失效和终态应用。切换失败回滚，回复丢失后按已保存状态续作。
- 加入前保留本机快照，核验并复制仍需保留的本机附件；先应用新空间终态，再允许本机旧内容参与正常合并。
- 本机模式已产生终态的设备可以加入已建立的新空间，保留并传播本机终态，不允许先向旧协议上传。
- 首台创建仍要求旧空间已同步稳定；已有本机终态且尚无目标空间时，不通过删除终态或伪造成功绕过检查，应由已稳定的设备先建立目标再加入。
- 附件证据在正文删除前保存，复用已有目标绑定和 If-Match 清理。真正改换存储目标不把旧清理任务重定向到新桶。
- 旧空间、暂存种子、迁移恢复资料、独立备份及对象存储历史版本不在清空范围。失败前复制的未引用文件也不在本轮自动回收范围。
- 同步进度采用保守判断：账本未确认、整体同步失败或仍有脏域时不显示全局完成；清理权限不足不能回滚已传播的删除。
