# 双端任务效率功能实现方案

日期：2026-09-14。
范围：任务内检查清单、任务模板与快捷复制、多行文本批量创建任务。
基线：桌面 1.1.0 / SQLite 19，鸿蒙 1.2.0 / RDB 20。
状态：P0/P1a/P1b/P1c 已提交；当前 SQLite 20 / RDB 21，清单网络传输与备份 v4 已接入。P1d-1 已开放已有任务的清单面板和进度，见[UI 入口与验证](TASK_CHECKLIST_UI.md)。新建清单、完整字段编辑和以后定义仍属 P1d-2，未完成原生设备验收。
旧版体验升级不再纳入本轮功能范围。阶段状态见 [roadmap](TASK_PRODUCTIVITY_ROADMAP.md)，规则见 [共享契约](TASK_PRODUCTIVITY_CONTRACT.md)。

## 产品目标

减少重复输入，把较大任务拆成可逐项完成的步骤；保留轻量、本机优先、无自建服务端。
三项功能共同使用任务创建草稿和确认流程，不另建三套日期、分组、提醒或保存规则。
不增加主导航；不修改小艺、实况窗、专注计时，不升级依赖或版本号。
桌面、手机、平板使用相同数据含义，不要求相同屏幕布局。

## 任务内检查清单

- 每个任务的详情/编辑区提供“检查清单”；初版单层，每任务本地新增上限 20 项，每项 200 UTF-16 单元。
- 标题、备注、日期、提醒、重复和清单共同进入编辑草稿；保存一次原子落库，取消全部不落库。
- 已保存详情里的直接勾选是一项独立即时操作：成功后更新计数，失败明确提示并恢复显示；不能混用未保存编辑草稿。
- 任务行只显示非空清单的完成数/总数，例如 2/5，不增加一排常驻按钮。
- 清单子项没有独立日期、提醒、优先级或资料关联；父任务允许独立完成。
- 清单中的空白新增行不应无声写入；保存时定位并提示，用户可以删除空行。
- 新重复实例继承该系列明确保存的清单定义并重置勾选，当前实例的临时修改不改变后续实例。
- 重复编辑沿用“仅本次/以后”：系列清单定义必须独立建模、独立同步，并参与生成去重。
- 完成或归档父任务不删除清单；归档只读。任务删除后保留清单以供恢复；恢复不自动重启提醒或重复。
- 同步并发造成超过本地 20 项时保留、显示所有有效项，不截断；仅阻止新增，仍允许修改、删除和勾选。

## 模板与快捷复制

- 任务更多菜单增加“复制任务”和“保存为模板”；新增入口的菜单增加“从模板创建”。
- 复制先生成可编辑草稿，保留标题、备注和有效分组，清单全部重置为未勾选。
- 不复制原任务 UUID、已完成/归档/删除/置顶状态、旧日期、提醒、重复规则、便签关联、附件或专注记录。
- 模板首版仅为“一项任务及其清单”，不做多任务项目模板、商城或复杂分类。
- 模板名称必填且不长于 60 UTF-16 单元；任务内容沿用现有标题 100、备注 1000 上限。
- 模板保存内容快照，不引用原任务的可变正文；修改或删除模板不改变已经创建的任务。
- 使用模板时始终预览并确认，默认无日期、无提醒、无重复；不解释模板中的自然语言时间为定时动作。
- 已失效分组显示提示并允许重新选择；不能创建悬空分组关系。
- 删除模板先确认，不增加新回收站大模块；模板墓碑仍保留同步冲突证据。
- 模板本地新增上限 100；同步有效记录超限时不丢弃，只禁止继续新增。
- 清单内核验收后再交付模板，不用“复制已经实现”替代模板管理的完成。

## 多行文本批量创建任务

- 从新增入口菜单主动打开，粘贴后先预览；不后台读取剪贴板。
- 首版一条非空逻辑行对应一项任务，最多 50 项，输入最多 20000 UTF-16 单元。
- 允许修改标题、取消勾选、选择统一分组；首版不自动解析日期、提醒或重复。
- 可去掉明确的列表前缀，保留正文、重复行和原行号；重复项提示，由用户决定是否取消，不擅自合并。
- 空行忽略；去掉前缀后为空或过长的项目显示错误，不能悄悄截断；未勾选项目不阻挡其他有效项目。
- 超过 50 项时明确要求拆分输入，不只创建前 50 项。
- 整批确认使用同一事务创建全部选中任务；失败全部回滚，保留用户输入与选择。
- 一次提交具有稳定操作 UUID 和负载摘要；按钮连击、通信超时后重试不得产生第二批。
- 同一操作 UUID 对应不同负载必须拒绝；用户修改已提交负载后开启新的提交。
- 本轮先交付“多个任务”；“把多行转为一个任务的检查清单”作为后续小增强，不混入本轮验收。

## 双端架构

| 领域 | 桌面 | 鸿蒙 |
| --- | --- | --- |
| 草稿与预览 | src/lib/utils/taskComposition.ts | services/tasks/TaskComposition.ets |
| 权威校验/事务 | Rust 独立 task_checklist / task_templates / task_creation 模块 | models + data/repositories + services/tasks |
| 迁移 | db.rs 增量迁移入口，独立 SQL/测试 | data/migrations 独立迁移，MigrationRunner 注册 |
| 前端编排 | api/stores；组件不访问 SQLite | store；components 不访问 RDB 或网络 |
| 同步 | 独立对象与领域 revision/ACK，复用 S3 会话互斥 | 同契约独立领域，复用配置世代和冲突保护 |
| 界面 | 复用任务编辑/详情与确认面板 | 复用统一任务草稿、手机/平板详情布局 |

共享草稿内核只处理受类型约束的内存数据，不充当不可信 JSON/IPC 的安全解析器。
上线前 Rust command 和 ArkTS repository 必须重新校验；界面通过检查不是写入授权。
不得将清单数组塞进现有 Todo JSON，不将清单子项伪装为普通任务。

## 同步、重复与备份

- 检查清单实例、系列清单定义、模板分别拥有明确身份、修改时钟和墓碑。
- 采用独立同步对象，旧端缺少字段/对象不等于删除；先合并父任务与重复规则，再解释依赖数据。
- 旧端生成重复实例可能没有清单，新端应按确定性身份补齐一次，不根据设备时间各生成一套。
- 系列模板的有效起点、时区、规则版本、同实例生成身份必须在 P1a 以双端 fixture 冻结，之后才写迁移和生产同步。
- 父任务墓碑阻止迟到清单重新显示；父任务恢复后只显示未被明确删除的子项。
- 清单已进入备份 v4 并带数量预览；不向 v3 偷偷追加会被旧端忽略的新语义。
- 导入旧 v1/v2/v3 不清空新增领域；新格式恢复按同一事务校验、合并，未知版本拒绝。
- 模板不保存凭据、附件原件或历史提醒。子项/模板的墓碑不能按固定天数直接清除。
- 版本兼容、跨端删除恢复、离线重试属于交付条件，不能先开放仅本机 UI 再宣称完成同步。

## 交互与验收

桌面窄窗口、100%/150% 缩放；鸿蒙手机、小平板、大平板、横竖屏/分屏；中英文、亮暗主题和大字号均覆盖。
清单输入聚焦后键盘不遮住当前行和保存入口，长内容自然换行。
模板选择和批量预览允许滚动，底部确认操作稳定可达；保存失败不能关闭面板。
不依赖悬停才能发现操作；按钮沿用已有普通/主操作/危险操作样式。
自动化验证与物理设备验收分开记录，不以构建通过代替真实同步、旧库升级或用户体验验收。
