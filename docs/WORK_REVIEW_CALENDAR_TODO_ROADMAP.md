## CT-1：日程创建待办完整交付

目标：从一条日程直接创建用户确认过的独立任务，复用普通任务生命周期和同步。

- [ ] 固定共享 fixture：定时/全天/跨日/多日日程、重复实例、未知时区、无标题、长摘要和中英文。
- [ ] 桌面日程详情增加创建入口；鸿蒙复用展开详情，避免 Button 嵌套导致点击冲突。
- [ ] 新增纯函数草稿映射和标题/备注/分组表单；关闭或取消无写入。
- [ ] 默认无截止日期、提醒、重复、今日计划；不运行自然语言快捷解析。
- [ ] 显示独立任务及普通任务同步说明，备注可删改，不复制内部标识或额外日历字段。
- [ ] 来源摘要沿用既有 1000 UTF-16 code unit 共同边界，超限必须用户调整，不静默裁剪。
- [ ] 接入原子任务创建，返回明确任务 UUID；同草稿保存/恢复使用同一 UUID。
- [ ] 测试返回丢失、重复点击、已落库但列表刷新失败、相同 UUID 已删除/永久删除，不重复创建或复活。
- [ ] 保存后立即更新列表/计数，复用正常同步和卡片刷新；错误保留草稿，不误报数据库损坏。
- [ ] 本机读取无需开启整本日历共享；合法共享快照可创建；目标切换/撤回后的隐藏缓存不能新建草稿。
- [ ] 日程改期/删除/停止共享不改变已创建任务；同一日程可明确创建多个独立跟进任务。
- [ ] 两端互相同步新任务，标题/备注/分组保持一致，旧版普通任务解析不增加门槛。
- [ ] 完成现有备份、归档、回收站和永久删除回归；更新 README 与用户可见文案。
- [ ] 双端专项测试与构建通过，生成包含两项功能的测试程序，不自动升版。

出口：桌面和鸿蒙都能从实际可见日程确认创建、查看、同步普通任务，取消、失败、重试和来源撤回边界清晰。不能只做鸿蒙创建，也不能以“任务已落库”代替界面立即可见。

## RC-1：联合验收与交付

目标：用固定场景验证双端一致性，记录真实设备范围，不再增加新的业务功能。

### 核心用例

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| R01 | 两个任务各有多日记录；今天/本周/上周/自定义 | 日期边界和不同任务计数正确，筛选一致 |
| R02 | 两条记录同毫秒、超过 30 条、连续翻页 | 稳定排序，无重复/漏项；条件变化从首页开始 |
| R03 | 旧记录改文、任务改名/移组、删除分组 | 原日期不变，当前名称/分组即时生效 |
| R04 | 已完成/归档/回收站/恢复/永久删除/缺父任务 | 完成和归档可见，其余按方案隐藏；复制一致 |
| R05 | 中文、ASCII 大小写、emoji、百分号、下划线、反斜杠 | 两端字面搜索结果一致，不被当通配符或 SQL |
| R06 | 本地零点、月/年边界、DST 切换、设备时区变化 | 按当地自然日归属；重算范围与分页 |
| R07 | 复制超过一页、超字符上限、空结果、剪贴板拒绝 | 全量且计数一致；失败无截断/假成功 |
| R08 | 搜索响应乱序、翻页中同步、复制中删除/目标切换 | 无旧请求覆盖、正文泄漏到新目标或混合报告 |
| C01 | 定时/全天/跨日/多日日程创建任务 | 原始日程范围摘要正确，不自动生成截止/提醒 |
| C02 | 无标题、地点为空、来源名称为空、长文本/emoji | 合理默认与校验，无截断/布局溢出 |
| C03 | 改标题/备注/分组，取消，重开，再确认 | 取消零写入，保存内容是确认后的草稿 |
| C04 | 连点保存、提交返回丢失、保存后刷新失败 | 同草稿只生成一条任务，可恢复已提交结果 |
| C05 | 再开草稿创建第二个跟进；两端各创建一次 | 两条独立任务均保留，不错误去重 |
| C06 | 日程改期/删除/停止共享/接管后查看任务 | 已创建任务不随来源改动/删除 |
| C07 | 鸿蒙未开启日历共享，但普通任务同步开启 | 从本机日程创建的任务可同步，说明提前可见 |
| C08 | 桌面缓存日程、断网创建，再恢复同步 | 本地立即可用，恢复后另一端可见 |
| C09 | 创建 UUID 已被删除或永久删除后重试 | 不重复插入、不恢复终态任务 |
| X01 | 两端离线各写进展后同步，再回顾与复制 | 原协议收敛，回顾按相同条件展示同数据 |
| X02 | 导出备份、导入另一端、旧库升级 | 普通任务/进展不丢失，无新增手动迁移 |
| X03 | 窄桌面、手机、平板、键盘、大字体、深浅主题 | 标题正文可读、菜单不裁切、底栏可操作 |
| X04 | 真实日历读取/共享来源创建，跨端同步 | 实际数据链路可用，不新增写日历或提醒行为 |

## 范围约束与完成定义

1. 两项功能均不要求用户选择同步空间或进行显式迁移。
2. 工作回顾不增加独立同步域；日程生成任务不增加持续关联协议。
3. 只有被测量证明必要的索引才安排本地 migration，不预先占用 schema 版本。
4. 不增加日历写入、自动提醒、AI 总结、文件导出、完成历史统计或后台自动建任务。
5. 若遇到无法复用的安全边界，先说明具体原因和最小调整，不把未完成工作无限拆成“下一步”。
6. 所有功能阶段必须包括 UI；自动化证据、设备验收和正式发布状态各自记录。

完成指：两端均可完成工作回顾与完整复制，均可从日程创建并同步普通任务；核心失败/重试/删除场景通过，核心设备检查已有结果。仅构建通过不记为整项功能验收完成。
