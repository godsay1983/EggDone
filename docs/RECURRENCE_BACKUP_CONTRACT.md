# 重复规则备份与恢复契约

最新兼容说明（2026-09-12）：E7/L3c 新导出已升级为数据 v3，并增加必需的 task_note_links，详见[TASK_NOTE_LINK_BACKUP_CONTRACT.md](TASK_NOTE_LINK_BACKUP_CONTRACT.md)。本文件保留 E3B/v2 历史契约；其中 recurrence 结构、验证和恢复规则继续适用于 v3。当前实现同时读取有效 v1/v2/v3；ZIP manifest 仍为 v1。下文“新导出 v2”等表述仅指 E3B 当时版本。

日期：2026-09-06。状态：E3B 双端实现；原生文件选择器、设备恢复及真实 S3 验收仍需人工验证。自定义重复编辑 UI 不在本阶段开放。

## 1. 格式与兼容

- 新的普通 JSON 和完整备份内 `data.json` 均使用 `format_version: 2`，保留 v1 的任务、分组、便签与附件字段。
- v2 必须包含 `recurrence: { document: { format_version: 1, rules: [...] }, instances: [...] }`。没有规则也写空数组，不能省略或写 null。
- ZIP 容器的 `manifest.json.format_version` 仍为 1；路径、SHA-256、体积限制和附件二进制约定不变。data.json 的校验和同时覆盖规则与回执。
- 当前客户端继续读取 v1：缺少规则不代表删除本地规则，也不重置本地规则进度。
- v1 文件不接受新增 recurrence 字段。旧客户端只支持数据 v1，会明确拒绝数据 v2，避免忽略规则后只恢复任务。双方都更新后再交换新备份。
- S3 Todo、便签、附件以及独立规则对象的格式版本均不变，不把备份版本 2 传给同步解析器。

## 2. 可移植实例回执

```json
{
  "todo_uuid": "确定性 UUID v5",
  "rule_uuid": "规则 UUID",
  "occurrence_key": "eggdone/recurrence/v1/规则UUID/日期T时刻/序号",
  "planned_date": "2026-09-06",
  "planned_due_at": null,
  "purged": false
}
```

- 包含所有 `recurrence.instance.v1:<todo_uuid>` 回执；即使任务已物理清理，仍保留回执，并标记 purged=true。
- 根据不可变规则、计划日期和序号验证 occurrence key 及确定性 UUID；序号至少为 2。全天 planned_due_at 必须为 null，定时为安全非负整数。
- 回执必须引用备份中的规则；同一实例 UUID 不可重复。purged 必须与备份任务是否存在一致。
- 规则文档沿用 2,000 条（含墓碑）/1,048,576 UTF-16 单元限制；回执最多 100,000 条，整个 recurrence 区最多 16 Mi UTF-16 单元。未知字段、缺少必需字段、无效类型或超限均拒绝。
- 不输出本地 projected_due_at。恢复回执时，桌面全天投影为 null，鸿蒙按接收设备时区计算已有的 18:00 日期投影；定时保留 epoch。不会据此覆盖用户已经编辑过的任务日期。
- 不输出编辑回执、通知消费回执、同步 ACK/ETag、凭据或本地路径。成功恢复 v2 后清除本机编辑回执，旧保存请求不得凭恢复结果重放；本机已有的通知消费回执保留。

## 3. 原子恢复与合并

1. 先完整解析校验文件；完整备份还需通过 ZIP 路径、文件数、体积、摘要及所属便签校验。
2. 恢复与正在运行的同步互斥；同步忙时提示稍后再试，锁在成功和失败时均释放。
3. 在同一数据库事务内读取最新本地快照，合并任务、分组、便签、附件元数据、规则和实例回执。鸿蒙同时进入 RecurrenceQueue，所有文档写入复用同一个原生 Transaction。
4. 规则采用现有同步合并规则：墓碑优先、实例进度不倒退、不可变定义冲突拒绝，不采用备份覆盖全库。较新的本地任务编辑保留。
5. 完成后检查活动规则与任务的关联冲突；不允许旧备份把活动规则当前任务改成旧快捷重复。缺少源任务或归档的规则可以保留为不可推进状态，不凭空补任务。
6. 本机已有回执而任务已物理清理时，不允许旧备份重新插入该实例；整次恢复拒绝。备份中的 purged 回执只增加防重建保护，不删除本机仍存在的任务。
7. 恢复本身不调用推进器，不创建下一实例，不取消规则墓碑，不重新开始已停止或耗尽的系列。后续用户操作/同步准备沿用已有幂等推进逻辑。
8. 成功恢复 v2 后清除规则 ETag/ACK，递增规则与 Todo 脏版本，并标记 Todo 待同步。下一轮重新读取远端并使用条件上传；恢复不代表已上传成功。
9. 任何元数据失败均整体回滚。完整备份的附件安装失败或事务提交失败沿用文件回滚；若磁盘故障导致回滚不能完成，保留回滚目录中剩余的原文件供排障，不自动删除。

重复导入不新增任务或重复实例；同步修订号会再次标脏，以强制重新确认远端。v1 导入不清空规则 ACK 或编辑回执。

## 4. 界面与入口

- 桌面：原有数据管理的 JSON 导出/导入、完整备份导出/恢复。
- 鸿蒙：设置内原有数据管理入口，手机和平板使用相同服务与流程。
- 预览显示备份内自定义规则数（包含已停止规则），不是本次实际新增规则数。
- 新增中文/英文的同步忙、实例已清理、规则或版本冲突提示；未添加新的规则编辑入口。
