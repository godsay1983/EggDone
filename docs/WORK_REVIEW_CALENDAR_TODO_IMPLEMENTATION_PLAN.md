# 工作回顾与日程创建待办实现方案

- 日期：2026-10-02。
- 状态：方案已编写，功能尚未实现；本轮仅文档，不提交、不升版。
- 范围：EggDone 桌面端与 HarmonyOS 端，两端功能语义一致，交互适配各自窗口。
- 核验基线：桌面 1.5.0；鸿蒙 1.6.0 / 1000036；数据库 schema 27，备份内层 v9，进展记录与日历共享格式均为 v1。
- 执行计划：[WORK_REVIEW_CALENDAR_TODO_ROADMAP.md](WORK_REVIEW_CALENDAR_TODO_ROADMAP.md)。
- 两个仓库保存相同正文；后续修改同步维护。本方案不覆盖既有进展记录和系统日历协议。

## 1. 目标与范围

本次只补齐两个用户闭环：

1. 工作回顾：按时间、分组和关键词查看多个任务的进展，复制成可用于工作总结的文字。
2. 日程创建待办：从当前可见的系统日程生成可编辑的任务草稿，确认后成为普通 EggDone 任务。

复用现有进展和任务同步，不引入新同步对象、账号、Object Key 配置或用户迁移步骤。日历继续只读，既不回写日程，也不为日程创建提醒。

首版明确不做：AI 总结、工时/完成率图表、自动操作流水、独立周报存档、定时发送、文件导出、任务与日程持续绑定、批量转换整本日历、自动排程。工作回顾不是完整审计日志，不承诺还原过去某时刻的原始文本。

## 2. 现有能力与接入判断

| 能力 | 当前实现证据 | 本次处理 |
| --- | --- | --- |
| 任务进展 | 桌面 task_progress_store.rs、鸿蒙 TaskProgressRepository.ets 已有独立记录、按任务分页和批量计数 | 新增跨任务只读查询，不用逐任务调用现有列表接口 |
| 记录时间 | created_at 与 updated_at 分离，编辑保留 created_at | 回顾按 created_at 归属，显示最新有效正文 |
| 生命周期 | 进展墓碑、父任务归档/回收站、永久删除终态已存在 | 查询和复制均应用同样的可见性过滤 |
| 系统日程 | 两端 occurrence 均有标题、时间、全天日期、地点、日历来源 | 仅从已有可见 occurrence 生成草稿，不额外读取日程描述或参与者 |
| 新建任务 | 桌面 create_captured_todo 原子保存；鸿蒙 TodoRepository.create 保存完整任务 | 复用普通任务保存语义，补齐新入口的返回结果和重试保护 |
| 数据兼容 | 任务备注、分组和进展均有现成同步/备份通道 | 不新增业务字段，不改 wire/备份格式 |

注意：鸿蒙 TodoStore.add 当前返回 void，且任务保存后还会加载列表；不能将“列表刷新失败”误当成“任务未创建”后再生成一条。桌面与鸿蒙的新入口都必须得到明确的已提交任务 UUID。

## 3. 工作回顾

### 3.1 用户流程与界面

入口放在两端“更多”中的“工作回顾”，不新增主导航标签，不在每个任务下增加按钮。

- 默认本周，周一至周日。日期选项为“今天 / 本周 / 上周 / 自定义”。
- 自定义日期选择起止日，界面两端日期均包含；错误范围就地提示。
- 分组默认为全部，可选择一个现有分组或未分组；首版不增加复杂组合筛选器。
- 搜索同时匹配任务当前标题与进展正文，去除查询首尾空白，单个完整关键词做包含匹配，不做分词或语义搜索。
- 头部只显示紧凑的“涉及 N 个任务 · M 条进展”，不是完成任务数量。
- 列表按记录创建时间倒序，按本地日期分段；每条展示时间、任务标题、正文及必要的分组/状态小标签。
- 长正文可展开，复制必须使用完整正文。空态区分“尚无进展”和“没有符合筛选的记录”。
- 点击任务标题或记录进入已有进展面板；返回保留筛选和滚动位置。数据发生变化时重新校验列表，不打开一个失效任务。
- 底部仅保留“复制摘要”主要操作；复制成功或失败均给出真实结果，空结果时禁用。

桌面采用可伸缩的现有对话框，筛选区与底部操作固定、中间列表滚动。鸿蒙采用现有导航/面板组织，手机单列、平板限制正文最大宽度；筛选控件窄屏可分行，避免横向挤压。沿用主题 token、标准按钮和标签，不新增大面积说明文字、设备元数据或嵌套卡片。中英文、大字体、明暗主题均纳入验收。

### 3.2 时间与内容语义

| 情况 | 固定规则 |
| --- | --- |
| 时间范围 | 用当前设备系统时区，将起始日零点和结束日次日零点分别转换为 UTC，执行 start <= created_at < end |
| 夏令时 | 按日历推进一天后再取零点，不能固定加 86400000 毫秒 |
| 编辑旧记录 | 展示最新正文、可显示“已编辑”，仍属于原创建日期，不重复算作今天进展 |
| 补写记录 | 属于实际创建日期；首版不支持补录“工作发生日期” |
| 未完成/已完成任务 | 均纳入，不要求任务已完成 |
| 已归档任务 | 默认纳入，显示归档标记，打开记录时沿用只读规则 |
| 回收站任务/已删除记录 | 不纳入列表、计数、搜索和复制；恢复父任务后重新出现 |
| 永久删除/父任务缺失 | 始终不纳入，不能因缓存或迟到同步显示正文 |
| 标题/分组变化 | 按任务当前标题和分组展示、筛选；不伪造历史标题和历史分组 |
| 分组已删除/不存在 | 有效分组为空，按未分组处理，不丢失记录 |
| 无进展的已完成任务 | 首版不纳入；不把 completed_at 混入进展时间线 |
| 不同时区设备 | 允许同一 UTC 记录落在不同本地日期；同一时区、语言和数据应得出相同结果 |

只基于当前本地已保存/已同步的数据展示；打开回顾或搜索不触发额外网络抓取。沿用现有同步状态，不把本地汇总宣称为“所有设备的实时报告”。

### 3.3 查询、分页与刷新

新增本地查询模型（拟定名，不是新同步协议）：

- ReviewQuery：start_at、end_at、group_scope（all/ungrouped/group）、group_uuid、keyword。
- ReviewCursor：created_at、record_uuid；请求需绑定相同查询条件。
- ReviewRow：record_uuid、task_uuid、task_title、有效分组、当前完成/归档状态、body、created_at、updated_at。
- ReviewPage：rows、next_cursor、matching_entry_count、matching_task_count。

每页 30 条，按 created_at DESC、uuid DESC 排序，多取一条判断下一页。总数按完整筛选集合计算，不是已加载条数；任务数按 task_uuid 去重。查询在数据库层关联任务和分组、排除永久删除终态，SQL 参数绑定。

关键词首版固定为字面包含：ASCII 英文字母不区分大小写，中文等其他字符精确匹配；百分号、下划线、反斜杠是普通文本，不解释为 SQL 通配符。两端共享测试向量，避免 SQLite/RDB 默认大小写规则不同。

不新增 FTS 或搜索服务。先在现有最多 20000 条进展数据规模下测量查询；只有执行计划和耗时证明需要时，才增加本地索引及正式迁移，不能为只读视图预先升级业务协议。

筛选变化/时区变化重置分页。搜索使用短防抖和请求序号，旧请求不能覆盖新筛选。进展编辑/删除/同步、任务改名/移组/归档/删除/恢复、分组变化和目标切换均使结果失效，按当前筛选重新加载。翻页按 UUID 去重；重载失败不能将旧结果冒充新结果。加载器必须有恢复路径，避免只变更数据但页面不刷新。

### 3.4 复制摘要

首版仅复制纯文本，不请求文件权限，不自动上传或生成持久化周报。

示例：

```text
工作回顾 | 2026-09-28 至 2026-10-04
分组：工作
涉及 2 个任务，3 条进展

2026-10-02
IAAS项目
- 16:40 中文路径验证通过，剩余大文件性能测试。
- 10:20 完成字段映射，还需要测试中文路径。

组网客户端原型开发
- 15:00 完成连接状态展示。
```

导出按日期倒序、同日按任务归组；任务组按该日最新记录时间倒序，同任务按时间倒序，UUID 用于同时间稳定决胜。复制使用当前筛选下的全部结果，不只是已加载页，顺序和格式在双端共享测试中固定。

点击复制时执行独立的只读一致性查询，计数与正文来自同一数据库快照，不使用旧列表缓存拼凑，也不跨页混合不同版本。使用当前筛选/时区的固定副本；过程中筛选、目标或相关数据改变时，放弃未交付文本并允许重试。不要长时间持有读事务等待系统剪贴板。

首版生成文本上限为 100000 个 UTF-16 code unit（包括标题和换行）。超过上限提示缩小日期/分组范围，不能静默截断或只复制前几页。该上限属于复制操作保护，不限制浏览历史日期范围。系统剪贴板失败保留筛选并提供重试，不记录正文到日志。

复制是用户主动的数据导出；不会自动清除用户剪贴板，也不能收回已经粘贴到其他应用的文字。设备侧继续复用现有剪贴板能力；如平台适配确需新增 API，实施时核对本机 SDK 与官方权限要求，不预先承诺无需任何平台适配。

## 4. 日程创建待办

### 4.1 入口与操作

两端统一文案“创建待办”。入口放在某条日程展开详情的操作区，不在日历下方堆叠常驻按钮。

- 桌面为日程行补紧凑的详情展开入口，在详情中提供“创建待办”。
- 鸿蒙复用已有点击日程展开详情。创建按钮必须是独立可点击区域，不嵌套在整行 Button 内，避免点击创建同时折叠。
- 本机日程、合法共享日程均可创建；桌面仍只消费共享快照，不要求本机日历权限。
- 只允许从当前按既有权限、共享和覆盖范围规则可展示的实际 occurrence 发起。空态、来源撤回、目标切换中的旧缓存不提供入口。
- 点击后打开普通任务草稿，用户可以修改标题、备注和分组，确认后才落库；取消不写入任何内容。
- 保存成功立即更新任务列表和计数，触发现有自动同步，并提供“查看任务”。不等待云端成功才显示任务，也不暗中改变当前日历筛选。
- 若任务不符合当前分组/日期筛选，仍清楚显示创建成功并允许查看，不能让用户误以为未保存。

首版创建表单只提供标题、备注和分组，不扩成另一个完整日程/任务编辑器。创建后通过既有任务菜单安排截止日期、提醒或加入今日计划。

### 4.2 字段映射

| 目标字段 | 映射规则 |
| --- | --- |
| title | 日程标题，允许直接改为具体行动；空/纯空白标题使用本地化“日程待办” |
| note | 可编辑的日程摘要，含日程标题、起止时间或全天日期范围、非空地点、可用的日历名称 |
| group_uuid | 默认未分组，可显式选择；不继承当前隐藏筛选或把日历名称当作任务分组 |
| due_date / due_at | 均为空；会议开始、结束时间不等于任务截止时间 |
| reminder_at / repeat_rule | 均为空；不继承系统日历提醒或重复规则 |
| priority / pinned / completed | 普通优先级、未置顶、未完成，沿用普通新任务默认值 |
| 今日计划/等待/检查清单/进展 | 不自动创建或继承 |

时间固定为草稿打开时的快照：

- 定时日程：按当前设备系统时区格式化两个时间戳，跨日时显示完整日期，标明显示时区；不按不可信的原始 timeZone 文本重新解析时间。
- 全天日程：保留 startDate 到 endDateExclusive 前一天，不当作午夜时间戳跨时区换算。
- 一条多日 occurrence 在多天出现，始终带入完整原始范围，不因点击日期裁成单日。
- 重复日程仅取当前 occurrence，不生成系列待办。
- 源时区未知或异常时沿用当前项目的时区降级规则，不猜测来源地区。
- 不复制设备 ID、owner_generation、内部日历/日程 ID、诊断码或整个原始 JSON。
- 当前模型没有日程描述、附件或参与者，不能在方案中假设可用，也不扩大系统日历读取范围。

备注控制在现有两端可接受的 1000 UTF-16 code unit 内；桌面底层当前按字符数校验，新入口需采用更严格的共同边界，不能改动其他任务路径的语义。自动摘要过长时显示超限提示并允许编辑后保存，不静默截断。标题沿用普通任务的非空及长度校验；表单生成与底层保存都要校验，不能报成数据库无法打开。正文按纯文本处理，不执行链接/HTML 或快捷新增语法，例如日程标题中的“明天”不能被解析成截止日期。

### 4.3 独立任务、共享与隐私

这是“从日程复制信息创建任务”，不是双向绑定：

- 日程改期、删除、共享来源接管或停止共享，不修改/删除已经创建的任务。
- 任务完成、删除、归档，不修改日程。
- 不新建关联表、不保存用于反向跳转的系统日历 ID，不显示无法可靠维护的“已创建任务数”。
- 草稿打开后源日程更新，不覆盖用户已编辑内容；草稿继续是用户确认的文字副本，不恢复任何已撤回的日历缓存。
- 日历共享未开启时，鸿蒙仍可从本机日程创建任务。创建出的任务按普通任务同步配置同步，与“共享整本日历”开关独立。
- 表单用一条简短说明明确：“创建后作为独立任务保存，并按任务同步设置同步。”用户可在保存前删除不希望带出的地点或摘要。
- 不新增日历写权限，不自动申请日历提醒权限，不改既有授权/ACL/Profile 配置；不自动开启日历共享。

### 4.4 保存与重复操作边界

同一草稿保存过程中禁用按钮。为该草稿生成一次普通 Todo UUID，保存/结果恢复复用该 UUID；不能每次重试都生成新任务。

实现一个范围受限的日程草稿创建入口，复用现有创建事务和校验。已有创建 API 暂不保证请求级幂等，不能只加前端按钮禁用就宣称重试安全：

- 首次保存原子写入标题、备注、分组和普通任务元数据。
- 返回丢失后先按草稿 UUID 查询已提交结果；若存在则返回已创建任务，不重复插入、不覆盖后续修改。
- 若同 UUID 已被归档、删除或永久删除，不重建；反馈已处理/不可用，不能绕过生命周期终态。
- 数据落库后的列表刷新、卡片刷新或网络失败，与保存失败分开处理，不因此创建第二条。
- 未成功落库时保留输入；保存结果不确定时先解析结果，再允许继续修改并重试。
- 草稿关闭后不承诺跨进程自动恢复，但已提交任务必须仍可在全部/搜索中找到。
- 需增加的本地查询/UUID 参数应限制在该入口，不顺手重构全局新增流程；不引入新的同步回执域。

允许从同一日程主动创建多个不同跟进任务。重新打开创建面板是新草稿，两端分别创建也是两条独立任务；首版不按标题、时间或日程 ID 跨设备自动去重。界面不把正常第二次创建称为同步冲突。

## 5. 模块划分与兼容性

以下为实施位置建议，新增文件名称可随现有结构微调，不改变职责。

| 模块 | 桌面端 | 鸿蒙端 |
| --- | --- | --- |
| 回顾模型/查询 | 新增 work_review.rs、命令薄封装、workReviewApi.ts | 新增 WorkReviewModels.ets、WorkReviewRepository.ets |
| 回顾状态/界面 | workReviewStore.ts、WorkReviewDialog.svelte；接现有更多菜单 | WorkReviewStore.ets、独立回顾组件；Index.ets 只挂状态/入口 |
| 日期/摘要规则 | 小型纯函数与 Vitest/Rust 测试 | 小型 ArkTS 规则与宿主/原生测试 |
| 日程草稿 | SystemCalendar.svelte 回调、calendarTodoDraft.ts、独立轻量表单 | SystemCalendarPanel.ets 回调、CalendarTodoDraft.ets、表单组件 |
| 创建与副作用 | create_captured_todo 的公共事务逻辑、todoStore.ts 新入口 | TodoRepository/TodoStore 新入口，复用保存后通知与同步编排 |
| 复制 | 复用现有系统剪贴板路径，必要时增加最小适配 | 将既有剪贴板用法封装在服务中，组件不直接处理平台错误 |
| 测试契约 | 两端同名 JSON fixtures，固定日期/筛选/摘要/草稿输入输出 | 使用相同 fixtures，不各写一套预期 |

工作回顾直接读取现有任务与进展，日程待办是普通任务。原任务/进展同步及备份流程自然覆盖，不增加导出字段。新任务的归档、回收站、永久删除、复制、模板行为沿用普通任务，不加来源例外。

预计无业务表变更。若性能验收确实需要新增索引，先复核可用 schema 版本，提供新旧库迁移并测试；只做本地索引迁移，不改备份/wire 格式，不要求用户显式迁移。当前文档不占用未来 schema 编号。

回顾筛选为会话状态，不同步到其他设备。复制文本、打开的日程草稿均不是持久化同步域。日志只记录固定错误类别、数量和耗时，不输出进展正文、日程摘要或凭据。

## 6. 验证与交付边界

共享测试覆盖日期边界、分组/搜索规则、生命周期过滤、完整复制、日程字段映射及重复保存。双端 UI 必须在各自功能里程碑内接通，不单独交付长期不可见的后台模块。

验收重点：

1. 同数据、同语言、同时区，双端筛选结果、条数和复制内容一致。
2. 查询、计数、复制均排除删除/永久删除/缺失父任务，归档记录仍能回顾。
3. 同步或本地编辑后立即更新，搜索旧请求不能覆盖新请求。
4. 复制的是全部匹配内容；超限、空结果、剪贴板失败有明确反馈。
5. 日程创建为普通任务，双端同步后可见，无额外日程提醒、日期误设或重复系列。
6. 写入成功但返回/刷新失败，再次操作不产生重复任务。
7. 关闭日历共享不会阻止普通任务同步，隐私边界在确认前可见。
8. 窄桌面窗口、手机、平板、大字体、深浅主题下控件可读可点，菜单和底部操作不裁切。
9. 旧库、备份导入导出、断网和同步重试不回归。

真机与真实系统日历测试在两项功能完成后集中进行；之前以共享 fixtures、隔离数据库、模拟器和合成日程验证。自动化、模拟器、真机、实际云端结果分别记录，未验证项不记为通过。测试不得使用真实任务做删除/覆盖试验，也不自动开启用户日历共享。
