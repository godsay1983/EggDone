# 今日计划实现契约

状态：2026-09-19 双端代码、界面优化与自动化验证完成，纳入本次本地提交；原生设备及用户实际同步验收中，未推送、未升版或发布。以本文件细化 LC3。

## 用户语义

- 普通任务标签区显示“今日计划”，使用与到期、重要标签一致的尺寸，并可同时出现；全部、分组和今天视图共用。仅标记当前本地日期内有效且未完成的计划任务，完成、移出、删除、归档或日期切换后取消显示；不会把昨日建议或完成凭据标记为今日待做。

- 首版只安排今天；“今天”页分为“计划做”和原“到期/逾期”。计划独立排序，不修改任务截止日期、提醒、分组、重要程度、主列表排序或卡片。
- 任务菜单加入/移出今日计划。昨天仍活动且计划有效、今天尚未安排的任务可逐项继续安排，不自动跨日迁移。
- 当天完成的计划凭据只读折叠；重新打开、取消归档或恢复删除都不自动恢复旧计划。
- “计划做”的活动任务复用普通任务卡片和完整菜单，保留分组、备注、清单及任务操作。菜单顶部依次为计划内上移、计划内下移、移出今日计划；鸿蒙采用同一行紧凑按钮。边界按完整计划而非当前筛选结果计算，普通列表排序在计划视图中禁用。桌面菜单按列表可用空间定位并内部滚动，拖动边框不再依赖卡片放大或外扩描边。
- 所有参与设备需升级；不要求再次迁移。新计划数据使用独立 sidecar，已有数据和 Object Key 不变。

## 双端 API

- `list_daily_plans(date)` / `DailyPlanRepository.list(date)` 返回 `DailyPlanSnapshot`：`date: string, revision: string, current: DailyPlanEntry[], previous: DailyPlanEntry[]`。
- `DailyPlanEntry`：`task_uuid: string, plan_date: string, status: 'planned' | 'completed', position: number`。标题和任务操作仍使用既有任务实体，不复制任务。
- `write_daily_plan(request)` / `DailyPlanRepository.write(request)` 返回刷新后的 snapshot。
- 请求：`operation_uuid, task_uuid, plan_date, action: 'add'|'remove'|'up'|'down', expected: string`。日期为设备当地日期 YYYY-MM-DD；生产层校验真实公历。UI 每个用户动作固定操作 UUID，失败重试保留；读取冲突后需重新确认动作。
- revision 为读快照指纹，覆盖计划状态和任务生命周期；写事务核对，取消零写入，重复请求不重放排序。错误 `PLAN_CONFLICT`、`PLAN_UNAVAILABLE`、`PLAN_INVALID`、`PLAN_LIMIT`、`PLAN_DATABASE`。写成功但刷新失败不得假报保存失败并重复排序。

## Wire 与存储

- document：`{format_version:1, events:[], plans:[], completions:[]}`，严格字段、类型、UUID、日期、安全整数、唯一逻辑身份；UTF-8 上限 4 MiB。
- events：`{task_uuid,event_id}`，合并集合并集。本机生命周期操作在任务写入同一事务生成事件。event_id 为目标状态版本：`updated_at:lower(hex(updated_by)):completed:archived_at-or-'-':deleted_at-or-'-'`。任务文字/日期编辑不生成事件；事件不以墙钟大小淘汰。同步和 v7 备份应用父任务时使用事务内保护标记，不从通用 updated_at 猜测原完成时刻，权威事件来自规划域；旧备份的本地状态变化仍使旧安排失效。
- basis 为当前任务全部 event_id 以 ASCII 升序排列、以 `|` 拼接的字符串（空集合为空字符串）；子记录不能安装权威事件。effective planned = 活动父任务 + included + basis 完全相等 + 非终态。
- plans：`{task_uuid,plan_date,included,position,clock,writer,basis}`。身份 task_uuid + plan_date；LWW 按类型逐项比较 `(clock,writer,included,position,basis)`（false < true），clock 和 position 为非负 JS 安全整数。重排只写该日关系；位置冲突按 task_uuid 稳定排序。显式 included=false 表示移出。
- completions：`{task_uuid,plan_date,event_id,basis,position}`，身份 task_uuid + plan_date + event_id，集合并集；同身份冲突按 `(basis,position)` 决胜。完成前只有有效计划生成凭据；basis 是完成前集合，不能包含自身 event_id。展示需父任务仍完成且未归档/删除，当前集合恰为 basis 加该完成事件。凭据无正文。
- 独立表、revision/synced_revision/etag/generation 与事务。终态删除物理清理对应计划/完成凭据，事件作为非正文防复活证据；备份导入保留现有事件，不从子 basis 反推。
- sidecar：`eggdone-planning/v1/<完整 todo object key 的 UTF-8 SHA256 小写十六进制>/plans.json`。复用强 ETag 条件创建/更新和有界重试；绑定当前配置 epoch，旧会话不可 ACK 新目标。首次缺失为空，已见后消失拒绝静默覆盖。
- 同步只 ACK 本次上传快照；独立 dirty 与远端探测，不能由主任务 ACK 消掉计划更新。当前完整任务/终态同步后合并计划，会话末尾仍需防本机更新竞态。
- 备份有数据时提升为 v7，携带 `daily_planning`；旧备份缺此域表示保留，不清除现有安排/边界。已迁移空间初始化/恢复不能漏掉计划，未处理路径必须显式阻止而不是静默丢失。

## 使用与边界

- 任务的“更多 → 加入今日计划”，然后“今天 → 计划做”；通过计划行“更多”上移、下移或移出。原“到期/逾期”筛选保留。
- 无日期任务也能安排；本地日历跨日自动刷新，昨天任务需点击“继续安排今天”。设备时区不同，各自查看当地日期对应的计划。
- 双端 schema 升至 25：24 创建规划表，25 修正远端应用的触发器保护，保留已有 24 数据；只有规划域非空的备份使用 v7，旧备份仍可导入并保留现有计划。
- 已有存储授权需允许上述 `eggdone-planning/v1/` 前缀的 GET/HEAD/条件 PUT。即使本机没有计划，也需读取此域以发现另一设备的安排。授权拒绝、非法内容或已见对象消失时明确失败，不覆盖云端、不自动修改权限。
- 旧的八领域空间迁移工具暂不迁移规划域。有计划/生命周期证据时阻止新的迁移操作，已有激活空间与正常同步不受影响；本机恢复快照完整保留规划表。今日计划不以迁移为前提。
- 自动化和构建不替代手机、平板真机及用户存储的最终验收。版本号、本地提交、推送和发布另行确认。
