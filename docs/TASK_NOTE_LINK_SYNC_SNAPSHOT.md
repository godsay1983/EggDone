## 原子快照

调用顺序的前提：网络层先合并任务、便签并完成重复规则协调，再调用 prepare，传入当前配置世代、已验证的远端 links 文档和时间。

prepare 在一个 IMMEDIATE 事务内完成：

1. 校验当前配置世代。空值、pending、旧世代均拒绝；读错误抛出，不当成成功。
2. 按 links v1 合并规则合并完整记录。空文档不删除已有记录，非法文档整体失败。
3. 协调实际存在的任务/便签删除记录，只把对应活动链接改成墓碑，不改任务、便签或附件。
4. 一致捕获任务 JSON、便签 JSON、links JSON，以及各自 revision、配置世代和生成时间。复用现有实体文档生成与校验逻辑。
5. 任一校验、写入或提交失败，回滚本次链接合并、墓碑和 revision。

缺失对象可能尚未下载，不视为删除。归档、完成不解除关联。删除协调时间取 now、实体 updated_at/deleted_at、链接 updated_at+1 的最大值；超出安全整数直接失败，不饱和后写入。保留原 created_at。实体恢复不自动恢复已删除的链接。

## 回执与配置隔离

- isCurrent 在短事务内比较配置世代、三领域 revision 和三份精确 JSON。即使远端实体合并没有推进本地 dirty revision，内容变化仍会让旧快照失效。
- acknowledge 只能在两份实体上传以及链接条件 PUT 全部成功后调用。L3a 只提供本地确认原语；上传顺序、条件请求和远端成功判断由尚未实现的 L3b 会话负责。
- 确认时重新做完整快照比较。不匹配返回 false，保留现有 synced_revision/ETag，不清除较新改动。
- 匹配才更新 links 的 synced_revision 与返回 ETag，不确认任务、便签或附件领域。空/控制字符 ETag 拒绝。
- 配置切换先失效旧世代，再写外部凭据。保存失败保留 pending 状态；重新配置相同目标也产生新世代，不能复用旧回执。
- 关联 revision 达到上限时，配置失效事务整体回滚，不能仅清掉部分领域或修改外部凭据。
- 鸿蒙排队入口复制请求与快照，避免调用方在排队期间修改对象。事务内没有网络等待，网络会话必须沿用现有全局互斥锁。

## L3b 接入要求

下一步必须把上述内核接到真实生产会话，而不是仅增加另一个未调用的服务：

1. 校验独立 `task-note-links.json` Key 与所有现有对象不冲突；新增独立 GET/HEAD/条件 PUT、错误分类和 token。
2. 实体与重复规则先合并/协调；实际上传内容必须与捕获快照一致。复用既有重复同步时，要防止中途推进任务导致捕获版本过时。
3. 先成功上传任务、便签，再上传链接；不先确认链接、也不在错误后清除其 dirty。
4. 配置隔离覆盖每个网络 await 前后；条件冲突最多两轮，重新下载、合并、取快照，不盲目覆盖。离线/超时/403 不当成空文档；404 只代表对象不存在。
5. 若上传链接前实体已变化，重新准备而不是发布失效快照；上传后变化则保持待同步。已有任务/便签成功回执不能因链接失败被误清除或伪造。
6. 接入手动同步、自动重试、独立远端探测及状态摘要；旧客户端只同步实体时继续协调删除。
7. 备份版本/预览/原子恢复留待 L3c；真实 S3 与双端离线冲突留待 L3d。
