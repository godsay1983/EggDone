## 请求与结果

请求严格包含以下字段，不接受额外字段：

```ts
interface BatchRequest {
  operation_uuid: string;
  group_uuid: string | null;
  items: { uuid: string; title: string }[];
}
interface BatchResult {
  operation_uuid: string;
  task_uuids: string[];
  created_at: number;
}
```

- 操作、任务及非空分组 ID 使用小写规范 UUID；每项任务身份不同。
- 选中项 1 至 50 条，标题已 trim、非空、最多 100 UTF-16 单元；禁止换行、控制字符、双向控制符和不成对代理项。
- 所有项使用同一有效分组。输入顺序保留，标题相同仍创建独立任务。
- 仅创建普通未完成任务：空备注、无日期/提醒/重复、未置顶、普通优先级，无清单或便签关联。不解析标题里的自然语言时间。
- 标题前缀处理、原行号和重复提示复用 P0 草稿解析器，不能直接将原始多行文本发给事务接口。

## 原子性与重试

在一个 IMMEDIATE 事务中校验分组、身份和排序，写入全部任务、普通任务同步脏标记，以及本机 `app_metadata` 的 `task.batch.create.v1:<operation_uuid>` 回执。任一写入失败整批回滚。

排序从当前未完成任务的最小顺序值之前预留连续区间，每行间隔 1024；数值超出安全整数范围拒绝，不重排其他任务。

相同 operation、相同负载和设备重试时，核对所有任务的初始字段及关联状态后返回原始结果，不增加任务、不再次标脏。负载改变报 `BATCH_OPERATION_REUSED`；任务被编辑、完成、归档、删除、重排或新增关联后报 `BATCH_STALE_RECEIPT`，不得覆盖或复活。已有任务及孤立清单、关联、重复定义占用 UUID 时，拒绝新建。

回执仅本机保留，不进入同步/备份；任务仍使用现有同步及备份数据。当前恢复实现不会清空该回执命名空间。另一台设备没有回执时，已有任务 UUID 仍阻止重复插入；不跨设备承诺回执恢复。恢复导致任务缺失或字段不同后，旧请求会拒绝，不能据此显示新的成功。

## P3b 接线要求

1. 一份确认草稿只分配一次 operation UUID；选中行的任务 UUID 按稳定草稿 key 保存。
2. 发送后结果不明时，重试必须复用完整原请求，不能重新分配身份；变更内容前先解决不确定结果。
3. 提交中禁用重复确认。成功后进入完成态，刷新列表和调度同步；失败保留输入，不显示成功。
4. 分组失效需重新选择；旧回执失效需读取现有任务核对，不自动创建另一批。
5. 取消尚未提交的草稿不调用接口。提交已经发生时，关闭界面不等于回滚。
