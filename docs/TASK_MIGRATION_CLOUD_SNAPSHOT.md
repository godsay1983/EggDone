配置过同步的设备：回收站尝试永久删除 -> 迁移准备 -> 准备本机快照 -> 备份并核对云端。
只有本机快照已验证且内容仍匹配，才显示云端按钮。重新校验仍只重验本机；云端按钮负责重新读取并核对云端。
显示 8 个域中实际存在的数据文件数、附件文件数、大小，以及本次验证/历史记录/未完成状态。
源数据变化、读取权限、格式、附件缺失和失败重试分别提示；失败不继续展示“本次验证通过”。
这是恢复资料准备，不是新空间迁移向导；没有切换、加入或云端清空按钮。

## 实现范围

- 直接使用两端生产签名 S3 GET 和现有八域解析器：任务/分组、便签、附件元数据、重复规则、任务便签关联、清单条目、重复清单定义、模板。
- 保存原始 UTF-8 字节、大小、SHA-256、强 ETag；404 单独记录为不存在，不把拒绝访问或其他状态当空数据。键按当前主对象键推导并验证互不碰撞。
- 下载全部被云端附件元数据引用的原文件/预览，包括已删除附件和本机从未下载的文件；不写 live cache，不恢复用户正文，不清除 dirty 或写 ACK。
- 快照位于应用私有 migration-backups/<localOperation>/cloud-<cloudOperation>/；manifest 与文件逐项落盘读回。文件/目录拒绝符号链接，文件名由 UUID 和固定后缀生成。
- app_metadata 的 migration.backup.cloud.v1 保存持久记录，绑定本机快照 operation/dataHash 和源 endpoint/region/bucket/key/pathStyle/allowHttp 的摘要；不包含访问密钥。
- 来源及对象版本/摘要不变时复用 operation 和已验证文件；来源变化使用新 operation，保留旧资料。失败期间 verifiedAt 不会被更新为成功。
- 完成后重新读取八个对象，检查 ETag、原始摘要和不存在状态；并在短事务中复核本机来源及持久计划，然后记录校验时间。传输期间不持有数据库事务。
- metadata 单对象及八域合计最多 16 MiB；本机与云端当前快照合计最多 512 MiB、10000 文件（含 manifest）。单个附件仍受各端现有下载限制，超限或缺失均关闭成功路径，不能跳过后宣称完整。
