# 任务效率功能共享契约

日期：2026-09-14；草稿规则版本：1。
适用：桌面与鸿蒙。P0 冻结纯草稿行为；持久化/网络 wire schema 尚未发布，P1a 完成后才可写新同步对象。
配套：[方案](TASK_PRODUCTIVITY_IMPLEMENTATION_PLAN.md)、[roadmap](TASK_PRODUCTIVITY_ROADMAP.md)。

## 限额与校验

| 内容 | 上限 | 行为 |
| --- | --- | --- |
| 任务标题 | 100 UTF-16 单元 | trim 后非空、单行；超限拒绝，不截断 |
| 任务备注 | 1000 UTF-16 单元 | 保留内部换行；超限拒绝 |
| 单任务清单 | 本地新增 20 项 | 超限不允许创建；同步后展示不受此截断 |
| 单项清单正文 | 200 UTF-16 单元 | 非空、单行；超限拒绝 |
| 模板名称 | 60 UTF-16 单元 | 非空、单行；超限拒绝 |
| 批量文本 | 20000 UTF-16 单元 | 超限拒绝整次解析，保留界面原始文本 |
| 批量任务 | 50 个非空原始行 | 超限要求分批，不部分创建 |

UTF-16 与现有 ArkUI/桌面链接创建规则保持一致；emoji 通常占 2 单元。禁止静默截断和拆分代理对。
带不可见控制符、双向控制符或不成对代理项的单行正文拒绝；备注允许制表和换行。
错误返回稳定代码与行索引，界面在后续 UI 阶段映射中英文，纯内核不生成用户提示字符串。
当前纯内核不是 IPC/远端 JSON parser；每层写入仍需运行时结构和权限校验。

## 编辑与创建草稿

清单草稿项使用局部 rowKey、content、completed；持久化 UUID 与原始版本快照在 repository adapter 中单独管理。
编辑必须保留既有 UUID，新增项提交前分配 UUID；不能以数组下标作为跨设备身份。
纯内核的新建草稿只含 title、note、groupUuid、checklist 和稳定草稿 key；状态显式为未完成、未置顶、无日期/提醒/重复、普通优先级。
copyTaskForCreation 通过字段白名单创建深副本，所有子项未勾选，源数据不变。
草稿 key 仅用于本机 UI/提交前关联，不是数据库或同步 UUID；持久化身份由原子提交层分配并在重试中复用。
草稿校验不做“清空”或数据库写入；编辑取消只丢弃当前草稿。
模板快照只含 name、title、note、groupUuid 和清单文本；应用模板重新生成新建草稿，绝不共享可变数组。

## 多行解析

- CRLF、CR、LF、Unicode 行/段分隔符统一为逻辑换行；行号为原始逻辑行的 1 基位置。
- 先忽略纯空白行，再识别前缀。去前缀后为空的行保留并报 EMPTY_TITLE。
- 去除 Markdown 列表标记“- ”、“* ”、“+ ”；其后可带 [ ] / [x] / [X]。
- 去除 1 至 3 位数字后接点、右括号或顿号且再接空白的编号；没有空白不识别为编号。
- 不把日期 2026-09-14、版本 1.1.0、负数 -5 或正文中的减号当列表前缀。
- 勾选框前缀只是输入格式，生成任务仍为未完成，不导入完成状态。
- 重复文本按 trim 后完全相同判断，所有重复行都标提示，默认保留且选中；不跨语言折叠、忽略大小写或去重。
- 不执行快捷时间解析；“明天 15:00 提交报告”完整保留为标题，日期/提醒仍为空。
- 确认前重新校验选中项，不相信首次解析的错误缓存；用户修正文案后可以通过，取消勾选的坏行不阻挡。
- 至少选择一项；生成草稿的 key 按稳定请求 key + 原行号组成，删选其他行不改变剩余行的 key。
- 相同 key 的稳定性只为后续幂等提交提供输入，不等于已经实现数据库幂等。

## 持久化与同步设计门槛（P1a）

下列设计是后续约束，不是已有 wire schema：
- checklist item：UUID、父任务 UUID、正文、顺序、勾选、创建/修改时钟、设备标识、删除墓碑。
- 每条子项记录独立合并；不同子项同时勾选均保留。同子项并发编辑采用明确全序，并以共享 fixture 验证交换/结合/幂等性。
- 排序相同时以 UUID 稳定排列；不为一次重排改写所有未变化子项的内容与勾选。
- 系列定义不与实例勾选共享一条可变记录；修改“以后”不重写历史完成情况。
- 重复实例与其清单项身份从系列、发生时刻、定义条目标识确定性派生；旧端先生成父任务时新端只补缺失项，不复活显式删除项。
- 模板低频整体编辑使用乐观版本检查；远端并发选择规则明确，不假装自动合并两份正文。模板删除具有墓碑。
- 本地创建上限不能充当远端数据截断规则。
- 创建、清单写入、同步标脏、操作回执必须同事务；相同 operation UUID + 相同负载返回原结果，不同负载拒绝。
- 批量创建前校验全部标题、有效分组和父子数量；事务失败零新增，旧回执不伪装成当前成功。
- RPC 超时后先按回执/UUID 恢复结果，不能由 UI 重新生成另一组身份。
- 定义独立对象版本、配置世代、revision/ACK、412 有界重试、404 与鉴权错误、未知版本拒绝。
- 备份新版本、新旧库迁移、删除/恢复及旧端重复实例兼容必须一起验证。

P0 尚未执行上述持久化与同步门槛，不得据纯草稿测试宣称它们已完成。
