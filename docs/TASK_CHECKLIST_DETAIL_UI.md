# 已保存任务清单即时勾选：P1d-2d

日期：2026-09-15。两端开发分支实现，本次按用户授权本地提交；未升版、未推送，代理未安装设备。

## 操作与范围

- 两端点击任务行的“清单 x/y”，或“更多 → 检查清单”，现在默认打开查看面板。
- 查看面板只展示已保存的标题、备注和子项。点击勾选框直接保存当前子项，成功后重新读取、更新进度并保持面板打开；没有“保存”按钮。
- 点击“编辑”才进入原有完整任务草稿，支持字段、清单内容、顺序和重复范围编辑。保存后返回查看；取消只丢弃这次编辑，不撤销之前已保存的即时勾选。
- 新建任务仍直接进入草稿，不提供即时写入。只读任务不允许勾选或编辑。
- 勾选仅作用于当前实例，不自动完成主任务、不修改以后定义，不重新安排日期或提醒。
- 桌面沿用紧凑文字和按钮；鸿蒙使用整行内容、44vp 点击区域及手机/平板共用的受限宽高布局。亮暗主题和中英文沿用现有资源。

## 写入与失败边界

没有新增数据库、Rust 命令、同步对象、权限或依赖。独立的 TaskChecklistDetailSession 在两端采用相同实现：
只接受子项 UUID 和目标布尔值，不接受编辑面板草稿。它从不可变的已保存快照生成原有 ChecklistSave 请求；
标题、备注、其他子项内容/顺序/勾选维持原值，包含删除项的 expected_items 快照不被裁剪。
既有 Rust/RDB 保存事务检查父任务版本和完整子项快照，实际只更新发生变化的子项及父任务修改时钟。

本阶段复用的是完整快照乐观检查，不声称允许同一本地快照上的多个并行写入：
- 写入中暂停其他勾选和编辑，防止交错提交。
- 另一设备/窗口已修改父任务或任一子项时，返回冲突并要求重新读取，不自动重试覆盖。
- 写入失败恢复显示，保留同一个绝对目标值、operation_uuid 和请求负载供用户重试；不会使用“反转当前状态”操作。
- 返回失败也可能代表响应丢失，提示不能确定是否保存，提供重试和重新读取。
- 提交成功后清除可重试请求，必须读取最新状态再接受下一次勾选。读取失败只提供重新读取，不再次保存。
- 回执可能对应较早提交，所以幂等重放之后同样读取当前状态；不根据旧回执直接覆盖屏幕。
- 同步排程/页面刷新在事务之外，回调失败不改写已提交结果。离线本地保存后按现有机制等待同步。
- 关闭失败提示后再打开也会重新读取。已提交勾选不会因为关闭查看面板而撤销。

## 建议验收

1. 打开已有两项清单，勾选一项。关闭后重开，确认保持且任务行显示 1/2。
2. 取消勾选，确认进度恢复；全部勾选后主任务仍未完成。
3. 点击“编辑”，改文字/排序/勾选后取消，确认这些编辑没有落库，先前即时保存的结果仍在。
4. 再编辑并保存，确认返回查看面板且内容一致；空清单可通过“编辑”添加子项。
5. 两端实际同步，核对勾选与计数；一端打开旧详情、另一端修改后同步，旧详情操作应报冲突，重新读取后可继续。
6. 手机/平板检查长文字、横竖屏、英文、大字体和编辑键盘。新建清单仍保持取消零写入、一次保存。
7. 重复任务的当前清单勾选后，生成下一实例，确认下一实例子项未勾选；已归档任务不能修改。
