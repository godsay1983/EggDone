# 任务与便签关联：L2 原子操作

更新：2026-09-12。L1 已本地提交：桌面 5e06653、鸿蒙 c43bba0。L2 本轮实现完成但未提交，未升版、推送或发布。仍无关联按钮、网络传输或备份格式变化。

## 业务边界

- create / create(draft, now, by)：以固定 todo_uuid 创建新任务、建立来源便签关联、写本地幂等回执，同一事务完成。
- change / change(todo, note, active, expected, now, by)：关联已有任务、解绑或显式重新关联；expected 是调用方看到的完整关联记录，首次不存在时为 null。
- 新建草稿支持标题、备注、分组、重要性、全天日期或具体时刻，以及独立提醒时间。标题按 UTF-16 最多 100、备注最多 1000，分组必须存在且未删除。首版新建为不重复任务；可关联已有重复任务的当前实例，不复制重复规则。
- 调用前保留固定任务 UUID；失败重试不得重新生成。取消草稿不调用持久化命令，因此无记录。
- 接入 UI 时必须使用真实本机设备标识，确认后调用；系统提醒、卡片、托盘与界面刷新只能在提交成功后执行。本阶段没有新增 Tauri command 或 ArkUI 入口。

## 幂等与并发

本地 app_metadata 使用 task_note_link_create.v1:<todo_uuid> 存储规范草稿回执，与任务、关联一同提交。回执是本机私有操作元数据，包含草稿内容，不进日志、不上传关联对象；不是密钥或凭据，也不是备份协议。

同 ID、同草稿重试直接返回现有关系，不覆盖用户后来编辑的任务。相同 ID 不同草稿、无回执但已有同 ID 任务均报冲突。若已解绑，旧创建请求返回墓碑，不重新激活；若实体已删除或归档则报不可用。此本地回执不承诺跨设备调用幂等，跨端关系身份仍由 v1 协议决定。

关联两端实体必须存在、未删除，任务不能已归档；已完成任务可保留或建立关系。已有目标状态是无写入的幂等结果；否则当前记录必须和 expected 完全一致，旧请求不能覆盖后来解绑/重连。解绑允许清理缺失实体的既有关系，不删除任何内容。

本地新增活动关系在事务内检查每任务 20 条上限；并发超限数据可读取和解绑，不静默裁剪。写入时间严格大于观察到的实体/关系时间；重新关联保留 created_at。安全整数溢出直接失败并回滚。

桌面使用数据库锁配合 IMMEDIATE 事务；鸿蒙复用任务操作队列并使用原生 IMMEDIATE 事务，入队前复制草稿和 expected。其他写入者造成数据库忙时向上报错，保留原请求供有限重试；不无界自动重试，不吞掉失败。

## 实体生命周期

单条/批量任务删除、系列删除、重复任务跳过、清除已完成、便签删除，都在各自事务中将相关活动关系转为更晚的墓碑。任一关系写入失败，实体删除、重复推进、同步脏标记一并回滚。批量逐任务提交沿用既有语义，不宣称跨整个批次原子。

任务完成、归档、仅停止/删除重复规则不传播或删除关系；未来实例不继承关系。恢复任务或便签不自动恢复关系。当前只协调本机删除入口，远端实体墓碑、部分同步与备份恢复协调属于 L3，尚未接入。

复用原有任务/便签 dirty 触发器及 links revision；不更改数据库 schema（桌面18、鸿蒙19）。links 上传 ACK、ETag 与配置世代仍在 L3。
