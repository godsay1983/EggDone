# 批量创建恢复与收尾（P3c）

日期：2026-09-15。桌面 1.1.0、鸿蒙 1.2.0；SQLite 21 / RDB 22，版本、表结构及同步协议不变。本轮按用户授权本地提交，未推送或发布；提交检查点见最新 handoff。

## 已实现

- 用户确认创建后，先将完整请求写入本机 app_metadata 的 `task.batch.pending.v1`，成功后才进入原有整批任务事务。
- 打开批量面板先读取恢复记录。加载失败时禁用新建，提供重新读取；不会把读失败当作没有待处理请求。
- 重启后展示上次提交的最终标题、统一分组和选中项，保持原 operation/task UUID。仅显示选中项并重新编号，不重新解析标题中的列表前缀，不自动创建。
- 原样重试复用原事务回执；任务已修改、删除或回执失效时仍拒绝重建，不复活旧任务。
- 返回已确认创建结果后才清理匹配的恢复记录。清理失败明确提示“任务已创建”，当前会话再次重试只清理记录，同时仍刷新列表并调度同步。
- “结束本次恢复”需要二次确认，只清除匹配记录，不删除任务或事务回执，不撤销已提交的任务。提示用户先核对列表，避免手动新建重复批次。
- 恢复记录写入、删除均使用独立 IMMEDIATE 事务及完整负载比较；不同请求不能互相覆盖或清理。损坏记录不会自动丢弃。
- 普通输入与预览仍是内存草稿，不持久化未提交文本；本阶段不是通用草稿自动保存。

恢复记录只存本机，不进入任务同步对象或 JSON 备份。未确认记录没有自动过期清理，用户可核对后结束恢复。记录损坏或并发冲突会安全阻止新批次；重启重读仍失败时需要诊断本机存储，不能以清空数据库作为常规解决办法。

## 刷新与同步

任务和同步脏标记仍在 P3a 事务内一并提交。列表刷新、同步调度和鸿蒙卡片刷新沿用生产入口；刷新失败只重试刷新，不调用创建接口。网络失败不回滚本机已创建任务，离线恢复继续由已有同步重试处理。

本轮新增的数据库回归证明：重启原样重试不会新增任务或增加任务脏版本；结束恢复不改变任务和脏版本。原生网络端到端验收仍需用户实际批次测试，不把本机数据库结果当成真实 S3 验收。
