## 2. 状态模型

不要把计划、工作状态和数据去向压成一个枚举。

| 维度 | 语义 | 对应行为 |
| --- | --- | --- |
| 完成状态 | 未完成 / 已完成 | 沿用现有完成字段与完成时间 |
| 工作状态 | 可处理 / 等待中 | 只作用于活动未完成任务，不表示完成或归档 |
| 数据去向 | 正常 / 已归档 / 已删除 / 已彻底删除 | 删除优先于归档；彻底删除是终态 |
| 每日安排 | 某个日期是否主动安排该任务 | 不改变截止日期、提醒、分组或重要程度 |

实体投影先检查彻底删除，再检查软删除、归档、完成，最后解释等待与每日安排。父任务状态不可用时，不得由迟到的计划/等待记录重新显示任务。

| 操作 | 完成状态 | 每日安排与等待 | 提醒和重复 |
| --- | --- | --- | --- |
| 加入/移出今日计划 | 不变 | 只改指定日期的安排 | 不变 |
| 设为等待/恢复处理 | 不变 | 写入/结束等待；移出计划需用户确认 | 不取消截止提醒，不推进重复 |
| 完成任务 | 设为已完成 | 退出可执行计划，等待结束 | 沿用既有完成与后继生成 |
| 归档已完成 | 保持已完成 | 不进入可执行计划 | 不影响已生成的后继任务 |
| 取消归档 | 保留原状态 | 不恢复旧计划或等待 | 不重启旧提醒/规则 |
| 重新打开归档任务 | 设为未完成 | 作为可处理任务，计划需重新加入 | 不重启旧提醒/规则 |
| 从回收站恢复 | 沿用现有恢复语义 | 不恢复旧计划或等待 | 仍作为单次任务恢复 |
| 彻底删除 | 不可恢复 | 清理关联业务内容并保留必要删除凭据 | 禁止后续调度该实体 |

新重复实例、快捷复制和模板创建不继承今日计划或等待原因。普通撤销完成、短时删除撤销的既有语义不在本轮擅自改变；与新维度的具体一致性在 LC0b 共享样例中冻结。

## 3. 归档管理与恢复

### 3.1 入口和列表

- 桌面和手机“更多”内相邻放置“已归档”“回收站”；宽平板在侧栏管理区域相邻放置，窄分屏退回菜单。
- 首版已归档仅包含任务，不增加便签归档。按归档时间降序及 UUID 排序，支持搜索、分页、预览和批量取消归档。
- 列表显示标题、分组、完成状态、归档时间；详情展示备注、清单和关联入口，归档期间内容仍只读。
- LC1b-2b 关联入口首版预览有效关联便签的当前标题和正文，明确只读文字预览，不自动加载附件、不开放编辑或关联变更；返回保留归档详情。读取失败可重试，打开时重新核对关联及便签可用性。
- 读取失败显示重试，不冒充空列表；分页按身份去重，操作前重新读取版本快照。
- “清除已完成”改为“删除已完成”，确认文案明确进入回收站；“归档已完成”保留。

### 3.2 三种动作

1. 取消归档：清除 archived_at，保留完成状态、完成时间、正文、日期、清单及有效关联。不重置清单勾选。
2. 重新打开：原子取消归档并设为未完成，清除完成时间；保留清单勾选，用户需要从头执行时可使用已有复制功能。保留日期并提示过期，不擅自顺延。
3. 删除：从归档页移入回收站，不是彻底删除，不级联删除关联便签。

取消归档后，如果主列表隐藏已完成，提示“已取消归档，可在已完成任务中查看”，可提供一次性“查看”跳转，不暗中永久修改用户偏好。
取消归档和重新打开均不重新注册旧提醒。重新打开的历史重复实例按单次任务处理，解除其旧内置重复/系列绑定；不得改动当前后继实例或活动规则。若目标仍被活动规则认作当前实例，返回明确冲突，不能直接断链。
失效分组降为未分组并提示。任务 UUID 不变，有效关联与清单保留；不恢复此前已解除的关联。

首版批量支持取消归档和移入回收站；重新打开先做单条，避免批量重启历史事项。批量确认固定目标及版本，逐批事务执行，冲突项报告并保留；不得将部分成功说成全部成功。

### 3.3 搜索联动

统一搜索增加“包含已归档”开关，默认开启，仅影响任务结果；普通搜索不查询回收站。
命中显示“已归档”，归档详情直接提供取消归档、重新打开及更多中的删除，复用归档服务，不另写一套恢复逻辑。
动作后保留查询和滚动上下文，刷新状态；如不再符合筛选，说明条目已移出结果。打开结果只读，用户明确点击动作才写入。

## 4. 安全清空回收站

### 4.1 用户体验

- 任务和便签均支持单条彻底删除、勾选后彻底删除，以及清空回收站。筛选后“删除选中”与“清空整个回收站”必须区分。
- 确认显示任务/便签数量及附件影响，说明不能从回收站恢复。取消不写入，不提供容易误触的默认危险焦点。
- “清空”覆盖确认时的全部分页记录，不只是当前页；不删除确认之后新进入回收站的记录。
- 预览后另端恢复或修改的记录跳过并报告，不能重新删除已经恢复的内容。
- 大量记录分批处理，使用持久操作 ID、固定目标快照和进度。中断后只重试未完成批次，不扩大到新记录。
- 成功项目立即退出列表；剩余项、冲突、失败和重试分别可见。本机完成与云端同步/附件清理分别报告。
- 离线可以在已启用兼容协议的设备本机提交；提示等待同步。不支持自动按天清空。

### 4.2 数据设计方向

彻底删除不等于隐藏列表，也不等于简单 DELETE 所有行。设计独立终态删除凭据，按实体类型和 UUID 标识，保存协议世代、操作 ID、版本及必要冲突证据，不保存标题、正文或附件显示名称。
新端合并时，终态删除凭据优先于该身份的任何旧普通实体、恢复动作、清单、计划或等待记录；原 UUID 不允许复活。重复发送同一操作返回已有结果，不再次清理或扩展目标。
具体 wire schema、Object Key、数据库版本和冲突排序在 LC2a 冻结，不能先向既有 JSON 任意追加旧端会丢弃的字段。

单批本地事务内持久化终态凭据、移除可恢复业务内容、协调关系并写入清理队列：
- 任务：清理其清单实例、每日安排、等待原因、创建/重试回执中的正文及相关索引；关联便签自身保留。
- 便签：清理正文、本机历史版本、附件元数据和索引；关联任务自身保留。
- 模板是独立内容快照，不因源任务删除而删除。活跃重复规则/系列定义不能按某一历史实例直接清空；先检查归属。
- 关联只移除对应关系；共享附件文件只有确认无其他有效引用后才可回收。
- 检查 SQLite/RDB 约束、触发器及现有导入逻辑，避免正文移除被触发器解释成普通更新或恢复。

物理文件删除与数据库不能组成同一事务，使用持久清理队列。先确认终态凭据及远端合并已生效，再条件清理远端原图/缩略图，失败可重试，不能盲删不同版本对象。
本机逻辑清除不是磁盘安全擦除。S3 历史版本、独立备份、操作系统缓存、未上线设备的副本不属于即时物理清除承诺。备份回导必须尊重当前终态凭据；恢复到全新独立空间的旧备份另行明确提示。

### 4.3 旧端兼容是阻塞门槛

仅添加一个新删除对象、只检查在线设备版本或只保留墓碑，都不能保证不认识该协议的旧端不会重新显示数据。
建议先原型验证“新协议世代/独立同步命名空间 + 显式迁移”：新端只在迁移确认后使用新空间，不再自动吸收旧空间后续写入；旧端即使继续写，也不能污染新空间。不得靠旧端不会检查的 manifest 声称强制升级已成立。

迁移前必须预览、备份并让用户确认所有需保留的离线修改已汇合；旧空间后续修改不能无提示丢弃。定义切换原子性、失败恢复、重复迁移、凭据切换、首次加入、回退限制以及旧空间保留策略。
若原型不能证明隔离或受控升级有效，LC2 不开放彻底删除按钮。需要用户决定迁移代价时明确提出，不用“只清空显示”替代功能，也不自动清除旧同步空间。
未配置同步的本机模式同样保留终态凭据；未来接入一个旧同步空间前先执行兼容检查，不自动合并。
LC1 可独立交付；LC2 门槛未满足不阻止继续分析，但默认顺序不能擅自跳到后续实现。

## 5. 今日计划

### 5.1 行为

- 任务菜单提供“加入今日计划/移出今日计划”；首版只主动安排今天，不增加未来排程工具。
- 现有“今天”内以分段控件区分“计划做”和“到期/逾期”；不把到期任务自动全部加入计划。两视图可以引用同一任务，各自按 UUID 去重，始终操作同一实体。
- 计划列表支持独立排序，不修改主任务 sort_order；已有今天视图及桌面卡片的到期语义保持不变，首版不重做卡片。
- 昨日未完成可主动“继续安排”，写入今天安排，不改截止日期。推荐列表按任务去重，不把多天历史堆成多条任务。
- 跨日不删任务、不自动迁移未完成项；当天完成的计划项可折叠查看，但不计入可执行数量。
- 保存失败保留原状态，不能先显示已加入再静默失败；快速连击、重复提交不会生成多份安排。

### 5.2 数据与同步

候选领域 daily_plans 使用 task_uuid + plan_date 作为逻辑身份，每日独立成员/移出标记、排序及版本。日期按设备当地日历日期记录，不转换成 UTC 零点；另一时区设备保留原计划日期，不擅自移动。跨时区看到不同“今天”须有测试和明确说明。
与父任务 UUID、完成/归档/删除生命周期共同校验；完成后恢复、从归档/回收站恢复不能因旧关系迟到而重新加入计划。LC0b/LC3a 冻结生命周期栅栏与确定性标识，不以查询过滤替代持久移出/失效策略。
独立同步领域、revision/ACK、删除记录及备份升级；旧端缺少领域不等于删除计划。跨端重排确定性合并，不能整表覆盖另一端新增项。采用现有同步调度，不承诺后台实时同步。

## 6. 等待处理

- 未完成、未归档、未删除的任务可设为等待，提供可选原因及“下次查看日期”；原因先定上限 200 UTF-16 单元，空原因允许，输入校验两端一致。
- 日期表示需要再次查看，不是截止日期，也不是精确系统闹钟。首版在应用内显示“该复查”，不新增通知权限或后台唤醒承诺。
- 等待页支持按查看日期/更新时间排序，无日期排在有日期之后；显示原截止日期和逾期标识。
- 到查看日后不自动恢复可处理，也不自动新增今日计划。用户点“恢复处理”才结束等待。
- 设等待时若在今日计划，提供“同时移出今日计划”选项，默认不勾选；用户选择后同事务生效。保留在计划的等待项明确标记，且不计入可立即执行数量。
- “全部”仍可见等待项，今天到期/逾期与四象限不隐藏其风险；专门的计划/可执行投影按工作状态区分。
- 完成、归档或删除终止等待；重新打开和回收站恢复不自动恢复旧等待。复制、模板、新重复实例不继承等待原因。
- 独立 workflow_state 领域记录状态、原因、查看日期和版本；恢复处理写显式 ready 状态，不用字段缺失表达清除。终态只保留必要失效凭据，等待原因不写普通日志。
- 状态与计划联合修改走 repository 事务，系统提醒/界面刷新在提交后协调。父任务完成/删除与远端等待更新并发时，由父生命周期裁决，旧等待不得复活。

## 7. 架构与交付约束

| 层次 | 桌面 | 鸿蒙 |
| --- | --- | --- |
| 界面 | 独立归档管理组件，复用 TrashDialog、ContentSearchDialog 和 Today 区域 | components 下独立归档/计划/等待组件；手机平板共用业务 |
| 状态/API | api + store，版本化命令和错误映射 | store 编排、严格 models |
| 数据 | Rust archive / purge / planning / workflow 模块，SQLite 增量迁移 | repositories + services，RDB 增量迁移 |
| 同步 | 独立领域协议与会话接线，沿用 ETag 条件写入和世代保护 | 与桌面共享 wire fixtures 与冲突语义 |
| 入口组合 | TodoPanel 只接入口和导航 | Index 只接页面组合，不堆数据库/网络逻辑 |

- 所有破坏性写入在权威层复核身份、类型、版本、父状态及关系；参数绑定，取消零写入。
- 事务失败全部回滚；提交成功但刷新/通知/同步失败，报告“已保存，后续处理失败”，不能重放创建或删除。
- 继承既有错误重试、同步凭据保护和时间戳校验，不升级无关依赖。
- 新领域需要备份预览、旧备份缺失领域保留、新格式旧端拒绝策略。具体 schema 编号及备份新版本在实施阶段分配，本轮不预写迁移。
- 新同步领域的 ack 不能覆盖其他领域未上传变化，配置切换后丢弃旧会话确认。
- 两端文案、概念和动作一致，不强求相同布局。使用现有主题/控件，操作收在更多菜单，避免每个新增能力增加一整行按钮。
- 手机、小平板、大平板、分屏、桌面窄窗及 100%/150% 缩放验证；键盘不遮挡原因/搜索输入和确认按钮，中英文、深浅色、大字体覆盖。
- 阅读源码和自动化不等于真机或真实用户 S3 验收，分别记录。

## 8. 验收门槛

| 领域 | 必测场景 |
| --- | --- |
| 归档 | 已完成/历史重复任务、取消归档后隐藏已完成、重新打开不重启提醒、失效分组、清单/有效关联保留、版本冲突 |
| 搜索 | 包含归档开关、结果内两种恢复、动作后分页/滚动保持、搜索与归档页使用相同服务 |
