# 全天任务日期同步映射（NS5-D2A）

## 范围与数据契约

本步是 DNS5-D2/HNS5-D2 的日期映射子阶段，不代表规则同步编排完成，也不开放自定义重复入口。

- 两端同步 JSON v1 不变。全天任务使用 `due_date: YYYY-MM-DD`、`due_at: null`；定时任务反之，无日期任务两者均为空。
- 桌面端复用已有 `todos.due_date`，本地数据库版本仍为 17。
- 鸿蒙本地数据库迁移到 18，增加 nullable `todos.due_date`。这是本地存储差异，不要求两端数据库版本相同。
- 鸿蒙保留本地 18:00 时间戳作为现有任务 UI 的兼容投影，但同步导出以独立日期字段为准，不能上传投影代替全天日期。
- 自定义重复事务新建全天实例时，在同一个事务中保存日期和投影；定时实例不写入日期。
- 旧 daily/weekly/monthly/weekdays 任务维持原有日期协议及本地时间保留逻辑。

## 编辑与展示

- 修改标题、备注、提醒、完成状态不会改变全天日期。
- 编辑器回传的时间等于当前时区的日期投影时，保留全天属性。更改时间或清除日期时，清除全天日期；重新设置旧时间不从旧回执恢复全天属性。
- 当前 UI 尚无独立“全天/定时”切换；主动选择同一天 18:00 与未修改无法区分，暂按未修改保留。这不是最终自定义规则编辑器设计。
- 标准详情编辑不清除 repeat_rule 为空的独立规则实例关联；从旧快捷重复改为不重复仍沿用原解除逻辑。
- 主页面读取时按当前时区重建投影，不写库、不制造新的冲突时间或 dirty。
- 鸿蒙桌面卡片按字面日期筛选全天任务，以月/日展示，不把 18:00 当作真实到期时刻；今天的全天任务不会因超过 18:00 就标为逾期。

## 迁移与限制

迁移只增加字段，不把旧的 18:00 定时任务猜测为全天任务。DDL 和版本记录在事务中执行，失败回滚，可重试。

旧版本已经把全天语义写成定时值的数据，不做启发式修复；需要从可信原始备份或明确的业务记录恢复。此前未开放的 C2 内部实例回执不是当前任务日期的权威来源，不自动覆盖人工编辑。后续规则同步启用前需继续处理首实例关联及历史内部测试数据兼容。

无效日期或本地时区不存在的整天拒绝投影，不静默移动到另一日。

## 自动化证据

- 共享 `docs/fixtures/todo-date-roundtrip-v1.json`：8 个连续状态，覆盖全天、闰日、1970 年以前日期、定时、无日期、完成和删除。
- 桌面端生产 SQLite 迁移、合并与导出回归，每个状态重放两次；随 `pnpm release:check` 执行。
- 鸿蒙 `scripts/test-todo-date-roundtrip.cjs --desktop=D:/Develop/EggDone`：实际 ArkTS 服务及 Repository 转译后接入主机 SQLite，验证往返、编辑、旧重复、桌面卡片、单行写入失败、迁移失败回滚/重试和幂等。
- 主机回归分别使用 Asia/Shanghai、America/Los_Angeles、Pacific/Kiritimati；另有 Hypium 日期映射单测。
- 这些不是原生 RDB、桌面卡片真实渲染或 S3/MinIO 联调验收。
