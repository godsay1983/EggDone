# 本机快照隔离恢复验证

日期：2026-09-18。纳入本次本地提交、未推送、未发布；版本、数据库 schema 和公共同步/备份协议不变。

## 本轮变化

两端“迁移准备”中的“准备本机快照”和“重新校验”增加真实建库恢复验证，不另加恢复按钮：

1. 校验持久计划、manifest、快照和全部附件。
2. 创建唯一的隔离临时数据库，运行本端现有完整 migration。
3. 校验内部格式、客户端、schema、固定的 24 张表、列名、行宽和字段类型。
4. 在事务中清除新库的初始化行，先装入永久删除保护和清理队列，再恢复业务记录，最后恢复对应同步状态。
5. 保持原生约束和触发器启用；插入值参数绑定。完整重新采集数据并比较摘要，检查外键。
6. 提交、关闭、重新打开隔离库，检查数据库完整性和完整数据摘要。
7. 按 UUID/original、UUID/preview.jpg 重建独立附件目录，刷盘、关闭并重新读取校验，包括回收站附件。
8. 清理本次临时资料后，再复核当前源数据及持久计划，才记录校验成功。

任意恢复、重开、附件复制、清理或源复核失败都不能显示恢复通过。失败保留原始快照，允许重试。
历史 verifiedAt 仍只作历史记录，重进面板必须重新校验；旧版本生成的记录不能自动当作恢复证据。

## 安全边界

- 不替换 live 数据库，不注册提醒、不启动恢复库的同步，不读取或导出凭据。
- 桌面临时库位于当前快照下的独立 recovery-UUID 目录；删除前核对真实路径仍是该快照的直接子目录。
- 鸿蒙通过独立 eggdone-recovery-UUID.db 配置打开 RDB，不经过 Database 的应用单例；关闭后使用对应配置删除。
- 内部恢复执行器拒绝已有应用 schema 的目标；没有接收任意库路径、表名或 SQL 的 UI/API。
- 不关闭终态保护触发器。快照若同时包含已永久删除 UUID 与对应实体/附件/关联，恢复失败，不能靠恢复复活内容。
- 当前是逻辑记录与附件的隔离恢复验证，不是可跨端导入备份，不还原原库文件页、sqlite_sequence 历史高水位、系统提醒、凭据和系统设置。
- 快照中的本机绝对路径字段按原值保留用于一致性比对；隔离附件通过 UUID 映射验证，不把该临时库当成可直接替换运行的数据库。正式回滚还需要受控路径重绑定及应用状态切换。
- 正常结束及可捕获异常会关闭/清理本次临时资料；进程被强杀、断电或清理失败仍可能留下隔离文件，本轮没有启动时扫描清除器，也未验收物理断电。
- 全量文件验证、恢复复制会额外使用磁盘空间；磁盘不足必须报错，不跳过附件。缺附件下载尚未实现。
