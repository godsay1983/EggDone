### 真实故障及修复

- 在隔离SQLite中，仅为本次生成的QA便签安装内容UPDATE拒绝触发器；不改用户库，不给正常用户路径添加故障开关。
- 输入新正文后确认数据库仍为旧正文，编辑器显示错误和重试。点击删除后正文与便签均保留，创建关联也被阻止。
- 但是删除按钮的异步回调仍将保存异常传播为未处理Promise。初轮实际WebView捕获1条pageerror，测试失败；数据保护并未失效，不能描述成误删数据。
- 桌面编辑器与便签列表统一调用 `requestNoteDeletion` 这一UI边界，消费已经由NoteStore展示的失败。底层 `deleteNote` 仍拒绝失败调用，保存/删除失败不清空选择、不丢草稿、不显示成功。
- 宿主测试保留底层拒绝断言，补充两个UI入口绑定、失败保留和成功删除断言；没有放宽原有保存要求。

### 修复后原生结果

1. SQLite真实保存失败时，删除和关联创建被阻止；原记录未删除，脏正文仍在。
2. 移除触发器后点击重试，实际SQLite正文更新为保留的输入。
3. 关联管理停留在旧版解绑确认时，通过另一原生调用解绑再重连。旧确认被实际Repository的预期版本检查拒绝；重新选择和确认后解绑成功，源便签未删除。
4. 上述流程中pageErrors为空。触发器由finally清理，核对剩余数0；脚本不移除其他运行遗留的触发器。
5. 第一批8组原生关联/附件/滚动/缩放回归重新运行通过。
