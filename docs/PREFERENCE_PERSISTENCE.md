# E6b2 通用偏好与任务视图持久化

日期：2026-09-11。状态：双端实现、构建及自动化通过，部分模拟器运行验证通过；用户验收待确认。本轮按用户要求提交当前E6a/E6b1/E6b2成果后继续E6b3；不推送、升版或发布。

## 本轮实现

### 桌面端

- 在现有 SQLite app_metadata 中新增 general_preferences_v1，内容包含 version、revision 和受限偏好键集合，不新增数据库表或同步协议。
- 迁移主题、语言、显示已完成、默认/最后任务视图、所选分组、智能筛选、专注/休息默认时长。窗口/缩放、快捷键继续使用原有存储；最近专注目标不在本轮迁移内。
- 只有原生读取成功且没有记录时，才完整读取旧 localStorage 并迁移；旧值保留为迁移来源。任一读取失败、损坏记录或未知版本均不以默认值覆盖。
- 迁移后原生库为唯一权威来源，不要求 WebView 旧值继续更新。仅浏览器预览仍使用 localStorage。
- 主页面和专注窗口等待初始化尝试完成后挂载；失败时仍可加载任务并显示偏好异常。
- 写入按单项在原生数据库锁内合并，避免窗口之间覆盖无关字段。带修订号的通知更新语言、主题和专注默认值，过期通知不回退缓存。
- 主题、语言、默认视图和时长在写入确认后更新；浏览筛选可先应用，保存失败继续显示警告。失效分组在成功加载分组列表后回退全部。

### 鸿蒙端

- 在现有 RDB app_metadata 中新增 task_view_preferences_v1，保留显示已完成、所选分组、默认视图和最后任务视图；智能筛选继续使用原有 smart_view 键。
- 设置页增加“默认任务视图”：记住上次、全部、今天、四象限、日历。手机自动换行，平板保留同一语义。
- 默认选项为记住上次；旧库无值时沿用全部、所有分组、显示已完成。便签、搜索文字、滚动位置不进入长期视图偏好。
- 已保存的智能筛选恢复时仍优先进入全部视图并应用该筛选；固定默认任务视图不是清除智能筛选的替代操作。
- 浏览操作立即生效，写入串行执行；保存失败显示“当前筛选已应用，但尚未保存供下次启动使用”，首页及设置页可重试。
- 加载失败不写默认值覆盖，分组/显示已完成选项在未就绪时不更改；导航加载晚到不覆盖用户新切换的视图。
- 分组列表尚未成功加载时不判定分组失效；删除或同步移除分组后回退全部，不删除任务。

桌面窗口重新获得焦点或重新可见时会回读原生偏好，补偿漏接窗口间通知；不重建任务列表或重置正在进行的专注。

## 用户验收步骤

1. 桌面：更改主题、语言、专注默认时长，切到日历、选择分组并隐藏已完成。从托盘选择“退出”，重新启动，确认设置保留；只关闭窗口不算退出。
2. 桌面：打开独立专注窗口，检查语言、主题和默认时长与主窗口一致。正在进行的专注计时不应因默认时长修改而重置。
3. 鸿蒙：更多 → 应用设置（平板侧栏 → 设置），找到“默认任务视图”。选择今天，结束进程再启动，应显示今天；测试前清除智能筛选，避免既有筛选优先级影响结果。
4. 鸿蒙：改为记住上次，选择工作分组、隐藏已完成，切到日历，结束进程再启动，确认三项保留。
5. 鸿蒙：从任务进入便签后结束进程，重新启动应回到任务视图而不是便签。期间不使用未保存草稿作为恢复测试。
6. 两端：选择某个测试分组后删除该分组，确认回到全部，任务不因筛选恢复而丢失。无需删除真实工作分组，可使用已有测试数据。
7. 覆盖安装新版后检查旧偏好仍存在；卸载或清除应用数据不在保留承诺内。读取/写入故障已有自动化，不要求手动破坏数据库。
