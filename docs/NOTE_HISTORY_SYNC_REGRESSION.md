# 便签历史恢复同步回归

更新：2026-09-12。对应 E8b3a；E8b3 整体尚未完成。本文两端保留同一副本。

## 验证范围

- 桌面使用生产历史事务、迁移、SQLite 与完整同步内核；鸿蒙使用生产 NoteHistoryRepository 和完整 SyncService，在宿主 Node SQLite/HTTP 适配器运行。
- 双方对独立的本地数据库使用真实签名 HTTP 请求交换 S3 对象，不复制数据库，不使用假 S3 响应代替成功或冲突。
- S3 为临时 SeaweedFS，固定镜像 `chrislusf/seaweedfs:4.34`，只绑定本机回环地址，数据放临时内存卷；独立运行 ID、桶和公开测试凭据。不会读取应用凭据、用户桶或现有设备数据库。
- 这不是原生 ArkData 经系统网络的全链路，也不是窗口/通知验收。已有原生 RDB 测试及 UI 检查是独立证据，不能简单拼接成整条原生用户流程已通过。

## 四阶段往返

1. 桌面准备：在独立库产生从未同步的私人历史，再写入当前版本；上传当前文字、颜色、置顶、关联和测试附件原件。直接读取远端对象检查历史字段和私人旧文未泄露。
2. 鸿蒙交换：新库首次下载没有历史列表。产生本机文字历史后保存预览，另一个独立客户端更改远端正文；真实同步后旧预览恢复被拒绝。重新预览并恢复，保留刚被替换的当前文字。注入离线边界后仍保留本地恢复结果与待同步状态，重试后旧客户端收敛到恢复结果，附件和关联不变。
3. 桌面反向：收到鸿蒙恢复结果，但没有收到鸿蒙的历史列表。在本机创建历史并重复远端并发更新、拒绝过期预览、重新预览恢复；错误测试凭据造成真实请求失败后，本地恢复文字不丢失，正常凭据重试成功。此前离线的客户端不会将恢复结果回退。
4. 鸿蒙复核：再次用全新独立库接收桌面恢复结果，核对正文、标题、颜色、置顶、关联、附件元数据及已同步状态；历史列表仍为空，重复同步不制造同文字历史。

恢复前后比较文字版本与非文字元数据；桌面直接检查远端对象白名单、当前正文、历史字段/私人旧文排除，以及测试附件原件字节一致。首次试跑的反向比较发现夹具初始化的旧关联记录也会参与正常冲突合并，已在记录基线前完成夹具收敛，未删除元数据保持断言。

## 编辑保存与入口保护

鸿蒙 `test-note-history-ui.cjs` 新增生产 NoteStore、父页面方法及对话框方法的集成场景：

- 已有写入进行中打开历史，等待真实保存队列排空，不提前展示历史。
- 等待及预览期间的迟到输入不入队，重复打开不启动第二次写入。
- 恢复后的相同输入事件不触发自动保存；再次编辑以恢复后的文字为起点。
- 恢复写入成功但刷新失败，关闭后不保留可回写旧文的编辑器和队列。
- 关联创建/管理或页面导航已经在等待保存时，不得再打开历史；历史打开或预览期间，后台导航准备返回失败。

入口竞态用例先在原代码复现失败，再补充生产入口条件通过。此修复只涉及鸿蒙页面互斥保护，不修改同步协议、schema 或用户数据。

## 运行方式

Windows PowerShell 7，在桌面仓库根目录：

```powershell
./scripts/run-sync-core-s3.ps1 -NoteHistorySessions -HarmonyRoot D:/Develop/EggDoneHarmony
```

如端口被占用，用 `-Port` 指定另一个空闲端口。脚本拒绝同时选择多个套件，验证精确 Rust 测试计数及双方阶段完成标记；失败也会在核实运行标签后清理本次容器，日志保留在临时目录。不会主动拉取镜像或删除其他容器。

鸿蒙仓库：

```powershell
node scripts/test-note-history-ui.cjs
node scripts/test-note-history.cjs
```

桌面仓库：

```powershell
cargo test --manifest-path src-tauri/Cargo.toml --lib note_history
./scripts/run-sync-core-s3.ps1 -TrashRecoverySessions -HarmonyRoot D:/Develop/EggDoneHarmony
```
