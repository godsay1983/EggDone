## 结论

当前不是“只差界面”，也不是从零重做：本机清空、确认与重试入口已实现；
有同步配置或同步历史的用户仍不能清空。剩余主要是生产链路整合，而非继续补通用基础设施。

前面轮次过多的原因是把备份、暂存、协议等内部步骤不断作为阶段交付，
没有先贯通“删除 -> 传播 -> 另一端不恢复 -> 附件清理 -> 失败续作”的流程。
后续先在隔离新空间贯通这个流程，再连接真实迁移入口；不再让迁移准备功能无限前置。

补充风险：
- 数据库触发器会拒绝父任务/便签复活，但不能代替同步过滤。直接把旧记录交给原合并器会报错，或让同批其他数据无法同步。
- 本机 erase 会拒绝仍被活动重复规则引用的任务。远端终态遇到离线旧规则时，不能简单复用这个拒绝路径，必须让终态优先，同时保护独立规则定义和其他实例。
- sync_target 的配置失效逻辑可复用，但其现有实现没有重置 lifecycle_sync_state；需要与新空间证明及配置切换一起纳入事务。
- 现有迁移预检会阻止本机终态和未完成清理队列。不能据此宣称“本机清空过的设备”已经可以加入新空间；加入流程也要覆盖这种设备，不能删除账本绕过。
- 旧备份遇到本机终态的拒绝/回滚已有实现；没有逐项冲突预览不是目前必须新增的功能。
- 保留旧空间意味着旧空间、暂存快照和独立备份可能仍保留副本。“清空当前空间”不等于擦除全部历史副本，也不保证立即释放桶内全部相关容量。

## 连续实施的三个验收环节

这些是同一个功能的内部检查点，不是三次要求用户“提交、下一步”的交付。
没有完成全部环节前，LC2 仍为开发中；不能跳至今日计划或等待处理。

### A. 新空间清空与防复活

目标：在隔离测试空间，通过两端真实同步服务和本地数据库完成清空流程，不只调用传输函数。

必须同时落地：
- 终态账本的严格校验、只增合并、条件发布、持久 ACK；缺失或损坏账本停止新空间写入。
- 任务、便签、清单、关联、重复规则及附件在读入、合并、上传和本机显示前遵守终态优先；不删除独立模板或无关实例。
- 并发会话发现终态变化后重新合并，不把过期上传当成完成。不能假设多个 S3 对象具备原子提交能力。
- 清理队列在正文删除前保存附件 UUID、所属便签、原图/预览哈希和大小、目标空间/epoch 等最小必要证据；按需要新增正式数据库迁移，覆盖旧队列升级，不能伪造缺失校验值。
- 先确认删除证据已发布，再清理当前空间正文和附件；先检查终态及有效引用，再做内容校验与条件删除，丢失回复可安全重试。
- 没有附件清理权限不回滚已经完成的记录删除，也不显示“全部完成”；保留待清理和重试状态。
- 新空间能力检查与生产会话一起接好后才允许测试激活；不能通过全局取消保护开展测试。

验收：A 端清空，B 端持离线旧副本重新同步，记录不重新出现在活动列表、回收站或搜索；
无关数据正常收敛；终态并发、附件失败、数据库回滚、应用重启后可恢复。反向再执行一遍。

### B. 旧空间迁移与另一端加入

目标：普通用户从回收站提示进入一次迁移流程，两端最终使用同一个可验证空间。

必须同时落地：
- 从已验证种子初始化八域、终态域及附件；空域也创建，预检真实封装大小及跨域引用。
- 一个旧来源对应一个明确发布结果。优先用固定来源记录的条件创建及完整读回解决竞争，不建立通用分布式选主、租约或后台协调平台。
- 同事务保存激活证明、Object Key、目标 epoch 和所有领域 ACK 失效状态；持久进度支持进程退出后判定旧空间或新空间，不混用两者。
- 另一端加入已发布空间，不再独立复制一个副本。加入前备份并处理未汇合修改，先获得终态再允许旧本机数据合并和显示。
- 已在本机清空过的设备也必须保留并合并终态；已有未完成清理不能因切换而改删另一空间。
- 保留旧空间且不自动追赶旧端后续写入；来源发生变化时明确提示和重新确认，不静默丢弃修改。
- 用户操作收敛为“检查并准备 -> 确认迁移/加入 -> 完成”，备份、复制、核对成为同一流程的内部进度，不要求用户逐个理解工程按钮。

验收：两端从旧空间迁入同一目标后均可清空；迁移中断、两端同时发起、晚到旧端写入、切换期间迟到 ACK 均不损坏数据。
只有暂存 published 标志或手动填写新 Object Key 都不能取得清空权限。

### C. 产品反馈与发布验收

目标：页面显示与实际进度一致，用户能理解和处理部分失败。

- 复用现有单条、批量、清空全部确认；目标在确认时固定，新删除的内容不被顺带清除。
- 区分“本机已移除、等待同步、云端附件待清理、已完成”，停止/重试不会扩大目标。
- 结果说明当前空间范围及旧空间/备份保留事实；不承诺取证级擦除。
- 旧备份冲突继续明确拒绝并回滚，不以新增导入冲突选择器阻塞本次交付。
- 隔离真实 S3 验证完整服务，不再以八域传输往返或 host 模拟激活代替；保留桌面 SQLite、鸿蒙原生 RDB 的区别。
- 桌面及手机/平板验收迁移、清空、离线重连、断网、凭据/权限失败、强杀恢复和中英文/亮暗/窄宽布局。

最终通过条件：真实产品入口可操作；同步用户不再被一律阻止；
离线旧副本不能复活清空内容；失败可重试；独立内容、旧空间和备份没有误删。
开发验证通过与用户真机验收分别记录，不将后者提前勾选。
