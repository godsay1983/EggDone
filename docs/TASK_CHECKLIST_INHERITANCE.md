# 检查清单继承与补齐（P1c-1）

日期：2026-09-14。两端生产逻辑已实现；P1c 整体仍未完成。
范围仅为重复实例清单继承和已有任务的迟到补齐，不含清单网络传输、备份 v4 或 UI。

## 已实现

- 完成或跳过高级重复任务后，下一实例从已保存的系列定义取得清单，不复制当前实例的临时文字或勾选。
- 子项 UUID 使用已冻结的 UUIDv5 规则；正文/排序来自定义，勾选为 false，创建/修改时间来自定义 created_at，updated_by 固定 checklist-seed-v1。
- 新任务、清单、规则进度、操作回执及标脏共用调用方事务；清单失败也回滚原任务完成或跳过。
- 同步前本地快照准备增加迟到补齐，覆盖定义较晚到达和旧端生成的、能验证身份的已有任务。
- 只插入缺失子项；已有项即使已改文字、顺序、勾选或写入删除墓碑，也不覆盖。身份不匹配时整笔拒绝。
- 缺失父任务不会新建；父任务删除/归档时不补齐，恢复且再次执行准备后才补齐。
- 停止规则仍可补齐已有历史实例，但不会因补齐创建新的父任务。
- 空/删除定义不生成子项；合法远端定义超过本地 20 项新增上限仍完整继承，遵守全局 10000 项/文档字节数上限，超限整体失败。
- 清单修改不改变父任务日期、提醒、完成状态或当前规则进度；补齐失败不被当成同步成功。

## 身份证据

先确认定义与规则的 rule_uuid、first_todo_uuid、日程和时区一致，再检查父任务的系列绑定、非旧式重复及可写状态。
发生日和序号使用已有重复引擎计算，不复制日历算法，不信任传入的布尔“已验证”标志。

优先使用原生重复流程已保存的实例回执，并校验 occurrence_key、日期、UUID 和时区计算后的 planned_due_at。
没有回执时使用规则当前进度、全天任务日期或定时任务附近 UTC 日期作为候选；必须通过完整重复日程和确定性父 UUID 验证。
定时任务的日期候选还必须与规则时区计算的实际时间一致；UTC 候选不是本机时区推断，也不按设备当前日期补齐。

历史任务被改成其他日期，且没有回执或可验证进度时，保留待补齐状态，不反推或遍历猜测原始日期。
手工任务即使具有相同日期和系列字段，也不能绕过确定性 UUID 校验。
首个任务只保存自己的清单，不从定义继承；分叉后旧实例回执不得用于新规则的首项。

## 代码入口

桌面：
- `src-tauri/src/task_checklist_inheritance.rs`：repair / repair_in_transaction，修复调用方拥有事务或独立事务。
- `recurrence_transaction.rs`：只补本次生成的 next.uuid，与任务生成一起提交。
- `recurrence_snapshot.rs`：本地规则依赖准备后补齐已有实例；不是远端清单上传回执。

鸿蒙：
- `data/repositories/TaskChecklistInheritanceRepository.ets`：repairInTransaction，必须由外层提交或回滚。
- `RecurrenceTransactionRepository.ets`、`services/sync/RecurrenceSyncSnapshot.ets`：对应生成和本地准备入口。
- `services/repeat/RecurrenceEngine.ets`：新增 occurrence 日期查询，复用已有日期/序号校验。

不增加系统 API、权限、依赖或数据库迁移，不接触实况窗与小艺。鸿蒙测试仍使用宿主 SQLite/crypto 适配，不将其等同于原生 RDB。
