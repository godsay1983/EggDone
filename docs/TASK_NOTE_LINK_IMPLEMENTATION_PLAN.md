# 任务与便签关联实现方案

更新：2026-09-12。
状态：L3d2a已提交（桌面de60450、鸿蒙9fd7038）；L3d2b跨端完整业务服务的隔离S3交换、冲突和恢复自动化通过，见[证据与宿主适配边界](TASK_NOTE_LINK_FULL_SESSION_TESTS.md)。L3d3与L4仍待完成，不升版、不推送。两端采用同一业务与协议语义。
权威数据契约见 [TASK_NOTE_LINK_PROTOCOL.md](TASK_NOTE_LINK_PROTOCOL.md)，阶段证据见 [TASK_NOTE_LINK_ROADMAP.md](TASK_NOTE_LINK_ROADMAP.md)。下文未来业务流程是后续设计，不代表已开放。

## 范围

核心流程：从已保存便签创建一个关联任务；从任务打开来源便签；从便签查看关联任务。用户主动建立关系，不自动抓取剪贴板或文件。
首版只操作本次任务，不自动把关联继承到重复规则的下一实例。保留现有 Todo.note 纯文本备注语义，不把它改成 Note UUID。
首版每任务最多 20 条链接；上限只限制本地新建，不在同步时丢弃远端有效记录。并发超限仍显示现有链接并禁止新增，允许用户解绑。

## 独立数据模型（L1 已冻结）

已冻结文档 task-note-links.json v1：
- uuid：由固定命名空间与规范化 todo_uuid + note_uuid 派生的 UUID v5，同一对实体只有一个逻辑链接。
- todo_uuid / note_uuid：不可变身份，严禁跨设备整型 id。
- created_at / updated_at / updated_by / deleted_at：与现有安全整数时钟、设备标识和墓碑约束一致。
- 不保存标题副本、附件、正文或额外排序；展示按 created_at/uuid 稳定排序。
- 同 UUID 不同端点、非法 UUID、超范围时钟、未知版本整笔拒绝；删除/重连同一对使用新单调时钟，不清理历史冲突证据。
- 冲突按 (updated_at, updated_by, isDeleted, deleted_atOrMinusOne, created_at) 字典序选择完整记录，详见协议；不靠数组顺序决定。

本地独立 task_note_links 表与迁移，桌面 SQLite / 鸿蒙 RDB 分别实现。唯一端点组合、查询索引、待同步状态与墓碑保留策略一并设计。不得提前写入当前 Todo/Note JSON，也不得与 recurrence-rules 对象混用。

## 生命周期和并发

- “从便签创建任务”：用户确认草稿后，同一数据库事务创建 Todo 与 link，并标脏两个领域；取消无记录。新任务 UUID 在重试中保留。
- 选择已有任务建立链接：读当前实体，要求均未删除；已存在活动链接视为幂等成功。
- 解绑仅写 link 墓碑，不删除任何任务/便签/附件。
- 删除实体：本机同事务删除关联链接；从旧客户端收到实体墓碑时，合并后写单调 link 墓碑。绝不据“本次下载未出现实体”推断删除。
- 缺失端点可能是部分同步，保留悬挂链接，不显示可点击坏入口，不删除对方内容；两个实体到齐再显示。
- 恢复实体不自动恢复链接。恢复旧备份不能覆盖较新解绑墓碑；重新关联必须由用户显式发起。
- 任务完成、归档不会删除链接；来源便签内可区分未完成/已完成/已归档；打开归档任务使用可达的只读详情或明确提示。
- 重复任务只链接当前实例，UI 明确标“仅本次”，不得向未来自动扩散。
- 空便签尚未持久化时不启用关联动作；先保存内容或附件再创建关联任务。

## 同步与备份

默认 Object Key 从 Todo Key 同目录派生；设置页只读展示，换目录沿用现有配置世代隔离。
下载合并 Todo 和 Note，再合并 links；上传实体在前、links 在后。局部失败保留分领域 dirty；412 重试有界，不循环刷新 UI。远端 404 与鉴权/临时错误严格区分。
只在本地已有链接或确认远端对象存在时启用该领域；兼容旧客户端不读取/删除未知对象。旧客户端删除实体后的清理由新客户端依实体墓碑执行。
数据备份v3已冻结并实现，包含 task_note_links 与关联数预览，不加入凭据、ACK或链接操作回执，见[TASK_NOTE_LINK_BACKUP_CONTRACT.md](TASK_NOTE_LINK_BACKUP_CONTRACT.md)。完整备份沿用既有附件文件，不因关系重复复制。导入一笔事务合并实体与links，恢复和同步互斥；本地解绑不能被备份活动记录复活，未知新版显式拒绝。旧v1/v2无links字段不清空现有关联。
不借关联功能修改自定义重复或实况窗协议。

## 桌面实现

- 新 link 类型、Rust repository/command 和原子创建用例；数据库层负责限额、并发与幂等。
- 现有 NoteEditor 更多菜单新增“创建关联任务”，复用快速收集确认层并预填标题，便签正文不整篇塞入标题。
- TodoItem 元数据行展示链接图标与便签标题；多条显示数量，点击受控弹层选择；不再给每任务加一排常驻按钮。
- NoteEditor 底部内容区提供可折叠关联任务列表，固定工具栏不挤占正文；选中项可打开或解绑，长标题省略并提供 tooltip。
- 返回来源便签保留未保存草稿和滚动位置；目标已删时提示并刷新，不空白跳转。

## 鸿蒙实现

- models、repositories、store、sync 服务按现有边界分层；ArkUI 只绑定状态。
- NoteEditor 更多/管理入口新增“创建关联任务”，复用独立确认弹层。
- 任务状态区域显示便签标签/数量，不挤压 More 按钮；便签正文下方关联列表按需展开。
- 手机受控 Sheet/编辑层，平板限制宽度；固定头尾、正文滚动，避免图片/附件与新关联列表争抢固定高度。
- 同语言/亮暗主题共用字符串与语义色，按钮沿用胶囊，图标加可访问名称。
- 创建、解绑、部分同步失败后由 store 统一刷新两侧；不从 Index 直接写数据库。

## 错误与安全

加载失败保留已显示内容并提供重试；保存中禁止重复提交；并发删除实体时原子创建失败并保留草稿。日志只记错误分类/计数，不记便签正文。链接不授予文件或网络权限，不执行外部 scheme。
空态不显示假的便签或占位任务；无链接时不添加无意义空块。

## 验收条件

共享 fixtures 覆盖确定性 UUID、冲突、墓碑、缺端点、重复创建、解绑后旧备份恢复、旧客户端删除和配置切换。
两端原生测试覆盖 Todo+link 同事务回滚、恢复、限额和新旧迁移；真实 S3 双向、离线并发、部分失败。
UI 验证中英文亮暗、窄桌面、手机/平板横屏、键盘/大字体和长标题；已有便签正文与附件可用空间不退化。
见配套 Roadmap；L1 内核交付不等于关联功能已上线，L2-L5 与完整原生/跨端验收仍须单独完成。
