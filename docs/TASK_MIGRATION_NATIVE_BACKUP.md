# 原生迁移恢复快照与准备入口

日期：2026-09-18。开发增量，纳入本次本地提交，未推送、未发布；桌面 1.2.0 / SQLite 22，鸿蒙 1.3.0 / RDB 23 不变。

## 可见入口

配置过旧同步空间的设备在回收站尝试永久删除时，原有安全拦截下新增“迁移准备”。
面板提供“准备本机快照”和“重新校验”，显示附件文件数、数据量、当前校验结果、源数据变化和失败提示。
从单条详情进入时先返回列表上下文。处理中禁用重复操作和关闭，完成后可退出准备面板。
这是本机恢复资料的准备入口，不是已经可执行空间迁移的向导；没有“继续迁移”按钮。

## 数据范围与边界

- 在只读数据采集事务中保存 24 张固定表的列名、全部行与字段类型；任务、分组、便签、附件、重复规则、关联、清单条目/定义、模板均包含软删除记录。
- 额外包含本机便签历史、清单/模板回执、app_metadata 中的草稿/幂等记录/重复实例保护、终态账本、清空计划与清理队列、各同步域 dirty/ACK/ETag、非敏感同步配置。
- 仅排除自身 migration.backup.* 元数据，避免保存计划导致自身摘要失效。系统设置、凭据保险库、通知系统登记、数据库空闲页和未登记的缓存文件不在该快照范围。
- 已永久删除的正文不恢复备份，purge_cleanup 只保留清理任务记录，不再复制其中待销毁的孤立文件。
- 格式 eggdone.local-migration-recovery.v1 是当前客户端、当前 schema 的内部逻辑恢复资料，不是 SQLite/RDB 文件镜像，也不是公共 v5/v6 导入格式。后续已接入[原生隔离恢复执行与校验](TASK_MIGRATION_RECOVERY_DRILL.md)，仍无替换当前库的用户恢复按钮，不能当成已经验收的完整灾备方案。
- 原有导入导出协议、库版本和旧同步协议均未更改；原有本机清空与旧空间禁用保护不放宽。

## 持久计划与文件校验

计划先以 migration.backup.v1 写入 app_metadata，包含操作 UUID、创建时间、业务快照 SHA-256、全部文件大小/摘要及校验时间。
数据正文只写应用私有目录 migration-backups/<operation>/data.json，不经 IPC 返回或记录普通日志。
同目录保存 manifest.json 与平铺的 <attachment_uuid>-original / -preview.jpg 文件，旧准备目录保留，不自动清理。

附件清单从同一个数据库事务读取，包含已删除附件；每个原文件及图片预览先按真实元数据校验，再复制、刷盘、关闭并重新读取校验。
文件源位置由应用目录 + UUID + 固定文件名推导，不使用数据库提供的任意路径。
目录/文件拒绝符号链接与错误类型。桌面 Unix 下准备目录限定为当前用户访问，鸿蒙使用 filesDir 沙盒，不写 cacheDir。
manifest 也按数据库绑定的固定内容重新校验。SHA-256 是完整性校验，不是对同权限攻击者的认证签名。

后续增量已接入[缺失附件只读下载](TASK_PURGE_ASSET_SAFETY.md)：优先使用有效本机文件/备份副本，缺失时从当前同步空间下载并按固定大小与摘要验证。仅写备份目录，不写云端或当前附件缓存；原空间也已丢失的附件仍明确拒绝，不跳过、不伪报完整。
最大元数据 16 MiB、总文件大小 512 MiB、目录内 10000 个文件（含 data/manifest），超出则失败，不截断。

同一源内容再次准备复用操作 UUID，重新读取已经复制的文件，缺失/损坏副本只有在本机源文件或远端下载内容验证通过后才重建。
文件 I/O 不持有数据库事务；最终短事务重新计算全部受保护本机数据的摘要，并检查当前准备操作与附件清单。
编辑正文、历史/回执变化、同步目标切换、dirty/ACK 变化都会使旧准备失效，即使记录数量未变也不接受。
源已变化时重新准备产生新操作并保留旧资料；磁盘故障或中断保留未完成记录，下次可重试。未验证物理断电恢复。
读取历史状态不自动声称文件仍完整；面板要求重新校验。之后正式切换仍必须再次校验，不能只信 verifiedAt。

备份期间共用 SyncRuntime / SyncSessionLock，拒绝与正常同步、已有附件传输并行；不清除 dirty、不补 ACK、不切换 epoch。
ArkTS 层通过 Repository 管理短事务与 RecurrenceQueue，Service 负责文件和互斥，组件只调用回调。
本机预检 blockers 仅作附加提示；快照可以保留未同步数据，但不因此满足迁移门槛。

## 本轮验证

- Rust 新增 5 项隔离快照测试：含回收站附件、本机状态、数据库重开同 ID 续作、复制失败、文件损坏、源变化、目标变化、非法路径/计划和终态保留。
- 桌面完整 cargo test --lib：365 passed / 23 ignored；cargo check、pnpm check（0 errors / 0 warnings）、pnpm build 通过。既有 dead-code 与大 chunk 提示保留。
- 鸿蒙 test-migration-backup.cjs 执行生产 Repository/Service + host SQLite/文件适配，覆盖中断续作、源文件缺失、落盘损坏、复制期间编辑、互斥释放、不清 dirty、坏计划与源变化。
- 两端原 40 组 migration-preflight 共享用例、鸿蒙原清空内核及面板回归通过。
- 桌面 test-trash-ui.mjs：原 24 组语言/主题/窗口/缩放与 4 组清空场景，追加准备入口、缺文件重试、成功、过期重验、无删除副作用及窄窗口检查；真实 Svelte + 隔离 IPC，不是 Tauri 原生验收。
- 鸿蒙 Debug 构建通过。尚未在手机/平板安装或执行本轮快照，未操作用户数据库与同步桶。
