# 安全清空原生接入进度

日期：2026-09-18。状态：开发中，本机清空及双端界面纳入本次本地提交；未推送、未发布。

## 完成边界

本次已将清空的本机后端、桌面和鸿蒙界面接入真实应用代码，不再只有 host 原型。
但 LC2 整体尚未完成：正式同步空间迁移、终态账本的生产同步、云端附件删除尚未接入。
当前仅从未配置同步且没有同步目标 epoch 的设备允许执行；配置过同步、关闭同步开关或清除配置均不能绕过保护。
本机永久删除后，连接旧协议同步空间也会被阻止。不要将此开发状态发布为完整清空功能。

用户要求按完整功能连续实施；不再把每个内部子步骤作为需要用户重新确认的产品交付。
用户接受显式迁移并保留旧空间，但未授权本次操作其真实数据；所有删除测试均使用隔离数据。

## 已接入内容

- 回收站提供清空全部、左侧批量勾选、详情单项永久删除。
- 清空全部由数据库选择所有已删除任务和便签，不局限于界面已加载的一页。
- 确认显示项目与附件数量，勾选不可撤销确认后才执行。取消不删除。
- 准备阶段固定 ID 与内容指纹，确认后新删除的项目不加入本次范围。
- 已恢复、内容或附件状态变化的项目跳过；活动重复规则当前实例不直接清除。
- 每批 50 项事务提交：删除正文、所属清单、关联记录及便签历史，写入终态、文件清理队列与进度一并提交。
- 不删除独立关联的任务/便签、归档记录和独立任务模板。
- 保留无正文的终态身份。触发器阻止同 ID 的任务、便签、所属附件/清单/历史/关联重新写入。
- 缓存操作回执中的正文被清除，保留操作身份以拒绝旧请求重放；相关批量创建仍在恢复处理中时拒绝清空，不丢弃其他创建草稿。
- 同一个操作 ID 可重试、暂停、进程重启后继续。已完成批次不会重做，失败批次整体回滚。
- 本机附件使用应用资产存储按 UUID 推导路径，不信任持久化路径作为删除目标。失败文件留队列并轮换重试，结果单独显示待清理数量。
- 保存后的页面刷新失败独立提示，刷新不再次执行删除。
- 鸿蒙短确认内容不撑满整个屏幕，操作栏采用均分按钮；手机/平板原生视觉仍待验证。

## 数据与兼容

- 桌面 SQLite schema 22，鸿蒙 RDB schema 23；应用版本维持桌面 1.2.0、鸿蒙 1.3.0。
- 新增 lifecycle_terminals、lifecycle_sync_state、purge_plans、purge_targets、purge_cleanup。
- 两端 migration SQL 等价，含幂等升级、终态和子记录防重建触发器。
- 无终态记录时仍导出备份 v5；含终态时导出 v6，必须包含 lifecycle_terminals。
- v6 导入严格检查 ID、数量、重复、版本和终态/正文矛盾；终态不能通过备份导入静默删除现存本机内容。
- 导入旧备份遇到已永久删除 ID 时整次拒绝并回滚，不偷偷恢复；当前还没有逐项排除冲突的导入预览。
- 迁移本机预检增加终态、清空计划和未完成文件队列盘点。现有旧空间预检对这些未覆盖的新数据明确阻止放行。
- remote_done 仅是未来清理队列字段；目前没有生产远端删除执行器。
- 永久删除指应用记录与所属本机文件的逻辑移除，不承诺 SQLite 空闲页、系统备份、用户导出备份、云桶历史版本的取证级擦除。
