# 双端归档批量管理与恢复

日期：2026-09-17。LC1b-2a，已实现并纳入本地提交；未发布，真机/真实 S3 尚待验收。
前序单条入口已本地提交：桌面 32a2d20，鸿蒙 47af21e。

## 使用方式

1. 桌面/手机进入“更多 → 已归档”；宽平板使用侧栏的“已归档”。
2. 点击“批量选择”，逐项勾选或“全选已加载”。加载下一页不会自动勾选新项目；搜索/刷新会清除选择。
3. 选择“取消归档”或“移入回收站”，检查固定任务清单与数量，再确认。
4. 查看成功数、跳过数及逐项结果，点击“完成”返回。取消归档保留已完成状态，首页隐藏已完成时需打开该筛选；不批量重新打开、不重新注册旧提醒。
5. 中断后重新进入，会显示“查看批量进度”。查看本身不会执行剩余项目；“继续处理”才继续。

只对明确选择的记录操作，不提供含未加载记录的“全部归档”操作。首次确认前取消不写入批次或修改任务。
确认前重新读取所选任务；确认后保存固定 UUID、scope、指纹，不按当前查询重新扩展目标。
移入回收站不是彻底删除，不删除关联便签。清空回收站仍未开放。

## 进度与保护

- 每批最多 50 项，持久保存进度。结果不明时复用同一操作 ID，已提交项目不重复执行；分批失败不回滚之前成功的批次。
- 内容或相关数据已变化、不再归档、缺失和活动重复规则当前实例分别跳过并记录结果，不覆盖其他操作。
- 最终回复丢失时，完成结果仍可从归档页重新发现；显式“完成”后隐藏结果，不删除去重回执。
- “结束本次处理”需再次确认，只停止剩余项目，不撤销已完成操作。底层拒绝继续已结束但未完成的批次。
- 关闭/返回保留已经开始的批次。处理中拦截重复点击与返回，结束后才可确认停止或离开。
- 新同步空间或备份导入使旧 scope 失效，不展示旧空间的批次，不继续其写入。
- 发生错误也独立刷新任务状态，因为最后一批可能已经提交；刷新失败不当作整批成功，也不要求重新创建操作。
- 前台确认时显示任务标题；重启恢复时未持久复制正文，结果用 UUID 标识，保留成功/跳过原因。

新增本机元数据 archive.batch.dismissed.v1:<operation>，复用现有 app_metadata，不改 schema。
导入事务同时清除这类结束标记。同步 wire、备份 v5、桌面 1.2.0、鸿蒙 1.3.0 均不变。
