# 双端统一搜索实现方案

更新日期：2026-09-12。阶段：E8c1 内核与接口已验证，未发布，尚无新的用户界面入口。

## 目标与范围

在同一入口检索任务、便签和附件文件名，按类型分组并显示命中摘要；保留当前任务/便签列表的局部快速筛选，不替换其语义。两端共享检索契约，不强求相同布局。

- 任务：当前标题与备注，包括已完成和已归档任务，不受首页分组、今天或隐藏已完成等筛选限制。
- 便签：当前标题与正文，不查询历史版本。
- 附件：只匹配显示文件名，返回所属便签及正文摘要；不匹配附件二进制、PDF 正文、OCR 或文件路径。
- 排除软删除任务、便签和附件，以及所属便签已删除或不存在的附件。
- 不自动下载/打开附件，不更改完成、归档、关联、同步状态；搜索词不持久化、不上传、不写普通日志。
- 没有数据库或同步协议迁移；使用当前已迁移的本地库。原始用户旧库与物理设备验收单列。

## 检索契约

共享数据：`docs/fixtures/content-search-v1.json`，两端文件逐字节一致。

| 项目 | 约定 |
| --- | --- |
| 输入 | 去除首尾 Unicode White_Space 与 BOM，包括 NEL；最多 100 个 Unicode 码点，拒绝 NUL |
| 匹配 | 连续字面子串；ASCII 字母不区分大小写，中文原样匹配；不承诺 Unicode 全量大小写折叠 |
| 特殊字符 | 百分号、下划线、反斜杠和引号均是普通文字，不支持 SQL 通配符或正则 |
| 空输入 | 返回空列表，不枚举全部资料 |
| 分组 | `todo`、`note`、`attachment` 分别查询；每组有独立总数和分页 |
| 页范围 | 默认 20 条，最多 50 条；offset 为 0 到 100000 的整数 |
| 排序 | 标题/文件名命中优先，再按 updated_at 降序和 UUID 升序 |
| 摘要 | 最多 160 码点；正文命中时保留其前方最多 32 码点，标题命中且正文未命中时取正文开头 |
| 附件结果 | 文件名、所属便签 UUID/标题、正文开头摘要，不返回本地路径或传输错误详情 |
| 一致性 | 每组总数与当前页在一个数据库事务内读取；不同组、不同页不是长期快照，后续修改可能改变分页 |
| 目标复核 | 打开前按类型和 UUID 重新读取最新内容及归档/完成状态；已删除或失去父便签则不可打开 |

查询必须使用绑定参数。SQL 模板按固定类型选择，不拼接输入；不用重型索引或拉取全部正文后在 UI 线程筛选。大库性能仍需实际规模验证，现有测试规模不是生产性能承诺。

错误不能伪装为零结果：无效请求使用 `SEARCH_INVALID_*`，目标失效使用 `SEARCH_UNAVAILABLE`，数据库失败统一为 `SEARCH_DATABASE_FAILED`，不向界面透出 SQL 或敏感路径。Tauri 参数解码失败可能在命令执行前返回框架错误，UI 也必须当作失败处理。

## 实现分层

- 桌面 `src-tauri/src/content_search.rs`：只读检索和目标复核。
- 桌面 `content_search_commands.rs` 和 `src/lib/api/contentSearchApi.ts`：注册 Tauri IPC 和类型化调用，不改现有列表命令。
- 鸿蒙 `models/ContentSearch.ets`、`data/repositories/ContentSearchRepository.ets`：共享返回结构和原生 RDB 事务读取，沿用现有队列。
- 下一阶段新增独立搜索状态管理和视图组件；数据库查询不得搬进 TodoPanel/Index 或 UI 组件。
- 鸿蒙不能只检查 `goToFirstRow()`：原生查询失败可能返回 rowCount=-1 的结果集。总数查询须确实返回一行，分页/目标结果集须有效，分页实际读取数须与结果集行数一致；失败回滚，不返回部分成功。
