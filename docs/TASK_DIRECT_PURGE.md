## 桌面后续修正

- 根因已确认：用户授权诊断的一条待清理附件，原实现返回 `SignatureDoesNotMatch`；修正后的同一附件条件删除成功。只删除了该附件的原文件，没有手动更新本地确认记录，也没有操作其他附件、权限或配置。后续正常同步会从 404 续作确认，并处理余下队列。
- `rust-s3 0.37.2` 会给无请求体 DELETE 加入 Content-Length/Content-Type 并签名，与[上游已报告问题](https://github.com/durch/rust-s3/issues/466)一致。现在复用库的 URL、时间、凭据、SigV4 签名和 HTTP 客户端，移除这两个字段后重新签名；If-Match 继续参与签名，仍不允许无条件删除或冲突后降级。
- 云端错误体限 16 KiB，通过已在依赖树中的 quick-xml 解析，仅映射允许的标准错误码，区分签名、时钟、凭据、权限及未知拒绝，不保存响应正文、路径、请求签名或密钥。临时真实存储诊断入口验证后已移除。
- 签名修正验证：Rust 414 项通过、37 项环境测试默认忽略；Vitest 433 项、Svelte 检查、前端构建、Rust fmt/check 通过。独立 S3 的 `DirectPurgeSessions` 和 `AssetSafetySessions` 均通过，临时服务已移除；证据分别位于 `%TEMP%/eggdone-sync-core-0ef3d9f2f64541728315aa0bf50f0426` 与 `%TEMP%/eggdone-sync-core-922000ecc41a4638bc061a1a9f83e0e8`。桌面开发版已重建，用户需执行正常同步继续剩余清理；修正纳入本次本地提交，未推送。

- 内容及终态发布成功后，文件级清理失败以 `cleanupWarning` 单独返回，界面显示黄色“待清理”，不是“同步失败”或完全成功。运行状态保存脱敏警告，重启后仍可见；回收站重试复用主界面同步调度。

## 同步与附件

- 原空间八个领域对象及附件路径不变，不复制全空间，不自动修改 Object Key。
- 原空间使用 `eggdone-lifecycle/v1/<主对象 key 的 UTF-8 SHA256 小写十六进制>/terminals.json`。文档为 format_version 1 和 terminals 数组，记录仅含 kind、uuid、operation_uuid、purged_at。
- 正常完整同步先合并删除记录，再处理任务、便签及其他领域。首次 404 使用 If-None-Match 条件创建；存在时要求强 ETag 并使用 If-Match，冲突重读合并。
- 本机按存储目标持久记录已见过删除文件。已见文件消失、权限错误、非法内容或缺少有效 ETag 会阻止云端同步，不当成空集合覆盖；本机删除仍可完成。
- 同步尾部核对远端令牌和本机删除记录版本；同步中又发生删除时，先发布新删除记录，再要求重试正文，不能错误宣告同步完成。
- 本机数据库删除不等待网络会话锁；本机文件清理仍与上传互斥，忙时延后，防止删掉正在读取的文件。
- 云端附件清理保留目标绑定、引用检查、大小/哈希校验和强 ETag 条件删除。历史对象缺少自定义哈希元数据时，只在后台对待删附件做有大小上限、绑定 ETag 的下载校验；不下载整个空间。正文改变、权限错误或校验失败保留待清理，绝不无条件删除。
- 删除响应丢失后可重试，已不存在视为完成。待同步状态以实际 ledger ACK/领域状态判定，不再要求空间迁移激活。
