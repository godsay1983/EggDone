# 自定义重复任务统一事务契约

日期：2026-09-05
阶段：DNS5-C2 / HNS5-C2
状态：内部事务接口已实现；普通任务入口、规则网络同步和自定义重复 UI 尚未接入。

## 操作入口

桌面端：recurrence_transaction::advance_current。
鸿蒙端：RecurrenceTransactionRepository.advanceCurrent。

请求仅包含规则 UUID、预期当前 Todo UUID、complete/skip/reconcile、操作时间、设备 ID、可选提醒时间。
调用方不能传入待写入的任务或规则对象。接口在同一事务中重新读取真实 Todo 与完整规则快照。

- complete：完成当前任务；带提醒时间时验证当前提醒仍匹配，且回执未消费。
- skip：删除当前实例并推进一次；不删除整个系列。
- reconcile：只使用已存在的完成/删除证据推进；不会凭空完成一个任务。
- 已耗尽/停用、旧 UUID、缺少任务、提醒过期：返回空结果，不改数据。
- 已归档但已完成的任务只允许 reconcile；仅归档不生成下一项。
- 原有 repeat_rule 非空或系列归属矛盾：拒绝，防止新旧重复算法同时生成。

## 事务边界

当前任务状态、下一项插入、实例回执、规则进度、由触发器维护的 Todo/规则 dirty、提醒消费回执一起提交。
下一项失败、规则失败、任意回执失败都回滚全部变化；重试仍得到同一个下一 UUID。

桌面使用 rusqlite IMMEDIATE 事务；调用者仍遵守现有数据库 Mutex。
鸿蒙规则合并与推进共用 RecurrenceQueue，写入使用独立 relationalStore.Transaction（API 14+）。
规则 Repository 的合并也切换为此对象，不再用 RdbStore 全局 beginTransaction 包裹异步规则写入。
事务内只调用该 Transaction 的 querySql/execute/commit/rollback，不嵌套另一个 Repository 的 merge。

队列只协调本进程自定义规则操作，不冒充整个应用的全局数据库队列。
其他事务持有写锁时，原生接口可能报 14800024；错误向上传播，保留数据，不能回落到非事务写入。
主机 SQLite 只能验证业务原子性；原生独立事务与 RdbStore 并发隔离另有设备测试。

## 下一项字段

| 字段 | 规则 |
| --- | --- |
| UUID | 固定 occurrence key 派生，不生成随机下一 UUID |
| 标题、备注、置顶、优先级 | 继承当前数据库里的值，不使用旧 UI 副本 |
| 分组 | 继承仍存在且未删除的分组，否则为空 |
| 排序 | 当前有效任务最小 sort_order 减 1024，拒绝安全整数溢出 |
| 完成、删除、归档时间 | 新项未完成且未删除/归档 |
| 创建/更新时间 | max(操作时间, 当前任务更新时间+1, 规则更新时间+1) |
| repeat_rule / repeat_next_due_date | 均为空，保持旧客户端可读且不触发旧重复算法 |
| repeat_series_uuid | 原始 first_todo_uuid，辅助验证系列归属 |
| 定时到期值 | 固定规则时区转换后的 UTC 毫秒 |
| 定时提醒 | 继承 reminder_at 与 due_at 的相对间隔；非安全整数或已到期则清除 |
| 全天提醒 | 不自动继承，避免将本地展示投影误作提醒时刻 |

每次只产生紧邻的一项，已有逾期不批量补建。

## 全天日期与实例回执

桌面：新项 due_date=计划日期，due_at=null。
鸿蒙：计划日期仍是无时区的 YYYY-MM-DD；为了兼容现有任务视图，新项 due_at 使用该日期的本地 18:00 投影。
这不是把全天任务升级为固定 18:00 到期，也不是把它当作无日期任务；不存在的本地日期拒绝投影。

双端复用已有 app_metadata 的版本化命名空间：
recurrence.instance.v1:<todo_uuid>。

JSON 值字段：
- rule_uuid
- occurrence_key
- planned_date
- planned_due_at（全天为空）
- projected_due_at（鸿蒙显示投影，桌面等于 planned_due_at）

这是一条本地实例回执，不是新增 Todo 同步字段；不改表结构，schema 仍为 17。
保留完整键和归属信息，不能复用键覆盖别的规则。数据库备份的规则恢复仍需后续专门处理。

重要后续门槛：现有鸿蒙 SyncDocumentService 并不知道该命名空间，不能将投影直接当定时值上传。
D 阶段必须接入全天日期导出、下载恢复关联、时区变化重投影，以及用户手动修改日期后的覆盖判定。
不得仅凭回执中的计划日期覆盖已经编辑的任务。
这些接通之前，普通完成入口和规则创建 UI 继续关闭，不给用户创建会被旧映射误传的数据。

## 碰撞、重放与删除

- 下一 UUID 已存在：要求旧重复字段为空且系列 UUID 匹配；不覆盖标题、日期、完成、删除或其他已同步修改。
- 现有实例回执归属/occurrence key 不同：整笔事务拒绝。
- 回执存在但 Todo 已被清理：拒绝重新插入，不使删除的实例复活。
- 已存在并删除的下一项保留墓碑；下次 reconcile 最多再推进一项。
- 规则推进后，旧当前 UUID 的操作返回空，不会再次生成。
- 提醒回执沿用 reminder.complete.v1:<uuid>:<reminder_at>，与既有消费语义一致。
- 同步后多设备的数据收敛仍由下一阶段的下载、合并与条件上传保证，本地去重不能替代真实 S3 验证。
