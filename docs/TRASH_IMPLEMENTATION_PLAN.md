# 双端回收站实现与验收

## 范围

E8a 分为数据内核、用户入口、原生与同步验收三个可提交任务。整体回收站没有完成前，不把 E8a 勾选通过。本方案承接 EXPERIENCE_EVOLUTION_IMPLEMENTATION_PLAN.md；E6/E7 未完成的人工及异常验收不阻塞 E8 开发。

## 固定规则

1. 回收站包含已删除任务和便签，不包含“仅归档”的任务。按删除时间降序、类型与 UUID 升序分页展示，默认每页 50、上限 100，允许继续加载与刷新。
2. 不新增同步对象、不复制实体、不改变 UUID。沿用 todos/notes 的 deleted_at、updated_at、updated_by；不会按天数清理删除记录，不提供清空或永久删除按钮。缓存清理不是墓碑清理。
3. 点击记录先获取新预览，显示完整标题正文、类型、删除时间、原完成状态、重复提示和可随便签恢复的附件名称。明确提示附件原文件可能需下载，也可能已被清理；元数据存在不代表原文件可恢复。
4. 确认提交携带预览快照。事务内重新读取并比较类型、UUID、版本三元组、标题正文、完成/重复状态及附件 UUID/名称/版本；变化或已恢复、已不存在时拒绝旧确认。用户必须刷新预览并重新确认，不能自动重试覆盖。
5. 恢复保留任务完成状态、日期和正文，但清空旧提醒、旧内置重复及系列绑定、归档状态；不存在的分组降为未分组。恢复的是一个单次任务，不自动重启自定义规则、不推进下一实例。若该 UUID 仍是活动自定义规则当前任务，拒绝恢复，待同步/规则状态核实。
6. 恢复便签时沿用已有数据库触发器，只恢复删除标记与父便签原删除时间相同的附件；更早单独删除的附件不恢复，不生成新附件或复制文件。不宣称远端已物理清理的原件能找回。
7. 旧关联墓碑继续保留；恢复前也对尚未协调的活动关联写入墓碑，避免实体恢复导致旧关联重新可见。恢复与关联协调、便签附件触发器处于同一事务，失败全部回滚。
8. 恢复时间戳至少为当前时间和已观察实体/附件最大更新时间加一的较大值，必须是非负安全整数；使用本机设备 ID，不接收 UI 伪造时钟。恢复后的正常实体同步可以压过旧删除记录，仍遵循现有双端冲突规则。

## 分层与接口

桌面：trash.rs 负责 SQLite 列表/预览/事务恢复；trash_commands.rs 持锁、生成本机时钟/设备标识、刷新角标并发出既有变更事件；trashApi.ts 只调用命令。鸿蒙：models/Trash.ets 与 data/repositories/TrashRepository.ets 负责同样的数据语义，复用现有 RDB 事务、设备标识与操作队列。组件不访问数据库。

- list(offset, limit)：读取一致的分页快照，offset 为 uint32；读取失败不能返回空列表。刷新从第 0 页开始，并发变化时后续页可能移动，界面按类型/UUID去重，不用旧页直接恢复。
- preview(kind, uuid)：只读事务获取当前删除记录和候选附件元数据。
- restore(expected)：立即事务比较预览并恢复；TRASH_CONFLICT / TRASH_NOT_FOUND / TRASH_RULE_ACTIVE / TRASH_INVALID_VERSION 必须区分失败，不将写失败显示为成功。
- 不新增数据库字段或 migration，旧库先走已有迁移；现有短时撤销入口暂不改，不能混同新回收站恢复语义。
- 恢复成功后的刷新、同步、提醒与卡片更新由 Store/页面协调。后续刷新失败不能邀请重复恢复；应提示已恢复并允许刷新。

## E8a1 验证

共享 docs/fixtures/trash-restore-v1.json 的 11 组案例由桌面 Rust/SQLite 和鸿蒙生产 Repository/宿主 SQLite 执行：恢复单次任务、便签与附件、删除版本变化、同版本正文变化、附件变化、已恢复、事务失败回滚、不安全时间、实体消失、写入者变化、活动规则阻止恢复。鸿蒙额外覆盖调用者修改确认对象与分页/非法输入；桌面额外覆盖恢复不复活关联。两端使用既有真实迁移创建隔离库；不改用户数据库。

命令：桌面 cargo test --lib trash_（3 项通过，含 11 组共享场景、关联事务回滚、磁盘库关闭重开）；鸿蒙 node scripts/test-trash.cjs（11 组及分页/输入校验通过）；桌面 pnpm test src/lib/api/trashApi.test.ts（3 项通过）检查 IPC 参数与失败传播。cargo fmt -- --check、cargo check、pnpm check、pnpm build 和鸿蒙 Debug 构建通过。没有把宿主 SQLite 当成 ArkData 原生测试，也未宣称真机、完整云端和附件文件恢复已通过。
