## 新增串联覆盖

| 场景 | 两端断言 |
| --- | --- |
| 勾选后完成重复任务 | 当前实例保持已勾选；主任务不因子项全勾选自动完成；显式完成主任务后，下次实例使用不同子项 UUID 且全部未勾选；定义不变。 |
| 重放旧勾选请求 | 在下次实例已生成后重试旧请求，既不重复生成任务，也不修改新实例或定义。 |
| 勾选后备份恢复 | v4 保留勾选状态；恢复清除本机旧操作回执；旧请求不能覆盖恢复后的内容；重新读取后可以取消勾选。 |
| 删除、恢复与归档 | 调用生产任务删除/恢复 API，删除期间隐藏清单进度，恢复后保留子项身份和勾选；归档后详情只读，清单数据不变。 |

## 用户验收与边界

用户已对上一轮即时勾选、关闭重开、编辑保存/取消及双端同步核对的基础操作说明反馈“验证通过”，不重复要求同一轮基础操作。

本轮代理未安装设备、访问用户数据库或真实 S3。宿主 SQLite 不能证明原生 RDB，浏览器 IPC 模拟不能证明原生 Tauri 窗口；测试包构建不等于安装和运行验收。
原生提醒、含实际附件的设备完整恢复、大字号/软键盘/所有平板尺寸仍按发布前矩阵保留，不据自动化预先勾选。

剩余清单专项手工检查可合并成两条，在测试数据上执行：

1. 建一个含两项的重复任务，选择“本次及以后”，勾选当前子项并完成主任务；确认下次子项均未勾选。对普通清单任务删除后从回收站恢复，确认原勾选仍在。
2. 在测试设备导出包含清单的备份，导入另一测试环境，确认清单与计数；涉及附件时再确认真实原件能打开。不要用覆盖正式数据的方式测试。

旧客户端不能打开 v4 备份；备份合并不会强行撤销本地墓碑，旧备份不等于回收站恢复。
