## 范围与入口

- 桌面手动/自动同步从 `commands::sync_now_inner` 进入 `task_note_link_session::run`；鸿蒙从 `SyncService.syncNow` 进入 `TaskNoteLinkSyncSession.run`。沿用现有全局会话锁，不新增并行同步器。
- 关联使用任务对象同目录下的 `task-note-links.json`，独立 GET、HEAD、条件 PUT、revision、ACK 和 ETag。禁止与任务、便签、附件或重复规则对象重名。
- 主界面同步摘要会计入关联待同步；同步诊断中的领域名称为“任务便签关联”。独立远端探测能发现只有关联变化、其他实体 ETag 不变的情况。
- L4 尚未开放创建/查看关联按钮。本轮无需在任务或便签界面寻找新入口，不把内核测试当作完整用户流程验收。
- 不改实体协议、数据库 schema、备份版本、小艺或实况窗。本阶段未包含备份关联；后续L3c已实现，详情以备份契约为准。

## 顺序与回执

一次外层尝试按以下顺序执行：

1. 同步任务与重复规则，获得实际成功上传的任务文档；重复流程继续沿用既有实体/规则协调。
2. 合并并上传便签，获得实际成功上传的便签文档。
3. GET 关联文件，验证后调用 L3a 原子快照：合并关联并协调实体删除，捕获任务、便签、关联内容与版本。
4. 比较快照中的实体与步骤 1、2 的实际上传回执。忽略文档生成时间，不忽略任何实体字段。不同则重做整轮，不发布基于过时实体的关联快照。
5. 再校验快照与配置世代，条件 PUT 关联。已存在使用本轮 GET 的 If-Match；404 使用 If-None-Match: *。禁止用 HEAD token 或其他客户端对象的回执授权上传。
6. 重新校验快照才能 ACK 关联。上传途中出现本地编辑，保留待同步，不返回可确认的 link token。
7. 继续原有附件同步与清理流程。关联失败不伪造任务/便签回执，也不撤销已经成功确认的实体进度。

外层最多两轮，包括 409/412 和实体快照变化；冲突后重新下载、合并、捕获，不盲目重放 PUT。内层任务/规则、便签各自已有两次条件冲突预算仍保留，因此这里的“两轮”不是整个会话只有两个 HTTP 请求。预算耗尽返回 `TASK_NOTE_LINK_SYNC_CONFLICT`，由已有重试入口处理。

若 GET 为 404 且合并后关联为空，不创建空对象；使用只允许空文档的 acknowledgeMissing 确认本地 revision，ETag 保持空。已有墓碑仍必须上传，不能按空活动关联判断文件为空。

## 兼容与失败处理

- 旧客户端不认识新文件，不要求它回写关联。实体先合并，明确的实体删除会墓碑对应关联；单纯未下载、归档、完成不等于删除。恢复实体不自动复活解绑。
- 只有 GET 404 表示缺失。401、403、限流、5xx、超时、非法 JSON、未知版本、无效/多个 ETag、无效 UTF-8 均失败，不当成空文件覆盖。
- HEAD 的 missing/denied/etag 是三个不同观察状态；观察不是上传成功。只有本轮成功且快照仍有效的回执才能更新关联轮询基线。
- 配置切换使旧世代失效，拒收旧上传/探测回执；链接错误不输出远端正文或凭据。
- 下载上限 4 MiB，链接仍遵循 links v1 的 10,000 条（包含墓碑）及安全整数限制。
- 用户自定义 IAM / MinIO 策略需要允许新对象的读取、探测和条件写入。窄策略只授权旧文件时，关联请求可能返回 403；不会通过忽略错误把关联显示为已同步。真实部署需确认缺失 Key 返回 404 所需权限，不能把 403 推断为“不存在”。
